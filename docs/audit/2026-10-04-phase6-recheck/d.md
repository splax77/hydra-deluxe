## How D42 settles this batch

D42 says a test may not keep a frozen copy of old code as a reference; it checks fixed expected values on hand-built inputs instead. That answers R7.30's question directly: test oracles are not exempt when the oracle is a second copy of the production algorithm. An oracle that is an independent fixed value (a literal from one run, or a sum a person can do by hand on three samples) is fine.

Applied here: 278's `reference_mix` is exactly the kind of copy D42 forbids, so it goes, and the mixer test pins the mixed samples of two or three tiny hand-built stems. The formula retypes (263, 264's edge loop, 265, 266, 276's truncation and glow lines, 279's 117, 281, 282) follow the same rule: where production exposes the function, the test calls it; where it does not, the test pins a literal. The copied test plumbing (117, 121, 277, 287, 288, 293, 294, 295, 300) is not what D42 is about; those fall under the plain derive-once rule for tests, which the precheck enforces as "one shared header per helper". The hand-written checks against FC videos in `test_squeeze_rating.cpp` are ground truth, not copies, and stay.
