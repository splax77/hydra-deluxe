## Questions for the user

Each one: what you see today, what you would see after, and my recommendation.

**Q1 (finding 7, high weight). When two paths tie for the top score, are both "optimal"?** Today the Paths tab and the Preview call both Optimal (gold), but the report's "Best path only" view keeps only the first and bolds only it. After: one answer in both places. I recommend "both are optimal": a drummer gets the same score playing either, so the report's Best-path-only view should list the tied variant too. The alternative is to keep CONTEXT.md's "first path only" and demote the second path in the Paths tab to the Within group.

**Q2 (4, 18, 36, 154). How does a squeeze timing print, and which part wins a tie?** Today one squeeze reads "13 ms" on the activation badge, "(12 ms)" when you copy the path, "12.6 ms" on the path button, and the report page can round an exact half differently from the app. After: whole-ms text rounds to nearest everywhere (copied text says 13 ms too), one-decimal text is unchanged, and the report prints the app's own string. I recommend that. For a squeeze and an early fill that tie exactly, the badge keeps naming the squeeze, as today.

**Q3 (305). Does an activation that skips fills still get an "early fill N ms" badge?** Today it does: an activation with no required squeeze can show a grey "early fill 20 ms" badge while its path button shows no timing. The approved 2026-09-27 plan said no badge. I recommend keeping the badge, because that timing decides whether the first fill appears and so what the skip count means, and recording it in an ADR. If you prefer the plan, the badge goes.

**Q4 (302, 51). Round percentages to nearest?** Today the Dynamics tab cuts decimals off (12 of 453 kicks reads 2%, 999 of 1000 reads 99%), and the leaderboard page can say 100.00% for a score 10 points short of optimal. After: nearest everywhere (3%, 100%, and 99.99% for the near miss). I recommend yes.

**Q5 (14, 99). "1 bar", and commas everywhere?** Today SP cap 1 reads "1 bars" in the song panel, the report subtitle and hydra_batch; "Within 1000 scores" sits next to "1,000 scores"; the dmleaderboards picker can say "1 scores"; and in a German-language browser the report pages print 1.234 next to a subtitle saying 1,234. After: one rule (singular at 1, commas at 1,000) in the app, the CLIs and the pages, whatever the browser's language. I recommend yes.

**Q6 (55). One name per fill rule?** Today the same rule is "Clone Hero 1.0" in the batch confirm, "Clone Hero 1.0 (legacy)" a few lines later in hydra_batch, "Clone Hero 1.0 fills" in the report subtitle and "CH 1.0" in the fill comparison's columns. After: the long name "Clone Hero 1.0" in sentences, the short "CH 1.0" where a column is narrow, both from one place; "(legacy)" goes. The checkbox stays "1.0 fills" (ADR 0010). I recommend that.

**Q7 (17). One name for a drum note?** Today a green tom is "GreenTom" in the Paths tab and the Preview box but "Green tom" in the Dynamics tab, and with Pro Drums off the Paths tab says "YellowTom" where Dynamics says "Yellow". After: the Dynamics wording everywhere ("Green tom", "Yellow cymbal", "2x kick", and plain "Yellow" when Pro Drums is off, since the chart then has no cymbal information). I recommend that; the compact "GreenTom" form was never asked for.

**Q8 (105). What should an empty report say?** Today hydra_report and the GUI say "No records stored yet, run hydra_batch first" even right after a batch stored a record under a different cap or fill rule. After: "Nothing is analyzed under these settings (SP cap 8, Clone Hero 1.1 fills). Analyze with these settings, or change them." when records exist, and today's sentence only when the database is truly empty. I recommend that wording.

**Q9 (309, 312). Leaderboard and fill-comparison labels.** Today a score 50,000 under optimal wears a "Matched" chip (it means "found in your library", not "equals optimal"). After: "Under optimal", "At optimal" and "Above optimal" chips, with the summary line to match. In the fill comparison, a chart whose 1.0 record has no paths is listed under "Only in 1.1 db"; after, each chart is labelled by which database holds a record. I recommend both.

**Q10 (70). How is a long label cut?** Today a cut title in the library ends in " …" (space kept) and is cut one character earlier than the same text in the Preview's path picker, which ends in "…" with no space. After: one rule, the picker's (space trimmed, an exact fit allowed). I recommend the picker's rule; upstream Dear ImGui has an open report either way (issue 9229).

**Q11 (57). Preview time box, half a tick before a tempo change.** Today, for up to half a tick before a change, the meter, section and drain box already show the new values while the BPM line still shows the old tempo. After: all four switch together. I recommend yes; only playback or scrubbing can land there.

**Q12 (20). Reload the Preview when the chart mode changes?** Today, with a song open on the Preview tab, switching difficulty, Pro Drums or 2x Bass keeps the old mode's notes on the highway while the path, gauge and score box come from the new mode. After: the Preview reloads with the new mode's notes (or says "No Hard Pro Drums notes in this chart."). I recommend yes; the settings-bar help text already promises it.

**Q13 (308). Which cap does the gauge use for a song that has no result yet?** Today it pins at 4 bars whatever the Settings cap says. After: it pins at the Settings cap, the cap the next analysis would run at. I recommend yes.

**Q14 (329). How far do the beat lines run?** Today they stop two measures after the last note, even while the music keeps playing and the time box keeps counting measures. After: they run to the end of the audio. I recommend that; if you prefer the two-measure tail, it becomes a named constant with a comment and nothing changes on screen.

**Q15 (69). A progress bar at 0 of 0: full or empty?** Today the scanning modal draws a 0/0 bar full, the batch strip draws it empty for a moment before the first update, and the Preview loader sits at 8%. After: one rule. I recommend empty ("not reported yet"); the scan's Done line already says "0 charts found" in words.

**Q16 (310). Average multiplier of a path with no scoring notes.** Today it reads "Avg. Multiplier: 0.000x"; it needs a chart with zero base score, which does not happen in practice. I recommend keeping 0.000x and recording the choice, so no code changes. Say the word and it becomes "n/a".

**Q17 (71). The no-notes sentence from the command-line tools.** Today hydra_replay and bench say "No drum notes in this chart." where the GUI says "No Expert Pro Drums notes in this chart." After: the GUI's sentence everywhere. Nothing in the GUI changes. I recommend yes.

## Prior art

Thousands grouping (99): MDN on `Number.prototype.toLocaleString` shows that with no argument the host locale decides and that `toLocaleString("en-US")` gives "123,456.789" whatever the browser is set to. https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/toLocaleString

Half-way rounding (36): MDN on `toFixed` shows the rounding follows the binary value, e.g. `(2.55).toFixed(1)` is "2.5", so a page and a C++ formatter agree only when one of them does the rounding. https://developer.mozilla.org/en-US/docs/Web/JavaScript/Reference/Global_Objects/Number/toFixed (Stack Overflow could not be fetched from this session.)

Ellipsis and the trailing space (70): Dear ImGui issue 9229, "Ellipsis should not discard trailing spaces" (opened 2026-02-11, no maintainer decision shown), shows the space-before-ellipsis choice is unsettled upstream too, so Hydra picks its own and tests it. https://github.com/ocornut/imgui/issues/9229

Zero-total progress (69): Dear ImGui issue 7451 is the NaN-from-`Count / (float)MaxCount` bug the Preview job's comment already cites; one fraction helper is the standard guard. https://github.com/ocornut/imgui/issues/7451
