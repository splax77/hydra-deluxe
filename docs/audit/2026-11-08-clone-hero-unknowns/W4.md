Found: the switch compares each word against twelve option names and no others: `--versus`, `--instrumentNames`, `--song`, `-i`, `--player`, `--profile`, `-r`, `-s`, `-v`, `--analysis`, `-p` and `--replay` (listing lines 61 to 245). None names a modifier, a speed or precision. The game's string table holds no other `--` option a launcher would take (the rest are UI style names such as `--unity-image`). The `--player` value is parsed by `0x396110` into an instrument and difficulty pair only (listing line 231). The loader then writes the modifiers word itself: 1 (None) for a non-drums player, 2 (DoubleKick) for Drums and ProDrums (`docs/clone-hero/code/6142/cli_loader_3968D0.asm` lines 330 and 350 to 357, as its `.md` reads them). One route does carry modifiers: with `--replay`, the loader copies the modifiers from the replay object's +0x70 instead (the same listing, lines 376 and 377). Whether a replay also carries a song speed was not read. The two other argument-array methods, `0x398440` and `0x3964F0` (`dump.cs` lines 17977 and 17983), were not listed, so "no other word is read" rests on the switch and the string table, not on every reader.

Answer for the main session: a plain command-line start can set no modifier and no speed; the loader forces None or DoubleKick. A replay file is the one loader route that sets modifiers, and it starts a replay, not a bot run of a chart (the bot write is skipped on that branch).
