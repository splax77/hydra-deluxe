### What the capture run must measure

The user said "Yes, capture" to a screen-capture run if code cannot settle FL-32. Code did not, so this is what that run must measure.

- The run: a bot run of one drum chart with the screen recorded beside it, on a chart with at least two fills. One fill should be generated by 1.1 (no written fill on the chart) and one written (a `.mid` pitch 120 or a `.chart` `S 64`). Each fill's chord should sit at a known tempo, so beats convert to milliseconds without doubt.
- The clock: line each video frame up with song time from two bot hits the trace records (`ch_notes`), one near each end of the song. Then convert each frame's time to a chart tick with the chart's tempo map, using the same rule the game uses (`time_to_tick_212BCC0.asm`).
- What to read on each fill, frame by frame:
  1. The first frame on which any fill visual shows. That means the activation note's own model, any lane or highway highlight, and any change to the notes before the chord.
