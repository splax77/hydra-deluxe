- Found: in the runs, 11 of the 15 folders say in words that `profiles.ini` was unchanged and absent before and after (for example `2026-10-31/ls-d0-run1/replies.txt` line 36, `2026-11-06/ls-d2b-run1/replies.txt` line 31); the other four (`ls-e-run1` line 14, `ls-o3-run1` line 17, `ls-t2-run-a` line 17, `ls-t3-run-b` line 16 of their `replies.txt`) say only that the files were restored or unchanged. The two File.WriteAllText methods do not take an ini name: `0x2113710` walks the loaded assemblies by reflection (skipping names that start with "Mono", "System", "Unity", "Rewired" and "Beebyte") and `0x2113C60` writes the one path in the class's static +0x28 with text from `0x2113D70`; neither was read to its end. Three more ini-class methods call the path lookup and then the document writer `0x2165C50` (`0x21134B0`, `0x21135B0`, `0x2114A80`, see `ini_path_lookup_2115760.md`); they were not listed, but each still needs a registered path for the clone's empty name, and none of the 9 registrations found passes an empty name (0x235452's joined name for `config.ini` was not read through).
- Proposed label: Proven in the game's code for the save method `0x2112DB0`: it never writes a key with the empty ini name, so the clone's settings do not reach `profiles.ini` through it, which the 15 human runs agree with. The three other writer methods (`0x21134B0`, `0x21135B0`, `0x2114A80`) are not listed; a page writer may prefer to keep the block Unknown for them, with this widened Evidence, until they are read.
- Hydra: no owner. Hydra never reads the running game; the tools back up `profiles.ini` and `profiles.bin` (`PROFILE_FILES` in tools/ch_mcp/game_files.py line 48, inside `DOCUMENTS_FILES` on line 49). Nothing found differs from what the tools do. One gap for the tools, not for Hydra: a file the game wrote under any other name would not be backed up or noticed, because `backup` copies only the named files.

## CR-49

- Unknown was: whether a bundle's stated song length can be longer than its real audio (Pressure: 273 s stated, 223 s heard); it needed the audio decoded and measured.
- Looked at: `C:\Clone Hero\1.1 june\Clone Hero\Clone Hero_Data\StreamingAssets\songs\Pressure.srb`, a song the game ships, in the folder `GAME_DIR` names in tools/ch_mcp/game_files.py line 32. The kept script `W11b/srb_audio_length.py` reads it per docs/srb-format.md ("The layout at a glance" to "The audio section"): stream 1's stated length by the same field walk as `srb_parse_metadata` (src/parse/srb.cpp lines 174 to 180), streams 2 to 4 inflated only to step past them, then each audio blob decrypted with AES-128-CFB (key read from src/app/preview_source.cpp line 53, IV the header halves swapped as at lines 85 to 87) into the scratch folder only. Each stem's length is its last Ogg page's granule position less the OpusHead pre-skip, divided by 48,000. Output kept in `W11b/srb_audio_length_Pressure.txt`. No audio or bundle bytes were committed.
- Found: the stated length is 273,467 ms (273.467 s). The bundle holds five Ogg Opus blobs (tags 1, 6, 0, 12, 3), and every one ends at granule 10,710,551 with a pre-skip of 312, so each is 223.130 s long. The audio section ends exactly at the end of the file (offset 19,769,735), so no blob was missed. The stated length is 50.337 s longer than every stem.
- Proposed label: question 1's label (a fact counted from the game's files): the stated length can exceed the audio, shown for Pressure.
- Hydra: `srb_parse_metadata` in src/parse/srb.cpp reads the stated value as the song length: `out.song_length_ms = static_cast<int32_t>(song_length);` (line 180). So for Pressure, Hydra's song length is 273,467 ms while the audio stops at 223,130 ms. What the game itself uses as a bundle's song end (the stated field or the audio's end) was not read, so this is not written as a DIFFERS line. It is an open question for whoever owns the one song end (D255).
