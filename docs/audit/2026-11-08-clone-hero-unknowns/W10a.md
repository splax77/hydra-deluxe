## IN-92

- Unknown was: where the game keeps its key bindings and settings. The tools say Rewired saves the bindings under `HKCU\Software\srylain Inc.\Clone Hero`. The feasibility study says `settings.ini` comes with a `settings_schema.json` of defaults and limits, and that `settings.ini` holds `poll_rate = 656`, the input polling clock. No game method had been read for any part.
- Looked at: the literals `settings.ini` (slot 0x3CAD120), `settings_schema.json` (0x3CAD1D8) and `poll_rate` (0x3D0BCA0) in `C:\Users\Patrick\Downloads\Hydra\hydra-data\ch-dumps\6142\stringliteral.json` lines 20115, 20147 and 93187. The byte scan `W10a/xref_settings_literals.txt` (made by `W10a/xref_scan.py`) found every code load of the three slots. The settings loader's existing listing `docs/clone-hero/code/6142/settings_load_374D50.asm` lines 1637 to 1671, with `setting_int_ctor_210C470.md`. New listings `poll_rate_to_rewired_233198.asm`, `settings_ini_path_377FC0.asm`, `settings_schema_path_164940.asm` and `settings_schema_bundle_1EB800.asm`, each with its `.md`. A caller scan of those methods, `W10a/xref_settings_methods.txt`. The ScoringPanel load of `poll_rate` at 0x19FAC5 (read with chdis from 0x19FA70, not committed) and class 565's lookup 0x12EE30. For the registry: `C:\Clone Hero\1.1 june\Clone Hero\Clone Hero_Data\app.info`; Rewired's `UserDataStore_PlayerPrefs` class at `dump.cs` line 4278; `UnityEngine.PlayerPrefs` at line 693692; a caller scan of `PlayerPrefs.SetString` (0x2881360), `Save` (0x28812A0) and `GetString(string, string)` (0x2881210), `W10a/xref_playerprefs.txt`. Unity's documentation page "PlayerPrefs" (Scripting API), https://docs.unity3d.com/ScriptReference/PlayerPrefs.html, which now redirects to https://docs.unity.com/en-us/engine/current/script-reference/unityengine/playerprefs.
- Found: `poll_rate` is a whole-number setting made by the settings loader. Its default is four times the screen's refresh rate: the loader reads `Screen.currentResolution` (line 1639), takes its refresh rate as a ratio (line 1644 calls 0x1BBD830, which `dump.cs` line 689373 names `Resolution.get_refreshRateRatio`; the listing's own comment names a method that shares the same code), divides numerator by denominator (lines 1658 to 1664), truncates and multiplies by 4 (lines 1665 to 1666). The minimum is 60 (line 1660, 0x3C), the maximum 1000 (line 1657, 0x3E8), and the fifth number is 5 (line 1655; `setting_int_ctor_210C470.md` calls it the kind). The setting goes to the settings statics at +0xC0 (line 1671). So 656 in the user's ini would be the default for a 164 Hz screen, or a value the player set; which, was not checked. Its unit and meaning: `GlobalVariables.Start` hands the value to Rewired's `ReInput.ConfigHelper.set_joystickRefreshRate` (`poll_rate_to_rewired_233198.asm` lines 1 to 12). The scan found two more readers in `GameplaySettingsMenu` (0x1AEE40 and 0x1AFD51), not read. The `poll_rate` load in ScoringPanel (0x19FAC5) is a string key passed to class 565's lookup 0x12EE30, which hands it to 0x3499B0 of another class; it does not read the setting, and what the lookup is was not read.

  `settings.ini` is the folder from `0x307B40` joined with the name (`settings_ini_path_377FC0.asm` lines 12 to 28, called from `GlobalVariables` 0x2344B0). `settings_schema.json` is built from the same folder method and stored in a static at start-up (`settings_schema_path_164940.asm` lines 4 to 38, in `GameInit` 0x164810, called from `GameInit.PreUnityInit`). Class 819's method 0x1EB800 reads the bytes of a file called `Threshold` and passes them with the name `settings_schema.json` to 0x1ECC50 (`settings_schema_bundle_1EB800.asm` lines 18 to 41). Who writes the schema file, and whether it holds every setting's default, minimum and maximum, was not read; the loader's (name, default, min, max) arguments make it likely but do not show it.

  The registry key: Rewired's `UserDataStore_PlayerPrefs` is the only caller of `PlayerPrefs.SetString` and `PlayerPrefs.Save` inside Rewired's code (15 of 25 `SetString` hits and 9 of 17 `Save` hits are its `Save...` methods), so Rewired keeps the bindings in Unity's PlayerPrefs. Unity's "PlayerPrefs" page says a Windows player keeps PlayerPrefs at `Computer\HKEY_CURRENT_USER\Software\ExampleCompanyName\ExampleProductName`, where those two are the names from Player Settings. The game's `app.info` holds the two lines `srylain Inc.` and `Clone Hero`. So the key is `HKCU\Software\srylain Inc.\Clone Hero`, as the tools say. The game's own code also writes PlayerPrefs (callers in `MainMenu`, `News`, `BuildCheck`, `CliGameLauncher` and class `ʳʲʾʵʻʽʶʾʺʲʷ`, `xref_playerprefs.txt`), so the key holds more than Rewired's bindings.
- Proposed label: Proven in the game's code for the registry key (Rewired's writer by byte scan, Unity's page and `app.info`) and for `poll_rate` (its build at `settings_load_374D50.asm` lines 1637 to 1671 and its reader at `poll_rate_to_rewired_233198.asm` lines 1 to 12), with the rule reworded to say `poll_rate` is Rewired's joystick refresh rate, defaulting to four times the screen refresh rate, limited to 60 to 1000. The schema file's path is proven (`settings_schema_path_164940.asm`); what the file holds stays Unknown, with the searches above added to its Evidence. The unit of `joystickRefreshRate` is Rewired's, from its own documentation, which was not fetched.
