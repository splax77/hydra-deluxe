## How these counts compare with the planner's run

The planner ran the probes as one-off commands in session 8bffee2b and gave these counts: 56 repeated strings (17 crossing a folder), 9 function names, 17 struct pairs, 5 store methods, 4 twice-used type names and 66 enums. This script lands near each one, and the gaps have plain causes.

Strings: the planner counted strings quoted inside comments. With comments counted (probe 1b) this run finds 59, 18 crossing a folder. With comments stripped (probe 1) it finds 16, 5 crossing. Both lists are below, because a comment quoting a button label is a second place that names it, which is a lead too. "Show in Preview" and "squeeze in -316 ms" appear only in comments.

Function names: 10 against 9. The extra one is `restart`, in `audio/ma_reader.cpp` and `audio/vorbis_reader.cpp`. It is a member-like helper in each reader and goes to G8.

Struct pairs: 22 against 17, from 232 structs against 194. This script reads `class` bodies as well as `struct` bodies, so it adds the audio reader classes (VorbisReader, MaReader, Mp3Reader, OpusReader), the Preview controller against its load jobs, and two job classes. Every pair the planner named is here.

Type names: 5 against 4. The extra one is `Path`, a struct in `core/model.h` and another inside `search/engine.cpp`. Enums: 62 against 66. The gap is small and only shapes C2's starting list, so it was not chased.

Store methods: the same 5.
