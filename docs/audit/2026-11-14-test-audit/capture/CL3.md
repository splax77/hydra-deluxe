# Capture list CL3 (records C1 to C15, C14-C15-fuzz, D1 to D16)

Scout CL3, task T5-CL3. This lists what the "claim not checked" records of C1 to C15, C14-C15-fuzz and D1 to D16 say they need: a chart dump, a screen capture, a real file or setting, or a recorded run of the game tooling. It judges no test.

How the lines were made (read this first). The records files are about 3 MB, so I did not hand-copy each record. A script split each records file into records (a heading per test, or where the file has no per-test heading, one record per line that says "claim not checked"), kept every record whose text says "claim not checked", and sorted each into a need by the words in the record (its Real-chart line, its shared-answer code such as C3F, S-FT3, C-WATCH, NEED-B, CAP-PB, and what it names). I read the legend and shared-answer sections of every file and about 700 distinct "Needed" sentences to write the need texts. Two limits follow. First, one record goes to one need row (the first rule that matched), so a record that needs a chart dump and a screen capture appears under one of them. Second, the need text is the general need of the group; the exact chart or file for one record is in that record itself. Every record is listed by its heading line in its records file: `L123` means the record whose heading or hit is at line 123 of `records/<file>.md`. Records the script could not sort are in the last row of the table they fell in as UNSORTED; none are dropped.

Section 4 reads "hook" as the game-side hooks of the Clone Hero tooling (the Frida agent, the kit, the memory reads) and the recorded calls and replies from the `ch` MCP server. No C or D record names a Claude Code gate hook as its needed input (I searched the records for "PreToolUse" and "gates"; see the notes).

What the records do not give me: where a record says only "claim not checked" with no named capture, the need row says so. The `testdata/input` paths below are the ones the records themselves name or that C7 names with a full path. I did not guess any other chart.

## Notes on how far to trust this list

The need rows come from keyword sorting, not from reading each of the 2,030 records. A record can sit under a neighbouring need (for example a Library record under a Preview row, or a precheck record under the real-repo row). The record ids are right: every record whose text says "claim not checked" is on at least one line. The per-record chart or file is in the record itself. Counts are of records (or, for files with no per-test heading, of hit lines) whose text holds "claim not checked", including those that only say it in the verdict. Files C14-C15-fuzz, C3, C14 and D15 use hit-line records. A re-read by a fresh scout of the Real-chart line of each record would tighten the sorting. I used about 45 calls and did not reach a second pass.
