A record spells out an answer only where it differs.

Common to all six files:

- Q2 (C2): the owner is the named Python tool module, listed per file. Callers in `src/`: none. The callers are the MCP server's tool list (`tools/ch_mcp`) and the probe scripts. So these are not display rules and not engine rules.
- Q3 (C3): a claim about what a tool's reply or status line says is a claim about text a person reads, so the real thing is a capture of that text from a real run. None exists in `records-screen/` (which holds Hydra screens only). Written as "claim not checked", capture needed named per file. A claim about a pure file or data helper is checked only where a record says which real input it ran on.
- Q7 (C7): adding commit "not read" for every test except where stated (I opened `git log` for the three newest commits on test_sp_tools.py only: 5a03a9e2, c50e0f9e, b9aab853; they are later edits, not the adding commit). I name the failure myself as the wrong result a user of the tool would see.

- Q11 (C11): the scenario is a tool being driven by a fake; the real case (a real Clone Hero run) is the one the capture must show.
- Verdict rule used: a test whose only fault is Q3 gets "Investigate, claim not checked only". A pinned copy of a constant, a typed literal that no rule backs, or a source-text scan is a fault in the test itself.
