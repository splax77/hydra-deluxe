"Record named it" is my judgment from a word search of each record's text (hand-built, typed, relabeled, pinned, snapshot, literal) and not a full re-read of all 86 records. Treat that column as approximate. The records mostly answered a "stand-in" question about a hand-made helper and none of them called a typed value or a hand-built row a fault, because the rubric had no question for it.

How I called the faults, so the reader can overrule me:

- X9: a hand-built Activation, PreviewActivation, SpMeterCurve, PathRow, library row or failure record; a record relabeled to another cap (`at_cap`), edited by hand (a score, a path text, a rules fingerprint, `ms_enabled = -1`), or made "under other rules" or "under an old build" by the test helpers (`other_rules_record`, `save_old_build_record`, `save_under_build_for_test`); a fake analyzer; a fake byte source. A song or chart the test builds is input to the engine, so it is not X9. A `.sng` container written by `make_sng` is treated the same way, as a built input file.
- X10: an error message, label, readout text, hex, tier token or threshold typed as the expected value. The song-length pad of 1000 ms is typed in every expected length of `test_song_length.cpp`.
- X12: the check or its header names a plan, a user choice, a standard (WCAG) or "pinned from one run" as the source of the expected value.
- Weak means I would accept being overruled: the helper is the only way to make that state, or the typed value is also a rule.
