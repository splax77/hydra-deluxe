# Plan: every part of Hydra becomes a library its own programs can link

Task id `hydra-libraries-plan`, session `d9bea2e5-9589-4187-a0d6-c231e61d8921`. Planner: Fable. Status: plan written and reviewed; the build waits for the user's yes and for the three answers below. Nothing is built.

The user's request (2026-10-28): "plan out how to make each component of hydra a reusable library". Scope, in the user's words: reusable by Hydra's own programs only (Hydra.exe, the new HydraPathBuilder.exe, the command-line tools, the tests and test runners). No public API, no DLLs, no promises to outside projects. Every path and line number below was read in the worktree on 2026-10-28; the include graph comes from the `#include` lines themselves, not from folder names.

## The plain version

Hydra today is one big static library (`hydra_core`: core, parse, search, store and app, 46 files) with five smaller ones on top (audio, render, dm, ui, image) and one test harness. The folders already read like components, but the include lines do not: the scoring code in `core/` reads the `Song` class out of `parse/`, `parse/` reads the model out of `core/`, the replay in `core/` reaches up into `app/` for a text formatter, `app/` reaches up into `audio/` for the chart sync rule, and the GUI's window set-up sits in the same file as the code that draws Hydra's whole window. So a program that wants only the Preview, or only the window set-up, gets all of Hydra.

The plan makes twelve libraries with a one-way order and keeps every file where it is today. `CMakeLists.txt` becomes the one place that says which file is in which library (headers get listed beside their `.cpp` files), and a new test reads those lists and every `#include` line and fails when a file reaches into a library its own library does not link. Four small fixes make the includes point the right way. The Preview and the window set-up become libraries of their own, and the headless GUI runner splits into an app-free engine and Hydra's harness, so the Path Builder links the engine and brings its own window. Hydra.exe is built from the same files and looks and behaves exactly the same; the proof is that the existing tests for every moved piece pass with nothing edited beyond include lines and the few call sites a move names.

Eight executor tasks in five waves. T3 (the layering test) goes first and alone, because it adds the header lines to `CMakeLists.txt` that every later task carries into its new blocks, and because its known-gaps list is each later task's red-then-green proof. Then three tasks run together: T1a moves the `Song` class down, T1b moves two small pieces, and T2 splits the GUI base out. T1c (the five bottom libraries) and T5 (the app-free runner) follow. T4 (the Preview library) comes after T1c, and T6 closes the record.

## How the layering stays true: the test (T3)

A new test file `tests/test_layering.cpp`, globbed into `hydra_tests` like every `test_*.cpp`, reads `CMakeLists.txt` through `sourcetree::root()` and walks the tree with `sourcetree::for_each_source_file` (`tests/source_tree.h`, the one walker). It builds two maps from the CMake text with its `#` comments blanked: file to targets (a file can be in two targets, as `tests/report_samples.cpp` is, and is checked against each), from every `add_library(` and `add_executable(` source list (the `${hydra_test_sources}` glob stands for `tests/test_*.cpp`); and target to the targets it may include from, from every `target_link_libraries(`, following PUBLIC links transitively and PRIVATE links one step. A `foreach(... IN ITEMS a b)` loop is read as a plain list with its variable (`${tool}`) replaced by each item. Every branch of an `if()` counts as taken, so a link under `if(HYDRA_UITEST_ATTACHED)` is allowed. Then, for every `.h` and `.cpp` under `src/`, `tools/` and `tests/ui/` that a target lists, it reads each `#include "..."` or `<...>` line and resolves it to a project file (first in the including file's own folder, then by the `src`, `tools`, `tests` and `tests/ui` include roots) or to an external by `tests/layering/externals.json`. It fails with `file: include "x" reaches target T, which L does not link` for each include outside the allowed set. A `src/` file in no target fails with `src/x: in no library's source list`. A header under `tests/` or `tools/` that no target lists is free to include and is not scanned (test helper headers belong to the exe that includes them). A project header with a `.cpp` twin belongs to the twin's target.

`externals.json` is a list of `{"header": "imgui.h", "target": "imgui"}` rows for the third-party and system headers that stand for a link line: `imgui*.h` and `imstb*` to `imgui`; `imgui_te_*.h` and `imgui_capture_tool.h` to `imgui_test_engine`; `d3d11.h`, `dxgi.h`, `d3dcompiler.h` to those three; `sqlite3.h`, `miniz.h`, `miniaudio.h`, `stb_vorbis.c`, `opus*.h`, `ogg/*.h` and `winhttp.h` to their targets; `json.hpp` and `stb_image.h` to the include directories `third_party/json` and `third_party/stb` (read from `target_include_directories`, because neither is a target). `mimalloc.h` has no row: no library links mimalloc by design (the CMake comment named above), `app/allocator.cpp` gets its header through an include-directory line, and a row would flag it. Standard and Windows SDK headers match no row and are free. Rows have the single-owner shape (`must_match` examples the test checks against itself), so a mistyped row fails the test, not the tree.

`known_gaps.json` is the baseline, in the shape of `tests/single_owner/baseline.json`: a `known_gaps` object whose keys are the ids of the tasks that remove the entries, each holding a list of `{file, include, date, added_by, remove_by}` entries. The date fields are read by `parse_dates` and `iso_plus_days` from `tests/single_owner/engine.h` (linked from `hydra_precheck_lib`), not by a reader of its own; Q3 is about the cap that reader applies. An entry past its `remove_by` fails, and an entry no include matches fails too, so the list cannot go stale in either direction. Each task's entries sit in their own block with the brackets on their own lines, so two tasks deleting theirs in one wave never touch the same lines. T3 writes an entry for every violation the test finds on today's tree; the twelve it should find are listed under T3. T1a, T1b, T1c, T2 and T5 each delete theirs, which is each task's red-then-green proof. T6 sets the object empty and adds the case `layering: no known gap is left`, so the list can never grow back: without it a new wrong-way include could be hidden behind a new entry, since "every entry names a real include" is true of it.

The reader is pinned on a made-up `CMakeLists.txt` string in the same file: three libraries, one PUBLIC chain, one PRIVATE link, one `foreach` with `${...}` in its link line, one `${...}` glob name, one `if()` block, with cases for each. No number is involved beyond Q3's existing cap. A new library needs no edit to the test; a new external header needs one row in `externals.json`. An ADR records the decision (T6).
