## Orchestrator answers (binding)

Open question 1: the typed query folds too, because D48 Q31 says the pages search the way the Library does, and the Library finds "Beyoncé" typed with its accent. The fold still has one owner. Each page carries a fold table that C++ builds by calling `fold_for_search` on every single character the owner changes: A to Z, U+00C0 to U+017F and U+FF01 to U+FF5E. Keep only the entries where the result differs from the input. The shared script folds the query by looking each character up in that table and keeping it when it is absent. It then splits on whitespace (`/\s+/`) and drops empty words. The script holds no letters or ranges of its own. Put the table builder beside `fold_for_search` in `library_query.cpp` (declared in `library_query.h`) so the ranges are named once. Add a test there: every table entry equals `fold_for_search` of its key, "É" maps to "e", and "Ä" is present. Extend the "one stylesheet and one script" case to pin that the script reads the table and contains no accented letter.

Open question 2: no browser-level test. The unit tests pin the payload and the script text, and the uitest scripts open the pages.

The search field uses the artist exactly as the page shows it. After F4, that is `display_artist`, so a tag-only artist searches as "(unknown)".

## Goal

The Library search folds accents and matches word by word, in any order, across fields. The three report pages lowercase the joined fields and look for the typed text as one run. So "beyonce" misses "Beyoncé" on a page and "beyonce halo" misses a row with one word in each field. This task makes the pages search the Library's way, with the Library's fold as the only owner. Nothing here changes a score or a stored record. It runs after D2 because it rewrites the collector lines K1a and K1b just changed.

## What changes (finding 67, D48 Q31)

Today each page's `filter` (in `src/app/report.cpp`, `src/app/dm_report.cpp` and `src/app/fill_report.cpp`) does `toLowerCase().includes()` on the joined song, artist and charter (and the path, on the paths page). `visible()` in `src/app/html_page.cpp` lowercases the query the same way. Decision: the pages search the way the Library does.

Owner: `fold_for_search` in `src/app/library_query.cpp`, declared in `src/app/library_query.h`. The Library already stores each row's fields as `fold_for_search(strip_rich_tags(x))`; the helper that builds that text is the one the collectors call. If it is not public, `library_query.h` exposes it. No second fold is written, in C++ or in the page script.

Each page payload gains one search field: the folded, tag-free text of the fields that page searches today. The three collectors fill it. `visible()` in `html_page.cpp` lowercases the query, splits it on spaces and keeps a row when every word is in the row's search field. The per-page `filter` stops joining fields and reads the search field. On screen: "beyonce halo" finds a row whose song is "Halo" and artist "Beyoncé"; "halo beyonce" finds it too.
