# P0-3a: the hook that refuses full test runs from subagents

## The task in plain English

In step 2 one agent ran the whole `hydra_tests` suite seven times chasing a load flake, and reviewers ran the GUI suite five times. A rule now says agents run only filtered tests, but nothing enforces it. You write a hook that does. It denies, with a plain reason, any subagent command that runs `hydra_tests.exe` with no filter, runs `hydra_uitest --all`, or runs a hook test file (`test_h*.ps1`) for the third time. The main session is never blocked: its merge step runs the full suite on purpose.

A subagent's hook input carries `agent_id`; the main session's does not. That is how the hook tells them apart. Hooks fail loudly: the only answers are deny with a reason or allow. Never "ask" (an ask inside a subagent hangs it forever).

## What counts as filtered

`hydra_tests.exe` is doctest. A run is filtered when the command carries `-tc=`, `-sf=`, `-ts=`, `-sc=`, `--test-case=`, `--source-file=`, `--test-suite=` or `--subcase=`. A command that only lists tests (`-ltc`, `--list-test-cases`) or asks for help is not a suite run. `hydra_uitest` is denied only with `--all`; a named script passes. A hook test run is any command naming `tests\test_h<digits>_*.ps1`; the third such run from the same agent in the same session is denied, the first two pass. Match the exe by name wherever it sits (`build-cpp\Release\`, a worktree, `&`, `.\`, `Start-Process`), and say in the gate's header what spellings you match.

## Tests you may run

Only `tests\test_h20_suite_gate.ps1`, at most twice, in the foreground. Never any other `test_h*.ps1`, never `hydra_tests.exe`, never `hydra_uitest`.

Cases the test must hold, each fed as JSON with and without `agent_id`:
- an unfiltered `hydra_tests.exe` run: denied for a subagent, with a reason that names `-tc=` and `-sf=`; allowed for the main session;
- the same run with `-tc="single-owner rules hold*"`: allowed for both;
- `hydra_uitest --all`: denied for a subagent; `hydra_uitest state` allowed;
- three runs of a `test_h*.ps1` by one fake agent id: the first two allowed, the third denied; a different agent id starts its own count. The test cleans up its count files after.
- the gate, run through `dispatch_bash_ps.ps1` once, still yields the deny.
