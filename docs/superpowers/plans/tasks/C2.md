# C2: the shell path limit gets one owner

## The task in plain English

Windows has two path cut-offs and Hydra asks about both in several places. 248 is where `win32_path` starts adding the long-path prefix (that is `kPlainPathLimit` in `winstr.cpp`, `MAX_PATH` minus room for an 8.3 name, because `CreateDirectoryW` is the tightest call). 260 is the most the Windows shell (`ShellExecute`, Explorer, a browser's command line) will take. Today the 260 question is answered in `shell_path` twice, in `report_files.cpp` twice, and in a test once. The scan test knows two of those as "known copies" waiting for a fix. This task gives the question one owner, `fits_shell` in `winstr`, and points every other line at it. Then it widens the `std::filesystem` scan rule, wraps two `absolute` calls the rule will now catch, and records both numbers in ADR 0020.

This changes no display and no record. No score, path or stored record moves. The corpus scores byte-identical is the proof, and the main session checks that at merge; you do not run the corpus.
