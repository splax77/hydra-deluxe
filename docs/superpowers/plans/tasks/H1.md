# Task H1: the five shared test fixtures for phase 3

Task id: H1. Base: main at dc7e582. Branch: claude/p3-h1 (worktree `.claude/worktrees/p3-h1`).

## Goal

Every later phase 3 test needs the same five awkward inputs, and the plan forbids each task writing its own. You build those five fixtures once, in the two test headers, each with one sanity case that proves the fixture holds the fact it claims. You change no production code and no display text; this task is code-only and nothing on screen moves.

## The five fixtures

Two live in `tests/record_fixtures.h`, under its "fixture helpers" section, because they are hand-built records and paths like the helpers already there. Three live in a new `tests/display_fixtures.h`, because they carry display-side facts (audio length, a stored result, a title). The new header follows the old one's shape: `hydra::test` namespace, inline helpers, a plain comment on each saying what fact it holds. Grep `tests/` before adding any helper; a helper that already exists elsewhere is a review finding, and so is one defined in two files.

**1. A record with a tied top-score variant (record_fixtures.h).** Today a record's paths form a tree: `HydraRecord::paths` holds the roots and each `Path::variants` holds the tied variants under it (model.h, `struct Path` and `struct HydraRecord`; `flatten_paths` in model.cpp walks them root-first). The two screens disagree on what "optimal" means: `build_path_buttons` in path_view.cpp puts the whole first score group in the Optimal group, while `collect_rows` in report.cpp sorts by score and calls only rank 1 best. O1 adds `HydraRecord::is_optimal` (Q1: both tied paths are optimal) and K1a and K2 point the report and the Paths tab at it. They all need one record where a root and one variant under it share the top total score, with a lower-scoring second root so the tie is visible. No existing test builds this by hand; test_fast_tempo.cpp builds variant trees for a different purpose with a file-local helper, which you must not copy. The fixture is a helper that returns that record. Its activations go through the existing helpers in the same file (`set_plain_window`, `set_sp_meter`, `set_skips`), never by hand.

**2. A path with zero base score (record_fixtures.h).** Today `Path::avg_mult` in model.cpp returns 0.0 when `chart_base_score()` is 0, a divide-by-zero guard; `format_avg_mult` in display_format.cpp prints it with an "x". D48 Q33 keeps "0.000x" and records it, so no production code changes, but the step 3a draft (finding 310) asks for a case that pins the zero-base path either way, and no test builds one (test_stars.cpp's avg_mult case uses base 1300). The fixture is a helper that returns a path whose base, ghost and accent scores are all 0.

**3. A chart whose audio runs 5 s past its last note (display_fixtures.h).** Today the two bars measure position against different lengths. The Paths timeline divides by `store::song_length_ms` (the last note's onset, record_store.cpp) in `build_activations`, path_view.cpp. The Preview scrubber divides by `PreviewTransport::length_ms`, which `PreviewTransport::load` (preview_transport.cpp) sets to the larger of the last note and the audio end, and `build_scrub_marks` in preview_view.cpp uses that length. Q25 says both bars measure against the last note, the scrubber keeps the audio tail only as play range, and the beat lines run to the audio end. C4a builds the one fraction helper; K4a and K4b point the Preview at it and need one chart where the two lengths differ. The fixture is a helper that gives a small song (built with this repo's `beat_song` or `build_tail_song` from record_fixtures.h, not a new song builder), its last-note ms as `store::song_length_ms` reports it, and an audio end 5000 ms later. It carries numbers, not a playhead: test_preview_transport.cpp already has a file-local `make_playhead`, and the fixture must not duplicate it. test_preview_view.cpp's file-local `TwoActs` is a scene, not a length, so this fixture does not overlap it either.

**4. A batch result arriving for the open chart (display_fixtures.h).** Today only the single-chart path refreshes the song panel: `AppState::store_finished_analysis` in app_state.cpp saves, clears `parked_lookups_` and calls `refresh_viewed_record`, while the batch path (`update_background_jobs`, then `tick_library`) refreshes library rows only. Q16 says the open panel shows the batch's result straight away; K3 builds `store_changed_for` in app_state.cpp. Its test needs a Ready record stored for a chart behind the AppState's back, the way a batch stores one. test_app_state.cpp does this inline twice (in `seeded_store` and in "refresh_library_row picks up one chart's new result"): a `HydraRecord` with `sp_cap` and `ms_limit` set, added under a `RecordKey` of the chart's md5, the chart mode, `CapQuery::at(cap)` and the default `Settings` lens. The fixture is a helper that takes a `RecordStore`, an md5 and a cap, and stores exactly that record under exactly that key. It takes a store, not an `AppState`, because test_app_state.cpp's `ScratchPaths`, `seeded_store` and `app_on` are file-local and this task does not own that file; K3 points those two inline copies at the fixture later. An empty current-version record reads back Ready (test_store proves it), which is what the sanity case checks.

**5. A title made only of Clone Hero tags (display_fixtures.h).** Today `strip_rich_tags` in library_query.cpp knows the eight tags (`kRichTags`: color, size, b, i, u, s, sub, sup) and `title_or_unknown` in song.cpp turns an empty or old-placeholder title into `kUnknownTitle`, "(unknown)". Nothing joins them: `library_model.cpp` strips with no fallback, so a tag-only title is blank in the Library, and the three report collectors call `title_or_unknown` on `report::plain`, which strips only `<color>`. Q14 says one cleaned title everywhere, "(unknown)" when nothing is left; O3a builds `display_title` in song.h beside `title_or_unknown`, and K2, K3, K1a, K1b and K5 point the screens at it. They all need one title string that is nothing but tags. The fixture is a named string constant holding a title built only from tags in `kRichTags`, with at least one `<color=...>` pair and one bare pair such as `<b></b>`, so both strippers' gaps show.

## Owned files (only these may change)

- `tests/record_fixtures.h`
- `tests/display_fixtures.h` (new)

No CMake line: hydra_tests lists only `.cpp` files and test headers are found by include. The sanity cases live in the headers themselves. doctest keeps registered tests in a `std::set` keyed by file and line, so a case in a header included by many test files registers once. If a sanity case shows up twice in a run, stop and report; do not add a `.cpp`.

## Sanity cases to add (one per fixture)

Name every case with the prefix `fixtures:` so one filter runs them all.

- `fixtures: a record with a tied top-score variant` pins that `all_paths()` lists the root, its variant and the second root; that the variant's `totalscore()` equals the root's; that the second root's is lower; and that `best_path()` is the first root. No other literal.
- `fixtures: a path with zero base score` pins `chart_base_score()` as 0, `avg_mult()` as 0.0 and `format_avg_mult` of it as "0.000x" (D48 Q33).
- `fixtures: audio runs 5 s past the last note` pins that the last-note ms equals `store::song_length_ms` of the fixture's song and that the audio end is exactly 5000 ms later (the plan's 5 s). Pin nothing about which length a view divides by; that is K4a's and K4b's job.
- `fixtures: a batch result stored for one chart` stores the record in a `RecordStore` opened on ":memory:" (test_analysis.cpp's pattern) and pins `get_record` on the same key as `RecordStatus::Ready`, and on another md5 as `NotAnalyzed`.
- `fixtures: a title made only of tags` pins `strip_rich_tags` of the title as "" and `title_or_unknown` of that result as "(unknown)" (D48 Q14). Do not pin what `title_or_unknown` says about the raw tagged string; that is the bug O3a fixes.
