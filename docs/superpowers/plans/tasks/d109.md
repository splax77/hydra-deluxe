# Task D109: a sound device that won't start shows the muted-preview line

The user's decision is D109 in `docs/audit/2026-10-03-fix-decisions.md`. Read it first; it is the whole spec, and its wording is exact.

## Today

`PreviewAudioDevice::start()` in `src/audio/device.cpp` swallows a failed `ma_device_start`: `started` stays false and nothing is reported. A failed `ma_device_init` throws from the constructor. `PreviewController` (`src/ui/preview_controller.cpp`, the block that makes the device and calls `start()`) catches that throw and stores it in `audio_warning_`. `src/ui/preview_tab.cpp` then shows the line "No audio device found; the preview is muted." with the stored message as its hover. `audio_warning_` clears when the next song loads.

## The change

1. A failed `ma_device_start` reaches the same catch. Either `start()` throws like the constructor, or the controller checks `started()` after `start()`; pick whichever leaves one place deciding "the device failed". When it fails, the device is reset, as the open failure does today. Name the step in the message the hover shows, the way the constructor's message names `ma_device_init`.
2. The warning line's text becomes exactly "Hydra couldn't use your audio device; the preview is muted." for both failures. Update every place that pins the old sentence (grep `tests/` and `docs/` for it), including `docs/UserGuide.md` if it quotes it. If a public doc changes, say so in your report; that doc needs a doc review at the merge.
3. Update comments that say the warning means the device "would not open", so they cover a start failure too. Name the owner; don't restate the rule.
