## Goal

Seven small facts each have two homes. After this task each has one owner and the callers in your files call it. How the dump JSON names a squeezed-out chord: one reader in `replay_json.cpp`. How many frames 120 ms and 400 ms are at the Opus rate: derived from `kRate` through the frames owner. Which format a stem's bytes are: `sniff_format` decides once, including a FLAC hidden behind an ID3 tag, and the MP3 opener stops sniffing again. How many reservoir bytes an MP3 frame leaves: one `reservoir_after`, and `kMaxReservoir` defined from dr_mp3's macro. How a scanned path is keyed and how the settings read as text: bench calls J2-1's owners. How a scan row becomes a library entry: bench calls `to_library_entry`. How a test measures the worst sample difference: `max_diff` in `tests/audio_util.h`, eight times over.

## What changes

**One squeeze-out reader.** A small function in `tools/replay_json.cpp` owns "which field names this window's squeezed-out chord": when the activation carries a non-negative `sqout_tick`, the window gets the tick and no offset; only when it has no tick does the reader walk `sqinouts` for the `SqOut` entry's offset, still refusing a `SqOut` with no offset. `windows_from_json` calls it. The writer keeps writing both. Update the two pins: in "a path JSON becomes windows with the squeeze-out offset intact", the second window now has the tick 11532 and no offset (the first window still has neither), and the case's name and comment say that the tick names the chord and the offset is for dumps from before the tick existed; in "windows read from a path JSON match the ones read from the record", compare the ticks, and compare the offset only for a window with no tick (today's records always have one). Then check `tools/replay.cpp`'s `score` echo (around line 376): with a dump that carries ticks it now prints no `sqout_offset_ms` key. That is a developer-tool output field, recorded under "Decided at launch"; name it in your report so the main session sees it.

**Opus sizes from the rate.** `kMaxFrame` and `kPreRoll` become constants computed from `kRate` through `frames_of_ms(120.0, kRate)` and `frames_of_ms(400.0, kRate)`; since the owner is not `constexpr`, they become `const` values initialised once, which their run-time uses allow. Keep the comments saying 120 ms and 400 ms. "decode_audio: Ogg-Opus output is pinned bit for bit" and the Opus `StemReader` cases fail loudly if the derivation is wrong.

**`sniff_format` sees through ID3.** In `src/core/audio_sniff.cpp`, an ID3v2 tag is skipped (header, syncsafe size, footer when its flag is set, and again if another tag follows, as dr_flac does; see "Decided at launch") and the bytes after it are classified: "fLaC" gives Flac; anything else, including an MP3 frame sync or too few bytes left to tell, gives Mp3, which is today's answer for every tagged stream. A tag that does not fit in the bytes given is also Mp3, so the existing six-byte "ID3" check keeps its answer. Export the tag-length helper from `audio_sniff.h` as the one place that knows how long an ID3v2 tag is, and let `long_untagged_mp3` call it instead of parsing the tag itself. `open_ma_reader` takes the format `open_stem_reader` already sniffed and stops sniffing; `flac_behind_id3` goes. The `Mp3Reader`-fails-then-`MaReader` fallback stays as it is. A tagged FLAC reaches `MaReader` as before, by a shorter route; a plain or tagged MP3 reaches `Mp3Reader` as before.

**One reservoir rule.** `kMaxReservoir` is defined from `MA_DR_MP3_MAX_BITRESERVOIR_BYTES`, and a `reservoir_after(reserv, back, own)` helper in `ma_reader.cpp` owns the min-of-mins formula; `simulate_reset` and `build_seek_points` call it. The copied dr_mp3 declarations are not touched.

**bench calls the owners.** `scan_mode`'s brace copy becomes `to_library_entry(it)` from `app/analysis.h` (on main since M6-J1a), and its known-copy row comes out. `relify` goes; `row_json` calls `relative_slash_path`. `folder_breakdown`'s header is built from `describe_settings`' three pieces, in the shape "Settings: the GUI default (SP cap 4 bars, depth scores 4, timing cap 10 ms)." (the pieces' own words, D54), and J2-1's known-copy row for that line comes out.

**`max_diff` everywhere.** Each of the eight loops becomes a `testaudio::max_diff` call with the same window of samples: pass the expected samples' pointer already offset to the first compared frame (the helper compares `a[i]` with `b[i]` over the index range), keep each case's existing tolerance check as it is, and for the header-gain case build the doubled expectation once (a vector of twice the plain samples) and compare against it. Include `audio_util.h`; its includes are already in the test's link. `fixture_bytes` in that file duplicates `testaudio::read_fixture`; the ledger did not ask for it, so leave it and name it in your report.
