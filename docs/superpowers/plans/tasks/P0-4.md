# P0-4: warm worktrees

## The task in plain English

In step 2, eight agents made fresh worktrees and compiled from nothing at the same time. First builds took 150 to 360 seconds each, the CPU sat at 100 percent, and timing tests flaked. Two things could help: seed each new worktree with a copy of an existing `build-cpp` so the compiler has most objects already, or just stagger cold builds so at most three run at once. You measure which, and write the helper that does the winner.

The helper is `tools/new_worktree.ps1`. It takes a task id and a base ref, makes the worktree under `.claude/worktrees/` on a `claude/` branch (the names the task briefs use), and gets it to a built `hydra_tests` target. If seeding saves at least half the cold build time, the helper seeds. If not, the helper only staggers: it takes one of three machine-wide build slots before a cold build and holds it until the build ends.

## The quiet-machine rule

Two other sessions are building on this box. A measurement under load is not a measurement. Before each timed build, poll for `cl.exe`, `link.exe` and `ninja.exe` processes every 10 seconds. Wait until none has been seen for 60 seconds. Wait at most 20 minutes for that; if the box never goes quiet, measure anyway and report how many compiler processes were running at the start and the end of each timed build. Put that count in the report next to each number.

## What to measure

Two timed runs of the `hydra_tests` target, each in a fresh worktree from `main`, each with `Measure-Command`:
- **Cold:** configure and build from nothing.
- **Seeded:** copy the main checkout's `build-cpp` folder into the worktree (robocopy or `Copy-Item -Recurse`, time the copy too), re-configure so the cache points at the new tree, then build. The build must do only the work the copied objects do not cover.

Prove each built tree works by running `build-cpp\Release\hydra_tests.exe -tc="single-owner rules hold*"` once in it. That is the only test you run. Note that the main checkout's `build-cpp` may be mid-build by another session; copy it when the machine is quiet, and if the seeded build fails because the copy was half-written, say so and copy again.

## Done when

- The report holds one measured number for each option (copy time, configure time, build time, total), each with the compiler-process count beside it.
- `tools/new_worktree.ps1` does whichever won: seeding when the seeded total was at most half the cold total, otherwise slot-staggered cold builds. The decision and both numbers sit in the script's header comment.
- The helper, run once end to end on a scratch task id, leaves a worktree whose `hydra_tests.exe -tc="single-owner rules hold*"` passes. Remove that worktree after.
- The helper waits for a slot in the foreground and prints a line each minute while waiting, like phase 3's helper does.

## Report

The branch and last commit hash, the two measured totals with their parts and load counts, which option the helper does and why, the end-to-end run's test line, and anything you stopped on.
