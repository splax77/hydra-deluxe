## Goal

The two developer tools stop keeping their own copy of the app's settings and their own answer for an empty record. `hydra_replay` starts from `app::Settings`, changes only what a flag asked for, and keys a `--legacy-fills` run the way the app keys a "1.0 fills" run, so it can read the stored 1.0 row. Both tools print "no score" for a record with no paths the way `hydra_batch` already does. `hydra_bench` writes the same path text from a database as from a scan. No app behaviour changes.

## What the code does today

**198.** `struct Args` in `tools/replay.cpp` types every GUI default again: cap "4", ms "10", depth_mode "scores", depth 4, prodrums and bass2x true, difficulty "expert". `settings_from` starts from `app::Settings` and then overwrites every field from `Args`, flag or no flag, and re-types the unknown-difficulty-reads-Expert fallback that `Settings::difficulty` already owns. Its cap check throws below a typed 1 with a message that types "(4 is Clone Hero's rule)" by hand (139). `--depth -1` passes straight through and the search stops with "search reached a broken state" (311). `check_chart` in the same file already does it right: it reads `app::Settings` defaults directly.

**103.** `settings_from` never sets `legacy_fills`. So `cmd_dump` and `cmd_target` set `legacy_fill_deadline` on the search settings by hand, and `cmd_dump` never reads the database with the flag: it prints "--legacy-fills: analyzing under the Clone Hero 1.0 fill rule; stored rows are not read.", returns `source` "analyzed-ch10", and lets `--db` be omitted. The usage text's `--legacy-fills` paragraph says the same. The app keys a 1.0 run through `Settings::legacy_fills` (search and record key together), so a 1.0 row the GUI shows is never dumped.

**68.** `flag_bool` takes "1", "true" or "yes" for `--prodrums` and `--bass2x`; the help says `0|1`.

**98.** `emit_dump`, `cmd_target` (two lines, word for word the same) and `folder_breakdown` in `tools/bench.cpp` each write 0 for the best score of a record with no paths. (The scouts placed the bench copy in `corpus_bench`; it is in `folder_breakdown`, the per-chart folder mode.) `summarize_record` in `src/store/record_store.cpp` already owns the answer: `PathSummary::score` is absent for an empty record, and `hydra_batch` prints "-".

**108.** `scan_mode` in `tools/bench.cpp` runs each path through a `relify` lambda (strip the `--dump-rel` root, forward slashes). `dump_db` writes `notespath` and `rootfolder` as stored, absolute with backslashes, though its comment promises the same shape for diffing.

**38.** `windows_from_json` in `tools/replay_json.cpp` leaves a bare SqOut offset unresolved, and `cmd_score` then resolves it with `resolve_sqout_note`, where the record reader (`windows_for_path`) drops such a window. D51 keeps this.

## What changes

**`Args` fields become optional.** Each setting flag is absent until given. `settings_from` starts from `app::Settings` (with the loaded rules), sets only the fields whose flags were given, sets `legacy_fills` from `--legacy-fills`, then runs SE1's clamp once. The difficulty flag is stored as the word and handed to `Settings` as `view_difficulty`; `Settings::difficulty` owns the fallback, so the Expert fallback line goes. The cap check keeps refusing a cap below the floor (so `--cap 0` still exits with a message, rather than quietly becoming 4 the way the INI does), but the floor comes from SE1's table entry and the message prints `kCloneHeroSpCap` instead of a typed 4. The NotAnalyzed message in `cmd_dump` prints the cap, ms, depth mode and depth from the `Settings`, not from `Args`.

**`--legacy-fills` goes through `Settings`.** With `legacy_fills` set in `settings_from`, `to_analysis_settings` and `record_key` already carry the 1.0 rule together. Remove the hand `legacy_fill_deadline` overrides in `cmd_dump` and `cmd_target`, the whole "analyzing under the Clone Hero 1.0 fill rule; stored rows are not read" branch, the "analyzed-ch10" source (a 1.0 dump now reads "record" or "analyzed" like any other), and the rule that `--db` may be omitted with the flag. Rewrite the usage paragraph to say that `--legacy-fills` prices under Clone Hero 1.0's fill deadline and that `dump` reads the stored 1.0 row when the database has one.

**`flag_bool` goes.** `--prodrums` and `--bass2x` call SE1's `parse_bool`; a word it rejects is an error naming the flag and exits 2, as any other bad argument does.

**One result-block writer.** Add it to `tools/replay_json.h`/`.cpp`, next to `paths_json`, so `tests/test_replay.cpp` can pin it. It takes the record, calls `summarize_record(rec).score`, and writes the "result" object with `score` null and `bestpath` "" when the record has no paths. `emit_dump` and `cmd_target` both call it. `folder_breakdown` in `bench.cpp` prints "-" for the same case, from the same `summarize_record` answer.

**One row-to-JSON function in `bench.cpp`.** It takes the row's fields and the relative root and does what `relify` does today. `scan_mode` and `dump_db` both call it, and `dump_db` gains a `--dump-rel <root>` argument after its two positional ones. Without `--dump-rel`, both modes write absolute paths with forward slashes, as `scan_mode` does today.

**38 stays, with a comment.** At the `sqout_tick` block in `windows_from_json`, one comment names the CLI resolve step in `cmd_score` as the deliberate exception to the record reader's rule (a dropped window), and why: an old or hand-edited JSON is the only input that carries a bare offset, and the CLI prints which chord it picked.

No scan row; the pinned tests below guard the shared writer.
