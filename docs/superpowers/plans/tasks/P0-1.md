# P0-1: the pre-review script

## The task in plain English

Reviews took 14 rounds because the first reviewer was everyone's first check. About 29 of the 51 findings were mechanical: a test helper defined in two files, a test that recomputes the answer instead of pinning it, a new number with no decision behind it, a source scan living outside the one scan file. You write a PowerShell script that finds those before any reviewer starts, and prints one plain list the reviewer can quote.

The script is `tools/derive_once_precheck.ps1`. It takes a git range (default `main...HEAD`) and a repo path, and prints one line per item: the kind letter, the file and line, what it found, and why it counts. It never edits anything. It needs no build.

It makes four checks.

1. **Helpers defined twice.** Every function defined in more than one file under `tests/`, matched by name, and again by body with whitespace and identifier names normalised so a renamed copy still shows up. The audit's examples: `collect_variants` in three files, `deact_edge_at`, the MIDI delta writer, the `.srb` fixture, the minimal `.chart` writer in four places.
2. **Recompute spellings in tests.** An SP-end offset rebuilt from two timecodes (two `timecode(...)` calls with `.ms()` subtracted), a typed 500 or 2.0 beside a hit-window or squeeze check, `== 1.0` where `is_scaled` exists, a hand-written path walk, a re-count of tied paths. Take the full list from merge-gate.md section 4, the "Kind B" paragraph.
3. **New numbers with no decision.** Every numeric literal the range adds (code and tests, not comments or `#include` lines). For each, look for it in `docs/adr/`, `CONTEXT.md`, and the "User decisions" header or test-limits table of any plan under `docs/superpowers/plans/`. List the ones found nowhere. Common harmless values (0, 1, 2, -1, array sizes, loop bounds that match a container) stay off the list; say in the script's header which ones you skip and why.
4. **Scans outside the scan file.** Any file under `tests/` or `tools/` other than `tests/test_single_owner.cpp` that walks `src/` or reads source text (a directory iterator over `src`, an `ifstream` of a `.cpp` or `.h`). Also any scan row added to `test_single_owner.cpp` whose must-match or must-not-match example list is empty.

- The self-test passes, and it fails when any one of the four checks is turned off.
- The script's header comment says in plain English what each check looks for and what it skips.
