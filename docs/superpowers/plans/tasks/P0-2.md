## The task in plain English

Four short documents under `docs/agents/` tell each kind of agent how to behave, so no task brief has to repeat the rules and no agent has to learn them from a hook denial. One is shared by every agent (the preamble). One is the reviewer's brief, which already exists and gets updated. Two are new: the fix-round brief and the integrator brief. Every brief is under 120 lines and written in plain English: one idea per sentence, no nested bullet walls, no code listings (name commands and files; do not paste scripts).

## What each brief holds

**brief-preamble.md.** How an agent learns its id (the progress hook's first reply). The status line rule and the exact `status_append.ps1` call. The exact commit command with the four trailers as separate `-m` arguments, never on stdin. Stage by name, never `git add -A`. Read with offset and limit; never `sed`, `head` or `tail`. Run only the tests the task brief names, never the full suite. Commit before 110 calls. Helpers in the foreground. When blocked, stop and report the exact error. Never delete, move or rewrite anything outside the owned files and scratch. Plain English everywhere.

**derive-once-review.md.** Keep the rule, the inputs, the seven review steps and the output contract. Add: the reviewer is Sonnet and uses no helper agents (helpers parked a round for 27 minutes). Name the five recurring kinds A to E with one line each. Say the orchestrator hands over the precheck's output (`tools/derive_once_precheck.ps1`, task P0-1) and the reviewer quotes it rather than re-finding kinds B to E, then spends its pass on kind A. One paragraph per finding. Reuse the implementer's failing-first run from its report instead of rebuilding at base. One build at most, and only to prove a disagreement.

**fix-round.md.** The first fix round sweeps the whole range by kind, not just the listed instances: for each finding, grep for every other copy of the same question and fold them all. Each fixed finding carries a grep proof in the commit body that no copy remains. Production findings and test findings go to two fresh agents in parallel. Each is capped at 100 calls and commits per finding, so an agent that runs out leaves finished work behind. Name the precheck as the first thing to run after the sweep.

**integrate.md.** The integrator joins task branches onto the wave branch. Before merging, it lists the owner functions `main` gained since the fork (`git log --first-parent <fork>..main` and the scan rows those commits added) and checks the branch calls them instead of carrying its own copies. It runs the precheck on the joined branch, then the scan test and the docs test with their filters, fixes the join in the merge commit, and hands the key and range to the review. It never runs the full suite; the main session does that once.
