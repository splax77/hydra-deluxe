## Decided at launch (D53/D54 addendum)

The user said to use the recommended answer for everything. Recorded here:

- All three hash callers call `normalize_chart_hash`, including the two internal ones. Dropping the internal lowerings would change what a database with upper-case hashes shows, and a test pins that case; calling the owner keeps it and still leaves one spelling rule.
- `fill_report.cpp` keeps its two assignments that set `legacy_fills` to 1 and 0 on the two sides. They take the caller's lens as `Lens::from` built it and change the one field the comparison is about; rebuilding each side through `Lens::from` would mean decoding the lens's ms field back into an optional, a second copy of that encoding. Only the test's `key_for` switches to `Lens::from`.
- The chart count's owner is a file-local helper in `report.cpp` that both `build_html` and `generate_report` call, because `build_html`'s signature lives in `report.h`, which is not owned here.
- The corpus helper takes a count, because the report test needs several charts and the other two callers need one; `first_analyzed_with_paths` is the one-chart form and fails loudly when the corpus has none.
- The contrast header takes 0-to-1 channels, so each test converts its own colour type and the formula lives once. No new contrast case: the two existing colour cases are its test.
- The non-increasing order case is a guard; if it is red on the base, the task stops instead of keeping the re-sort quietly.
