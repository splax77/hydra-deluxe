## Goal

Seven small facts about what the Paths tab shows each live in two places. After this task each has one owner and the copies call it. No label, number, colour or pixel changes; nothing is stored.

What squeezing out a row costs, and whether a row is the squeezed-out chord: `core::sqout_cost` and `core::sqout_position` (J3-1 and D29's owner), read by the sentence and the table instead of two subtractions and a flag. ## Decided at launch (D53/D54 addendum)

The user said to use the recommended answer for everything. Nothing here is visible or stored, but these shapes had no decision written down:

- `measure_label` owns the one-based measure number and `format_measure` builds on it, rather than a third helper taking three numbers: the timeline needs only the measure, and the full form is the measure plus ".beat.tick".
- `first_measure_label` is `format_measure` of a default `Timecode`, which the timing header defines as tick 0 with its measure, beat and tick zeroed, so the first measure's spelling is derived and no "m1.1.0" literal remains in `src`.
- The backend table id builder lives in `path_view.h`, the app layer, because `paths_tab.cpp` has no header of its own and the plan already makes `path_view.h` the home of the tab's id text (J4-4's path button id).
- `longest_activation_badge` is derived: the longest word in the badge's own table plus the whole-ms form of `kSqueezeWindowMs`, which is the bound on every figure a badge can show (a non-free squeeze is inside the window; a required fill is within 60 ms). The audit's minus-sign worry is settled by `hardest()`: it only words timings that need hitting, and those are never negative. No new number: 999 goes, 500 is the window the model already owns.
- `timeline_start` is a view field like `timeline_end`, empty together with it, so the tab prints the view and decides nothing.
- `br.squeezed_out` stays for the sentence's wording, `summarystr` and the warning colour; only its use as a pricing position goes.
