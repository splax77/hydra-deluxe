## Goal

Which MIDI pitches the drum parser acts on: one marker-pitch table in `song.cpp`, with the note-off gate derived from it. Which notes file wins inside a .sng: `pick_notes_file`. ## What changes

**One marker-pitch table.** `song.cpp` names each marker pitch once (the solo marker 103, the flam marker 109, the Yellow, Blue and Green tom markers 110 to 112, the SP marker 116, the fill marker 120) and lists them in one table. `is_handled_note` asks the table for the markers and keeps the pad and 2x kick rules from `difficulty_chart_codes`. Both `optype` switches use the names as their case labels. The note-off gate becomes "a note-off on a pitch that is not a marker is dropped": every marker is 103 or above and every pad or 2x kick pitch is below it on every difficulty, so the answer is the same for every handled note, and the comment now says why. A `static_assert` beside the table pins that its lowest pitch is 103. Export a small `is_midi_marker_pitch(int)` from `song.h` so the test below can pin the table. No parse changes: the corpus invariants and the `.mid` cases prove it.

**The .sng loader calls `pick_notes_file`.** It collects the entry names, takes the pick's position and format, and keeps throwing "No chart files found in SNG file." when there is no pick. Its known-copy row comes out.

**The .srb loader calls `srb_read_metadata`.** It takes the fields and the notes offset from the owner and inflates the notes there. Delete the loader's own `kSrbHeaderSize` guard: the owner throws the same text on the same input, pinned by J1-5's case "srb: one reader gives the metadata and where the notes stream starts" and by "srb: malformed containers throw instead of crashing". Its known-copy row comes out.

**`difficulty_from_name` calls `equals_ci`.** If your base has `equals_ci` in `strutil.h` (J2-1 landed under you), the lambda goes and the two `std::tolower` lines J2-1 listed as known copies come out of `tests/test_single_owner.cpp`. If your base is main and `strutil.h` has no case-blind equals, leave the lambda, leave J2-1's known-copy rows alone, and say so in your report; the main session hands the line to J3.

**`Song::solo_sections`.** `Song` gains a vector of solo sections, each the first and last position (inclusive) in `sequence` of one maximal run of consecutive solo-flagged timestamps, in song order. One function in `song.cpp` builds it from the finished sequence, and both parsers call it where they already sort `practice_sections`, so the .chart and .mid loaders agree by construction. The rule is exactly the run rule the replay and the scene use today, so when J3-2 and J3-4 repoint them nothing moves; see "Decided at launch". Nothing stores a `Song`, so no record changes.

**Tests ask `chart_format_of`.** The two `test_song.cpp` checks, the `test_midi.cpp` check and `small_chart` compare `chart_format_of(path)` with `ChartFormat::Mid` or `ChartFormat::Chart` (include `parse/chart_files.h` where it is missing). Corpus files are all lower-case today, so the cases visit the same files.

**`check_invariants` takes a flag.** A second form (or a default argument) skips the activation-fill check; the ghost-kick case calls it with the flag and drops its loop. The three checks stay as they are.

**The EVENTS fixture uses `midi_util.h`.** The three tracks are built from `track_name`, `set_tempo`, `text_event` moved by `after(384, ...)`, `note_on` and `end_of_track`, and assembled with `smf_tracks`. Add a `note_off` builder to `midi_util.h` beside `note_on` (a delta-0 note-off with an explicit status byte), so the drums track keeps a real note-off rather than a zero-velocity note-on. The division moves from 192 to the header's 480; the case checks ticks and names only, so its pins stay. `put_varlen`, `put_meta`, `put_bytes`, `put_track` and the hand `MThd` go, and the two known-copy rows come out; the "Which test helper writes MThd/MTrk chunks?" rule then holds with no `test_song.cpp` baseline.
