## Goal

What one drum note is worth is written three ways today: `ChordNote::basescore` prices it in one line, and `category_scores` builds the same number twice more from eight running sums. Star Power is paid as "one extra copy" while the constant that says x2 sits unused. After this task the scorer prices each note once, as its base score times its combo multiplier, and everything else (the category shares, the Star Power share, the squeeze-out cut, the multiplier-squeeze gain) is read off that one value. The scorer also learns to say the combo after a chord and the solo bonus a chord earns, so the graph and the replay can stop counting those themselves in J3-2. On the stars side, `core/stars` gains the "cutoff plus solo bonus" figure the Stars tab and its GUI test add up themselves, and a `score_without_solo` the model's `avg_mult` can call in J3-1.

No score, path, record, label or pixel changes. This is the hottest function in analysis, so the real test is at the merge: the main session checks that every corpus score is byte-identical and the analysis time is within noise. Your pins only prove the per-note numbers did not move.

## What the code does today

**160 and 161.** `category_scores` in `src/core/scoring.cpp` steps the combo one note at a time and, for each note, adds to about twenty accumulators (`base_note`, `combo_cymbal`, `combospdynamic_cymbal` and so on). The chord's six totals are sums over those. The per-note `CategoryScores` (filled when `per_note` is given) spells `base`, `combo` and `sp` as sums of the same terms, and `dynamics_bonus` a third way. The squeeze-out cut on the same loop reads `note.basescore() * combo_multiplier`. `ChordNote::basescore` in `src/core/model.cpp` (line 81) is the one-line rule: 50, plus 15 for a cymbal, doubled for a ghost or accent. The audit's table: plain tom 50, cymbal 65, ghost tom 100, accent cymbal 130. The two agree on every note type, checked by the audit and by the "87" cross-check in `tests/test_stars.cpp`.

**162.** The scorer pays Star Power as exactly one extra copy of a note's value (the `sp_*` accumulators mirror the base and combo ones). `kStarPowerMultiplier = 2` in `src/core/timing.h` (line 27) is read only by `shown_multiplier`, which draws the Preview's disc. Nothing ties the two.

**163.** The solo bonus per chord, 100 times the note count when the chord is in a solo, is written in `ScoreGraph::build` (`src/search/graph.cpp` line 125 at the M_D tip) and in `replay_path` (`src/core/replay.cpp` line 175). Both read `kSoloBonusPerNote` from `model.h`; the small rule around it has no owner.

**164.** The combo after a chord is counted by the graph (`combo_ += timestamp.chord.count()`, `graph.cpp` line 139), by the replay (`combo += ts.chord.count()`, `replay.cpp` line 179), by the scorer (one note at a time, then thrown away) and by the test "the graph finds the chart's multiplier squeezes once, in chart order" in `tests/test_search.cpp` (line 130). `CategoryScores` already carries `multiplier_after`, the multiplier at the last note, but not the combo itself.

**166.** `path_stars` in `src/core/stars.cpp` (line 32) subtracts the solo bonus from the total before comparing with the cutoffs. `Path::avg_mult` in `src/core/model.cpp` (line 733) writes the same subtraction. `render_stars_panel` in `src/ui/stars_tab.cpp` (line 50) prints `cutoff + sc.solo_bonus` under "With full solo bonus", because `StarCutoffs` (`src/core/stars.h` lines 30 to 34) has no with-solo field. The GUI test `test_stars` in `tests/ui/uitest_details.cpp` (the loop near line 350 at the M_D tip) builds its expected text with the same sum, so a wrong sum in the tab would pass.

## What changes

**One note value.** In `scoring.cpp`, one small file-private helper prices a note at a multiplier: its `basescore()` times that multiplier. The loop in `category_scores` calls it once per note and derives everything from the result. The shares, in words: the combo category gets the value above 1x (the value minus the base score); the accent or ghost category gets the pad's 50 (`kNoteBasePoints`) when the note is a ghost or accent, and the base category gets the rest of the 1x value; the Star Power category gets `kStarPowerMultiplier - 1` copies of the whole value (162); `dynamics_bonus` is what the note earns above a plain note of the same pad and cymbal type at that multiplier; the squeeze-out cut is the value itself (161). The twenty accumulators go, and so does the header comment in `scoring.h` that defends them ("kept rather than folded together so a change ... can be diffed against the history"); replace it with one sentence naming `basescore` as the owner. `multsqueeze_gain`'s two `basescore() * multiplier` lines call the same helper. Keep the loop allocation-free and branch-light: this function runs once per chord per path candidate across the whole corpus. Do not change `Chord::notes(true)`, the order notes are read in, or where `sqout_rule` applies.

**`combo_after` on `CategoryScores`** (164's owner): the combo after the chord, the caller's combo plus the chord's note count. Filled on the chord total; on a per-note entry it is the combo after that note (so the last note's equals the chord's). The graph, replay and test callers wait for J3-2 and are listed as known copies.

**`solo_bonus(const Chord&, bool flag_solo)`** declared in `scoring.h` beside `category_scores` and defined in `scoring.cpp` (163's owner): `kSoloBonusPerNote` times the chord's note count when the flag is set, else 0. Its two callers wait for J3-2.

**`StarCutoffs::with_solo`** (166's owner): a seven-entry array beside `cutoffs`, filled by `star_cutoffs` as each cutoff plus the solo bonus, with a header comment saying what it means (the score you see at that cutoff if you collect every solo bonus). `render_stars_panel` prints `sc.with_solo[stars - 1]`; the GUI test's loop reads the same field. Also **`score_without_solo(const Path&)`** declared in `stars.h` beside `path_stars` and defined in `stars.cpp`: the total minus `score_solo`. `path_stars` calls it. `avg_mult`'s line in `model.cpp` waits for J3-1 (phase 7 wave 2 owns `model.*`) and is a known copy.
