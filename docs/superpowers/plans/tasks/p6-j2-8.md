## What changes

**`far_time(cfg, now_s, speed)`** is a new exported function in `highway_draw.h`/`.cpp`, and `time_to_z`, `z_to_time` and `build_highway_draws` call it. `build_highway_draws` may equally take its far edge as `z_to_time` at `z_future`, as long as the formula is typed once.

**`track_rect(cfg, width, height)`** beside `track_height` returns the clamped width and height, the track height, the camera aspect (width over track height) and the track's top row (height minus track height). `track_height` stays exported (the tests and J1-3's renderer case call it) and becomes a read of the rect, so the clamp lives once. `project_to_image` and `bottom_left_room` read the rect instead of clamping and dividing themselves. `PreviewRenderer::resize` stores the rect and `render` reads its aspect; the fade rectangle converts the rect's track height and image height to screen coordinates where it does today, so the -1 to 1 maths stays in the renderer but the anchor comes from the owner.

**One fan helper** in `obj_loader.cpp`'s anonymous namespace: given a mesh and a polygon's corners as vertices, it pushes the fan from corner 0. `load_obj` builds its corner vertices and calls it; `push_quad` becomes a call with four corners (or goes, with `make_flat_quad` and `make_box` calling the helper). Vertex order must be byte-identical to today; "load_obj fan-triangulates quads and keeps per-corner attributes", "make_flat_quad" and "make_box" pin it.

**`widest_word`** becomes the widest line of `wrap_words(text, 0, width_of, keep_last)`: a zero width makes every allowed break a line, so the widest line is the narrowest box. Its `text.find(' ', start)` walk goes. The existing `widest_word` case must pass with no pin edited.

**The json owns the numbers.** In `preview_config.h`, every Onyx value leaves the struct: the member initializers of `PreviewConfig`'s nested structs and `LightConfig`'s three colours become empty braces (value-initialised), so a `PreviewConfig` that was not loaded holds zeros, never Onyx's numbers. `Color`'s white and `Vec3`'s origin stay, because they are the types' own defaults and `Material` relies on them. The header comment ("with Onyx's values as the defaults so a missing key changes nothing") is rewritten to say the json is the one source and a missing key is an error. In `preview_config.cpp` the `get_*` helpers stop keeping a default: a key that is absent, or present with the wrong type, throws `std::runtime_error` whose message starts `3d-config.json: missing key ` followed by the key's dotted path as it reads in the file (for example `track.time.secs_future` or `objects.gems.light.ambient`). `text.time_box.font` stays unread. The malformed-JSON error keeps its text. The controller's `kOnyxDefaults` line is not yours (J3-5 deletes it); after your change it returns a zeroed struct that nothing reads, and you say so in your report so J3-5's brief can quote it.

**The tests load the shipped file.** New header `tests/preview_config_util.h` (header-only, like `tests/audio_util.h`; no CMake change): `shipped_preview_config_text()` returns the text of `HYDRA_ASSET_DIR` plus `/3d-config.json` through `hydra::read_file_text`, and `shipped_preview_config()` returns a reference to one static `PreviewConfig` loaded from it. Every `PreviewConfig cfg;` in `test_highway_draw.cpp` and `test_overlay_layout.cpp` becomes a copy of `shipped_preview_config()`. In `test_preview_config.cpp`, "PreviewConfig defaults are Onyx's 3d-config.yml values" is deleted; "the shipped 3d-config.json loads to the Onyx values" keeps every literal in `check_is_onyx` (a pin from a run, D42) and gains the one pin the deleted case held alone, `sp_active_color` as `#6cf7c6`; "keeps defaults for missing keys" is replaced by case 1 below; "reads the time box size and margin" keeps its 20 and 12 but builds its input from the shipped text with those two values changed (parse it with `nlohmann::json`, which `hydra_tests` already includes from `third_party/json`, set the two keys, dump). `is_background` in `test_preview_renderer.cpp` compares each channel to the renderer's own `config().view.background` scaled to a byte, so the hex literal goes.

The lane loop iterates `state.make_lane_bounds(win, near_t, far_t)` and draws each `LaneSpan` with its own pad through the existing `strip_tex` and `target_tex(pad, true)`; the two instant scans and the fallback go.
