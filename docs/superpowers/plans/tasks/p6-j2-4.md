## Goal

Ten small facts about the app's state, its jobs and its toolbar each live in two or three places. After this task each has one owner and the copies call it, and nothing on screen changes: every label and every time keeps its exact text and value.

Is a batch or an analysis running: `AppState::batch_running` and `AppState::analyze_running`, which already exist. How many charts the library holds: `LibraryModel::rows().size()`, so the `library_total` cache goes. How long the UI trusts a cached "this file exists" answer: one caching helper in `AppState` with one interval. What a failed job records: a protected `fail(e)` in `ResultJobBase`. What the toolbar's batch button says while a search is typed, and what the song panel's Analyze button says: one exported label function each. How long the status line stays: `kStatusFadeSeconds`, which the GUI test turns into frames. How a scan row becomes a library entry, and how a library entry becomes a scan row: `to_library_entry` (J1-6's owner) and one named reverse. How many workers a batch gets: `batch_worker_count` alone; the third floor goes. Which charts a batch analyzes: the rows the library screen shows; the dead search-string `BatchJob` goes.

## What changes

**The running guards call their owners.** `start_batch` and `start_analyze` test `batch_running()` and `analyze_running()`. The toolbar's `batch_busy` becomes `app.batch_running()`. The harness's two lines call the owners too. The harness's state dump, which prints "finished" or "running" per job, answers a different question and stays.

**`library_total` goes.** The field and its assignment in `reload_library` are deleted. The four readers read `app.library.rows().size()`, the same expression the heading uses. The `matches()` count stays what it is: the filtered view, a different number.

**One cached file check.** `app_state.h` gets one small helper type that holds a "checked at" time and a cached answer, looks again once `kFileCheckSeconds` has passed or when it has been reset to "look now", and otherwise returns the cache. `details_ui`'s chart-file pair and `library_ui`'s report-file pair become two instances of it; `selected_file_ok` and `report_file_shown` call it with their probe (`file_exists_utf8` on the chart path, `app::report_file_exists`). `kReportCheckSeconds` is deleted; `kFileCheckSeconds` is the one interval (D54). `close_details` and the new-report path keep resetting their instance to "look now". Both existing tests pass unchanged, timestamps included.

**`fail(e)` in the base.** `ResultJobBase` gets a protected `fail(const std::exception&)` that records the raw text, the plain message unless the job is cancelled, `ok_ = false` and then publishes `finished_`. `run_guarded`'s catch calls it, and so does `AnalyzeJob::start`'s catch; the four hand-written lines in `library_jobs.cpp` go. `finished_.store(true)` then appears only in `job_base.h`.

**Two label functions.** `library_toolbar.cpp` exports `analyze_search_label(int64_t count)`, declared in `library_parts.h` beside `render_actions_row`, returning exactly today's text; the button label and the width sample call it, and the two copies in `uitest_batch_reports.cpp` call it. `details_panel.cpp` exports `analyze_button_label(store::RecordStatus)`, declared in `details_view.h`, returning "Analyze this song" for NotAnalyzed and "Re-analyze" otherwise; the headline, its width sample (the NotAnalyzed label, the wider one) and the harness's `analyze_button_ref` call it. Neither function touches ImGui, so a unit test can call them.

**`kStatusFadeSeconds`.** `AppState` gets `static constexpr double kStatusFadeSeconds = 6.0;` beside its other named UI timings, with a comment saying what it is (how long a neutral status line stays; problems never fade). `render_status_line` reads it. `test_status_line` stops yielding a bare 400: it yields the fade's length in the harness's fixed frame time plus one frame, so the check lands on the first frame on which the line is gone, in both of its waits. The frame time is `ImGui::GetIO().DeltaTime`, which the harness fixes at 1/60 s in Fast mode; do not type 60 or 400. The known-copy row for 219 in `test_single_owner.cpp` comes out, and the C4b rule then holds with no exception.

**Both scan-row conversions have an owner.** `ScanJob::run` calls `to_library_entry`. For the reverse, `library_jobs.h`/`.cpp` gets `scan_item_of(const store::ChartLibraryEntry&)`, which copies the six fields the brace list copies today by name and leaves `sig` as it is today (empty). `BatchJob::run` calls it. If you find anything downstream of `BatchJob` reading `ScanItem::sig`, stop and report; nothing should.

**`set_analyzer_for_test` trusts its count.** The `std::max(1, workers)` goes; the count is stored as given. Every caller in `tests/test_library_jobs.cpp` passes 1 or 2, and a 0 would now be refused by `run_work_pool` with its J1-6 error instead of being quietly repaired. No new test; the existing `jobs:` cases are the test.

**The search-string `BatchJob` goes.** Delete the first constructor, the `search_` member and the `list_chart_library` call in `BatchJob::run`; the given rows become a plain vector, not an optional. The store's search parameter itself is J4-2's (`record_store.*` is frozen in J2); leave it. Nothing visible changes, because nothing built the search-string job.
