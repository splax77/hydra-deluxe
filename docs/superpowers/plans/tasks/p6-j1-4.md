## Goal

## What changes

**One frame pair in a new header under `src/audio`.** Name it `src/audio/frames.h` unless you find a better name (say which in your report). It is header-only, so no CMake change, and it includes nothing from miniaudio, so the UI can include it. `frames_of_ms(ms, sample_rate)` rounds the way `seek_ms` rounds today (`llround`), and `ms_of_frames(frames, sample_rate)` divides the way `position_ms` does. `Playhead` calls both; its "no source, so rate 0" guards stay in the player, because they are about a missing source, not about the conversion. The load-job caller waits for J3-5.

**One `stem_converter_config` for both mixers.** It takes the input rate and channels and the output rate and channels, and gives back miniaudio's converter config together with whether the stem is a passthrough. `convert_stem` and the `StreamMix` constructor both call it, so the converter settings (the miniaudio defaults, D54) are typed once. Its declaration needs miniaudio's config type: put it in `src/audio/mixer.h` or `stream_mix.h`, whichever both `.cpp` files can include without the new frame-pair header pulling miniaudio into the UI (today only `src/audio` files and two tests include miniaudio or `mixer.h`; check before you choose).

**The gain floor stays where it is.** `Playhead::set_gain` does not change. This task adds the scan row and keeps the existing gain case green.

**One test helper header, `tests/audio_util.h`.** Header-only like `tests/srb_util.h`, it holds `read_fixture(name)` (the bytes of `testdata/audio/<name>`) and `estimate_freq_hz(audio, channel)` (the mixer file's form; the decode file's callers pass channel 0). Both test files include it and lose their copies, and `test_stream_mix.cpp`'s `fixture` becomes a call to `read_fixture`, including inside AU1's new case. `test_stem_reader.cpp`'s path builder is listed as a known copy for J2-6, not edited.

**The mixer oracle goes.** Delete `reference_mix`. The bit-for-bit case becomes a pin on stems a person can add: three mono stems already at the output rate (so no resampler runs), with sample values that are exact in a float (quarters and eighths), lengths 3 and 2, and one stem with zero channels, which adds nothing. The expected mix is the hand sum, compared with the file's existing `same_bits` (exact bits, not `Approx`). The mixed-rate path keeps its existing frequency case, "mix_stems resamples to the output rate and unifies channels", which does not need a second mixer.
