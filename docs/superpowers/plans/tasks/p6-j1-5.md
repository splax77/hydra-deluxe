## What changes

**`pick_notes_file`** goes into `src/parse/chart_files.h`/`.cpp` beside `notes_file_format`. It takes the names in a listing (folder entries or .sng entries, as plain strings) and returns which one is the notes file and its format: the first name that is a notes.mid, else the last name that is a notes.chart, else none. Both rules are today's. No caller changes here; J1-6 (the scan) and J2-3 (the .sng loader) call it.

**The .srb reader** goes into `src/parse/srb.h`/`.cpp`: one function over a `ByteSource` that inflates the metadata block at `kSrbHeaderSize`, parses its string table, and returns the parsed fields, whether the table parsed, and the offset where the next stream (the notes) starts. Call it `srb_read_metadata`. It throws what `srb_inflate_stream_reading` throws on corrupt or truncated input, and a source of `kSrbHeaderSize` bytes or fewer throws too, as the loader does today. The Preview's audio walk later continues from the returned offset (J2-5); the loader (J2-3) and the scan (J1-6, through `memory_byte_source` over the head bytes) call it for the metadata.

**`find_song_ini`** goes into `chart_files.h`/`.cpp` beside `is_song_ini`. The one answer is a pick over a folder listing (`DirEntry` entries from `core/winstr.h`, which `srb.h` already includes): the first non-folder entry whose name `is_song_ini`, or none. A second form takes a folder path, lists it with `list_dir` and picks. The listing form exists so the scan (J1-6) can pick from the entries it already has instead of listing every folder twice. First match wins, the Preview's rule; see "Decided at launch". The private copy in `preview_source.cpp` keeps its name and stays until J2-5; C++ lookup finds the file's own private function first, so nothing there changes or breaks. If the build says otherwise, stop and report.

**`parent_folder`** goes into `src/core/winstr.h`/`.cpp` with `parent_of`'s exact rule: strip trailing separators, cut at the last slash or backslash, and return empty when there is none. See "Decided at launch" for why that rule and not the other. No caller changes here (J1-6, J2-1, J2-5).

**`shell_execute_ok`** goes into `winstr.h`/`.cpp` and owns "above 32 means success". `winstr.h` must not include `windows.h` (it takes handles as `void*` elsewhere), so the function takes the ShellExecute result as a plain pointer or integer and the two callers cast once at the call. Both callers are yours: `shell_open` in `report_files.cpp` and `show_in_folder` in `win32_dialogs.cpp` call it, and the two `> 32` lines go.

**`MidiFile::from_file`** becomes a one-line read through `read_file_bytes`. The `fopen_utf8`, `fseek`, `ftell` and `fread` lines go. The error on a missing file is now `read_file_bytes`' own `std::runtime_error` starting "cannot open file: " (D54). `plain_error_text` already maps that prefix to the same sentence the user sees, and the song loader already reads through `read_file_bytes`, so nothing visible changes. The three known-copy rows for `midi.cpp` come out of `tests/test_single_owner.cpp`; the "How many bytes does a file hold?" rule then holds with no `midi.cpp` baseline.

**`tests/sng_util.h`** is a new header, no new .cpp and no CMake change. It takes `test_sng.cpp`'s `make_sng` body and its two little-endian writers as they are (same signature: the metadata pairs, then the files), under a `testsng` namespace like `srb_util.h`'s `testsrb`, and reads the prefix length and mask size from `kSngXorMaskOffset` and `kSngXorMaskSize` in `src/parse/sng.h` instead of bare 10 and 16. `test_sng.cpp` includes it and drops its own copies; its fixtures must stay byte-identical, which the file's own cases prove. `test_preview_source.cpp`'s copy (J2-5) and `write_sng_with_metadata` (J1-6) are not yours. Note for J2-5, in the header comment: that copy has a "no pairs means 20 junk bytes" mode; the shared one writes a real empty block.

## Decided at launch (D53/D54 addendum)

The user said to use the recommended answer for everything. These two edge rules had no recommendation written down, so they are recorded here:

- `parent_folder` takes `parent_of`'s rule (strip trailing separators; empty when there is no separator), not `dir_name`'s. Reason: the scan is the one caller that can meet an edge, because the user's song folder arrives exactly as typed, trailing slash included, and `rootfolder` is a stored library field; keeping `parent_of`'s answer keeps every stored row byte-identical. The other two callers only ever pass full paths with a file name, where the two rules agree.
- `find_song_ini` keeps the first match, the Preview's rule. On a Windows folder there is never a second, so the scan's switch from last to first (J1-6) changes nothing.
