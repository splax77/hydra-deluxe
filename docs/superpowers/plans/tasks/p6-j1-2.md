## What the code does today

**208.** `setup_imgui` in `src/ui/app_shell.cpp` types `18.0f` three times: the main font (line 242), the mono font (line 244) and the merged CJK fallback (line 262). ImGui scales merged glyphs by the ratio of the two sizes, so the CJK merge must read the same number as the main font; today nothing ties them together.

**210.** `main.cpp` reads the primary monitor's scale from the ImGui Win32 backend (`ImGui_ImplWin32_GetDpiScaleForMonitor`, line 106) and hands it to `setup_imgui` and to the default window size. After the window exists it asks the backend again for the window's monitor (`ImGui_ImplWin32_GetDpiScaleForHwnd`, line 173). Hydra's own rule, `ui_scale_for_dpi` in `app_shell.cpp` (line 163, DPI over 96, and 1.0 for a reported 0), serves only the `WM_DPICHANGED` path (`main.cpp` line 424). The two rules agree at every real DPI; they differ only at a reported DPI of 0, where the backend gives 0 (an unusable window) and Hydra gives 1.0.

**211.** `parse_layout_line` (line 143) and `remember_library_share` (line 150) in `app_shell.cpp` each write the open interval `> 0.0f && < 1.0f`.

**270.** The frame clear colour, 0.10, 0.11, 0.13, 1.0, is typed in `main.cpp` (line 180, as an `ImVec4` that line 280 premultiplies by its alpha) and again in `tests/ui/uitest_harness.cpp` (line 218, as four floats).

**293.** `Harness::init` in `uitest_harness.cpp` (lines 174 to 179) calls `D3D11CreateDevice` for a WARP device itself. `warp::make_device` in `tests/warp_util.h` (lines 16 to 23) does the same thing with the same arguments and the same `ComPtr` types, and the renderer tests call it.

**294.** "Does this name select this test" is written three times: `Harness::queue` (`uitest_harness.cpp` line 148, `what == "all" || what == t->Name`), and `run_parallel` in `tests/ui/uitest_main.cpp` twice (line 83 for the chosen tests and line 93 for the "no such test" check). The script-file step in `queue` (a name that is an existing file runs as a script) is a different question and stays.

**276, the app-shell line.** "app_shell: set_ui_scale rescales sizes, fonts and px() together" in `tests/test_app_shell.cpp` (lines 190 to 191) checks the scaled frame padding against its own recomputation of ImGui's truncation, `float(int(before * 2.0f))`. `scaled_style` in `app_shell.h` (line 125) is the production rule and is already exported.

## What changes

**One `kFontSize`** in `app_shell.cpp`, set to 18.0f, read by the main, mono and CJK loads. A file-local constant is enough; nothing outside the file needs it.

**The startup scale** in `main.cpp` goes through `ui_scale_for_dpi`. Both backend calls go. In their place one small helper in `main.cpp` reads a monitor's DPI the way the backend does inside: ask `GetDpiForMonitor` from `shcore.dll`, loaded at run time (the project does not link `Shcore.lib`, and `CMakeLists.txt` is not yours), and fall back to the screen DC's `LOGPIXELSX` when that call is missing. The primary monitor read at startup and the window's monitor read after `CreateWindowW` both pass that DPI to `ui_scale_for_dpi`. The `WM_DPICHANGED` path already does. The result is the same number at every real DPI (D54), so nothing visible changes; the only difference is DPI 0, which Windows has never reported.

**`share_is_valid(float)`** in `app_shell.h`/`.cpp` owns the open interval. `parse_layout_line` and `remember_library_share` call it. Exported, so the test can pin it.

**One clear-colour constant** in `app_shell.h`, holding the four components. `main.cpp` builds its `ImVec4` from it and keeps the premultiply at line 280 as it is; `Harness::frame` reads its four floats from it.

**`Harness::init`** calls `warp::make_device(device, context)` and drops its own `D3D11CreateDevice` call; the error message on failure stays. The render-target creation after it stays where it is. If `warp_util.h` is not on the GUI runner's include path, include it by relative path from `tests/ui`; do not touch `CMakeLists.txt`. This task owns `uitest_harness.cpp` only for this finding (293), the clear-colour read (270) and the select function (294); every other line in it belongs to J2-4 and J4-4.

**One select function** in `uitest_harness.h`/`.cpp`, say `selects(what, test_name)`, true when `what` is "all" or equals the test's name. `Harness::queue` and both loops in `uitest_main.cpp` call it; the script-file branch in `queue` stays.

**The app-shell test** compares the scaled frame padding against `scaled_style(base, 2.0f).FramePadding.x`, where `base` is a copy of the style taken before `set_ui_scale`, instead of recomputing the truncation.
