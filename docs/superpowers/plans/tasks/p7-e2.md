## Goal

A multiplier squeeze is a chord that straddles a multiplier step (combo 10, 20 or 30), so the order you hit its notes changes the score. Two questions: does this chord straddle a step, and what does the right order gain? `to_multiplier` in `src/core/timing.cpp` owns the steps and `category_scores` in `src/core/scoring.cpp` prices each note at its own multiplier. `MultSqueeze` in `src/core/model.cpp` answers both questions its own way and gets 4- and 5-note chords wrong. After this task `MultSqueeze` asks the owners. The user's note: such chords never appear in a real drums chart, but Clone Hero allows them, so Hydra must get them right. Scores do not change; the stored multiplier-squeeze list does, so this task changes stored results. The results stamp stays "2.1.0".

## What the code does today

**49.** `MultSqueeze::applies` accepts a chord only at combos 7, 8, 17, 18, 27 and 28, then asks that the chord's last note land on the step or one past it, then rejects a chord whose notes are all worth the same. `category_scores` prices note i of a chord at `to_multiplier(combo + 1 + i)`, notes in base-sorted order. The two disagree for 4-note chords at combos 6, 8, 16, 18, 26 and 28 and for every 5-note chord. The comment above `applies` admits it and says the reason is not recorded. `ScoreGraph` in `src/search/graph.cpp` asks `applies` of every chord and stores the squeeze.

**50.** `MultSqueeze::points` returns the dearest note's value minus the cheapest note's, which assumes one note crosses the step. On a 4-note chord at combo 7 two notes cross. Kick 50, red 50 and two cymbals 65 at combo 7: the best order is worth 360 and the worst 330, so the real gain is 30; `points()` says 15. `build_multsqueezes` in `src/app/path_view.cpp` shows that number as "(+N pts)" and `multsqueeze_summary` adds them up.

**247.** `MultSqueeze::multiplier` is `to_multiplier(combo) + 1` and `MultSqueeze::direction` is "high" when combo mod 10 is 7, "low" otherwise. Neither reads the payouts. `howto` names the edge notes from `direction`, with a special case for 3-note chords.

**335.** The scoring values Hydra took from Clone Hero (`kCymbalBonusPoints` 15, `kSoloBonusPerNote` 100 in `src/core/model.h`; steps at combos 10, 20 and 30 in `to_multiplier`) have no recorded decision. D51 call 13 records them as they are.

Storage: `src/store/path_codec.cpp` stores each squeeze as its chord code and combo only; `points`, `multiplier` and `howto` are recomputed on read. So existing records change bytes only where the chart holds a chord this task newly lists.

## What changes

Owner of "does it straddle": `to_multiplier`. `MultSqueeze::applies` becomes: the chord straddles when `to_multiplier(combo + 1)` is less than `to_multiplier(combo + chord size)`, and not every note is worth the same. No combo list, no mod-10 rule, no size limit. The comment above it goes; replace it with one sentence citing D51 call 3 and the user's note.

Owner of "what does the order gain": one new function in `src/core/scoring.h`/`.cpp`, say `multsqueeze_gain(chord, combo)`: the best order's total minus the worst order's total, each note priced at its own `to_multiplier` step the way `category_scores` prices it. The best order is `Chord::notes(true)` (cheapest first); the worst is the reverse. `MultSqueeze::points` calls it and nothing else.

`multiplier` and `direction` read the payouts, not the combo. The multiplier is the one the last note in the best order is paid at. The notes that cross are those paid at the higher multiplier in the best order. `howto` names every note that crosses (D51 call 3). Keep every sentence the existing tests pin: when exactly one note sits alone on its side of the step, name that note ("Hit [Kick] first.", "Hit [YellowCym] last."); when both sides hold the same number of notes, name the cheap side with "first.", which is what today's 2-note pins say. The wording when several notes must be placed is an open question below.

`category_scores` and `to_multiplier` do not change. The one 335 comment goes in `src/core/scoring.cpp` above `category_scores`, since the constants' home `src/core/model.h` is not an owned file: cymbal +15, solo 100 per note, steps at combos 10, 20 and 30, recorded as they are by D51 call 13.
