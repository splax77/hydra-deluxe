## Decisions this plan makes

These are the plan's own choices. The user's yes to the plan approves them.

**Where the cards go.** The cards go to `docs/sessions/`, one file per session with its current name (`<date>-<id8>.md`), and `index.md` goes beside them. The audit blocks, reference pages and memory notes name cards by session id, so keeping the names keeps those links.

**What stays outside.** The condensed transcripts and the pipeline's working files stay in `C:\Users\Patrick\.claude\projects\C--Users-Patrick-Downloads-Hydra-hydra-test\session-cards\`. They are inputs to card writing, not documentation. The card tools still read the transcripts to write new cards; no permanent doc cites one.

**How a new card reaches the repo.** The card tools write new cards and `index.md` straight into the main checkout's `docs/sessions/`. After `check.py`, `index.py` and `link_memory.py`, the main session runs the docs check (`hydra_tests.exe "-tc=docs match code*"`). Then it stages the new cards and `index.md` by name and commits on `main` with the usual trailers. The start hook's printed steps say this. No reviewer is needed, as above.

One hole in that design is A1's to close before it builds. The start hook also fires in sessions that run in a worktree, and `main` is checked out only in the main checkout. The memory note `agents-write-only-their-own-worktree` says a hook refuses an agent's write into another worktree. This review found that refusal only in the older `hooks\` folder, not in the current `gates\` folder, so whether it still holds is unchecked. If it does, card writers in a worktree session could not write into the main checkout, and the main session could not commit there. A1 settles this first: it either takes the cards root from the session's own top folder, so the cards ride that session's branch to `main`, or it shows by a test that the fixed main-checkout path works from a worktree. A1 reports which one, because it changes where a new card first lands. A `.gitattributes` line keeps `docs/sessions/*.md` byte for byte (`-text`). Without it, line-ending changes in a checkout would change a card's sha. `prune_list.py` would then hold that session back until `check.py` ran again.

**Cards are public from now on.** `writer-brief.md` gets one short section. It says cards are published, so a card holds no secret, token or key, and names no file outside the repo except as "kept locally" or "not kept". A file that lived in a scratch folder is described as "a scratch file, not kept", never by its path.

**Plan decision blocks get a permanent home.** Before a plan with a "User decisions" or "Test limits" block leaves, the block is copied word for word into the decision log `docs/audit/2026-10-03-fix-decisions.md`. If the block belongs to an existing D-record, it goes under that record. Otherwise it goes under a new D-record that names the plan and says the block was copied when the plan left the repo. Check 3 then reads it from the log. This keeps the user's rulings, which are permanent, and needs no precheck code change.

**Citations of removed files keep their words.** A permanent doc that cites a removed plan or handoff as history keeps the line. The path is rewritten to say the file left the repo and how to read it: "`<path>` (removed; `git show <commit>:<path>`)", where the commit is the last one on `main` that holds it. Audit records keep their quoted words and line numbers, so no recorded finding or verdict changes. Where the citation backs a fact, the fact moves first and the citation points at its new home.

**Cards keep their plan and handoff paths.** The 90 lines in cards that name a plan or handoff are left as written. A card records what a past session did, at that time, the way a commit message does. The new dangling-path check (task B2) skips `docs/sessions/` for that reason, and so does rule 4 of "The rule for finished" below. Without that skip, the 80 cards that name a plan or handoff would keep it in the repo for good.

This narrows the handoff's "never leave a permanent doc pointing at a removed file" (handoff, Part B, item 2) in two places, and the user should see both. First, the cards. Second, the rewritten citations in the previous paragraph: a line that says "(removed; `git show <commit>:<path>`)" still names a file that is gone, but now says so and says how to read it. The handoff allows "the citation is rewritten", and this is the rewrite. The user's own rulings ("they dont need to be kept in the repo") do not forbid either.

**A guard for the future.** A new docs check fails any permanent markdown file, and any code comment under `src/`, `tools/`, `tests/` or `installer/`, that names a `docs/` path that does not exist in the tree. It skips `docs/handoffs/`, `docs/superpowers/` and `docs/sessions/`, and a path written with its removal commit. It lives beside the scratch-path check in `tests/test_docs_match_code.cpp`. With it in place, a later session can remove a finished plan in the same merge that finishes its work, and the check proves nothing still points at it. CLAUDE.md gets one line saying so.

## The rule for "finished"

A file in `docs/handoffs/` or `docs/superpowers/` leaves when all of these hold, checked at the moment of removal.

1. It is not on the keep list.
2. It is not a release note. Those move to `docs/releases/` instead.
3. No unmerged branch edits it (`git log --all --not main -- <path>` is empty).
4. No tracked file outside the two folders and `docs/sessions/` names its path, its path without `.md`, or its folder. If one does, that citation is handled first (tasks A3, A4 and A5), and then this holds. The cards are skipped because they keep their paths ("Cards keep their plan and handoff paths").
5. No kept file points at it to be read (see the paragraph above `release-next-notes.md` in the keep list). A kept file that names it only as history is edited in the same commit.
6. If it is untracked, it is first committed to the local branch `archive/finished-docs-2026-10`, which is never pushed, and then deleted from the checkout.

Under this rule the scouts counted 558 files in the two folders: 31 kept and 527 finished. Of the 527, 445 are named by no other file and 82 are named by tracked files that must be rewritten first. The 445 includes the 20 release notes the scouts counted as free, which move to `docs/releases/` instead of going, so about 425 leave at once (407 tracked, 18 untracked) and about 82 later (78 tracked, 4 untracked). The scouts did not apply rule 5, so a few of these move to the kept side. The cards skip in rule 4 only adds files to the removable side. The build recounts.

The main checkout has 22 untracked files that are neither kept nor release notes (17 if the Path Builder mockup folder counts once). One of them, the hook-redesign plan, has two commits on a branch. The user's "Archive branch, then delete" answer named 15 files, so the user is asked to confirm that it covers the larger count when approving this plan. The archive branch keeps every one of them either way.
