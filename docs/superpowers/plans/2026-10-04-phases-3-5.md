## How this plan differs from steps 1 and 2

The audit of those sessions (`docs/audit/2026-10-04-step1-2-session-audit.md`) found the plans themselves seeded most review findings. So this plan follows these rules:

- **No code listings.** Each task names its owner functions, files, test cases and the numbers its tests pin. The implementer writes the code.
- **Owners first, callers second.** Wave D1 builds each owner function in its home file, with tests. Wave D2 points the screens at those owners, one task per group of files, so no two tasks edit the same file. This stops parallel tasks inventing two owners for one fact. It also keeps the hot files (report.cpp, path_view.cpp, preview_view.cpp, model.cpp) to one writer per wave.
- **Questions before code.** All 33 display questions are in `docs/audit/2026-10-04-phase-3-5-questions.md` and get answered before wave D starts. The pre-review script flags any new number with no decision behind it, so stragglers reach you in one batch before review, never mid-chain.
- **Shared test fixtures come first.** Task H1 builds the fixtures phase 3 tests need. Every display task uses them; none writes its own.
- **One scan file.** Every new "one owner" rule is a row in `tests/test_single_owner.cpp`, with an example line it must match and one it must not.
- **Each task has its own brief file.** `tasks/<id>.md` beside this plan holds the shared preamble plus that task alone, so an agent reads 150 lines instead of this whole plan.

## Who runs what

- **Planning:** Fable.
- **Implementers:** Opus, one per task, each in its own worktree, all launched together through a Workflow.
- **Reviewers:** Sonnet, both for the light per-task answer check and for the derive-once review before each merge.
- **The main session:** merges, builds once per wave, and runs the full suite once per merge to main.

**Tests.** Agents never run the full suite. Each task's brief names the test files and test cases it may run. A Phase 0 hook refuses an unfiltered suite run from any agent.

**Reporting.** Every agent writes a status line every 10 calls or 5 minutes. When blocked, it stops and reports the exact error; it never waits. Helpers run in the foreground. Agents commit before 110 calls.

**Dependencies.** A later task waits on the earlier task's commit, not on its review. Cold builds start at most three at a time.
