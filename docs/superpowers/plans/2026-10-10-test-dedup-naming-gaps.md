# Plan: one owner per test rule, names that say what they protect, and the last coverage gaps

Planner TP-5 (agent a57c5350f5fd67e72), 2026-10-10. Source: the audit at `docs/audit/2026-10-10-test-suite-audit.md` and the four scout reports. Every claim below was checked in the code unless it says "claim" or "not read". Line numbers are from the checkout as of commit 784e47cc.

## What is wrong, in one paragraph

The C++ suite is healthy, but it breaks the user's own derive-once rule in about a dozen places: the same user-facing sentence is typed out in four or five test files, the same "tags come off a title" walk is pasted into three report tests when `test_song.cpp` already pins the rule, three tests pin the same chartmode keys, four SP-overfill cases build the same song four times, and two test files carry the same `ScratchPaths` struct and the same library-row builder word for word. One reword or one refactor then turns four or five tests red at once, and none of the extra copies would catch a bug the owner's test misses. On top of that, nine files are named after "Step 2" of a plan that finished months ago, eight test cases are named "finding 37", `test_search.cpp` is 2,000 lines of Star Power end-of-window maths under a name that sounds like library search, and eight files run past 1,000 lines. This plan gives each shared piece one home, renames by behaviour one move per commit, keeps the pins that protect a user decision and loosens the ones that only pin source text, and closes the five "no test names it" source files (one tiny new test, the rest already covered or untestable).

## What this plan leaves alone

Other sessions own: hook dispatchers, uncapped waits, the 18 s overlay test, dev-tool cases (the skipped "write samples" case, the dynamics-tag dev aid, the blink benchmark), no-assertion tests, `leak_checked`, "every corpus chord", the `test_rules` one-chart loop, the Opus cancel test, `delete_results_without_chart`. Other planners own: the single-owner redesign, old-DB fixtures, the golden image, stem tests, the recomputed oracles in `test_song`/`test_fill_deadline`, perf digest settings, wall-clock asserts, the audio device test, hook-suite hygiene, CI and tooling. Nothing below touches those.

## Risks

Doctest's `-sf=` filter matches on the path doctest recorded at compile time, so the before and after counts must be taken with the same filter form; the executor writes both numbers into the commit body. The single-owner scan's "only shrinks" baselines will object if a clone row disappears without the matching code change; the executor removes the row in the same commit as the dedupe. Splitting `test_app_state.cpp` and `test_store.cpp` moves anonymous-namespace helpers that several cases share; each split file may need its own copy of a two-line helper, which is a new duplicate, so the mover puts shared helpers in a header instead. The exported database-sentence constants change `user_messages.h`, which the GUI includes, so Task 1.2 rebuilds the app and the GUI runner once. Renames break any open branch that touches the renamed file; wave A runs when no such branch is open.

## Size

About 40 commits across 20 tasks. Wave A is a day of agent time in parallel (eight agents, each under 20 tool calls except 1.2 and 1.5). Wave B is half a day. Wave C is the big one: 22 move commits over eight files, two to three agents a day for two days, plus the reviewer per task.
