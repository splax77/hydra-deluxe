Report windows, mock

The path report (boards 1-3) and the dmleaderboards comparison (boards 4-5) move from the browser into their own Hydra windows. Both are the same window frame filled with different rows. These are drawings for layout, wording and order, like the 2026-09-27 redesign mocks. They aren't the code. The rows are the sample rows from the test that writes sample pages, and the numbers are made up.

1. The report window, opened over Hydra

The report is a real Windows window with its own title bar and taskbar button. You can drag it to a second monitor. It minimizes and restores with Hydra and stays in front of it. Hydra's own window is drawn faintly behind it.

Hovering the Path header: The path in path notation: one entry per activation, with its skip count and squeeze symbols.

Generated from hydra.db. Timing tiers measure how big each squeeze is, in steps of your hit window. The Paths tab's row labels measure how far a hit lands from the Star Power end, so the two can differ. 'Beyond' means past the 170 ms window.

The line under the table is today's page footer, word for word. The column legend under it on the HTML page goes; header hover text carries the same words.

Click a row to select that chart in Hydra; the main window's Paths tab then shows it (row 1, highlighted). Click a header to sort; click again to flip; Shift+click adds a second sort. The arrow marks the sorted column. Hover a header for what the column means, or a cut-off cell to read all of it. The gold bar marks a best path, as on the HTML page. Esc or Ctrl+W closes the window.

3. What changes in Hydra's main window

The labels stay as they are today. The finished-batch strip loses Show in folder, because there is no file. Its second line says the report is ready instead of naming a file. Open report and Open automatically now mean the window. Open automatically no longer touches the dmleaderboards comparison, which always opens its window because you asked for it; its hint becomes “Open the path report as soon as it's built.”

The strip's counts line is drawn by the existing code and is only sketched here.

5. Getting there: the player picker hands over to the window

The “Compare dmleaderboards user” box keeps its first two steps (loading the user list, then picking a player). Picking a player now closes the box and opens the window, which shows the wait and the result. The box's old third step (Done, Open report, Compare another, Close) goes, because the window is the result.
