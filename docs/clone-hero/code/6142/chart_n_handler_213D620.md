# chart_n_handler_213D620 (build 6142, RVA `0x213D620`, class #8615)

Made 2026-10-30 with tools/ch_mcp/chdis.py. It handles one `N` line of a .chart track. The jump tables sit after the code, so the listing stops at the last real instruction (the tables at RVAs `0x213DAE4`, `0x213DB10`, `0x213DB28` and `0x213DB4C` were decoded separately from the DLL bytes and are given below). Inputs: the line's text span (rcx), the track (rdx), the tick (r8), the line state (r9: `isScanning` at +0xC, the instrument byte at +0xD).

Lines 1-17: set up. Lines 18-26: call `0x213DB70` to read the line's two numbers, the lane value (a uint, kept in esi) and the length (a long, r12). Lines 27-59 (the flag-only pass): when `isScanning` is set, and the track already has more than one note, call `0x215FE80` on the track; false returns. True: lane 5 sets the track flag +0xA1, lanes 66 to 68 set +0xA2, then return without adding a note. With one note or none the code falls to line 60 and adds notes as usual.

Lines 60-70: pick a table by the instrument byte minus 4 (RVA `0x213DAE4`, decoded: instruments 4, 5, 10, 11 and 14 use the six-fret keys-style table at line 175; 6 (Drums) and 9 (ProDrums) use the drum table at line 71; 7, 8, 12 and 13 and anything above 14 use the default table at line 192). Lines 71-75: drum lane value above 5 goes to line 95, otherwise a jump table (RVA `0x213DB10`, decoded to lines 76, 79, 82, 85, 89, 92). Lines 76-94: lane 0 is type 13 (KickDrum), flags 0; lane 1 type 14 (RedDrum), 2 type 15, 3 type 16, 4 type 18 (OrangeDrum), 5 type 17 (GreenDrum); lanes 1 to 5 set the flags register to 0x10 (Tom) at line 99. Lines 95-98: lane 32 goes to line 106, any other value gets type 0. Lines 100-105: type 17 sets the track flag +0xA1. Lines 106-109: lane 32 is type 13 with flags 8 (DoubleKick); no check of difficulty or any setting.

Lines 110-118: first-call setup. Lines 119-148: take a note record from the pool (track +0x10) and fill it: tick at +0x10, length at +0x18 (the line's length only when it is larger than the int at +0x114 of the object at track +0x50, otherwise 0; lines 119-126), flags at +0x24, type at +0x20, the note's own index at +0x28 (the list size before the add, lines 153-157). Lines 153-174 and 299-308: add the record to the track's note list (track +0x60), the fast path and the grow path.

Lines 175-209 (not drums): table at RVA `0x213DB28` for the six-fret keys-style tracks (lanes 0 to 4 become types 10, 11, 12, 7, 8, lane 8 type 9, lane 7 type 1) and the guitar table at RVA `0x213DB4C` (lanes 0 to 4 become types 2 to 6, lane 7 type 1). Lines 210-211: a non-zero type goes to line 106's add path. Lines 212-217: type 0 means the lane is a modifier: call `0x213D160`; a zero kind returns. Lines 218-222: kind 7 (Cymbal) sets the track flag +0xA2. Lines 223-278: build a 0x20-byte record (start tick and end tick both the line's tick, the track's difficulty byte, the lane, the kind) and add it to the per-kind list given by `0x182160210` (the grow path is lines 255-262, the fast path 279-298). Lines 309-312: the throw stubs.
