# chart_e_handler_213CAF0 (build 6142, RVA `0x213CAF0`, class #8615)

Made 2026-10-30 with tools/ch_mcp/chdis.py from GameAssembly.dll; the game's method name is obfuscated, so it is named by class and RVA. It handles one `E` line of a .chart track. Inputs: the whole file text as a span (rcx), the track being filled (rdx, class #8661), the tick of the line (r8) and the line state (r9: position at +0x8, `isScanning` byte at +0xC, the stack of open solos at +0xE).

Lines 1-17: set up. Lines 18-44: first call only, loads the metadata slots for the strings `solo`, `mix`, `soloend`, `[mix`. Lines 45-64: read the text position, the span and its length. Lines 65-84: walk forward from the position to the first LF, or to a CR followed by LF, so the "line" ends there. Lines 85-112: store the new position in the line state, cut the line out of the span and call MemoryExtensions.Trim, which removes whitespace from both ends. Lines 113-115: if the `isScanning` byte is set, jump to the exit; nothing is recorded in the flag-only pass.

Lines 116-142: does the trimmed text start with `[mix` (an ordinal, case-sensitive prefix test)? Yes goes to line 319. Lines 143-168: the same test for `mix`; yes goes to line 319. Lines 169-199: is the trimmed text equal to `solo` (function `0x20FE510` with its ignore-case argument 0, an exact test: same length, every UTF-16 unit equal; see decompile lines 58799-58811)? Yes goes to line 251. Lines 200-230: the same test against `soloend`; no goes to the exit (line 307).

Lines 231-250 (`soloend`): pop the newest open-solo index from the stack in the line state (`TryPop`; nothing open means exit), find that Solo record in the track's solo list (track +0x78) and write its length (+0x18) as the line's tick minus the record's start tick (+0x10) plus 1. Lines 251-306 (`solo`): push the current size of the track's solo list onto the stack, take a Solo record from the track's pool (track +0x40), initialise it with the tick, and add it to the solo list; the code at 285-306 is the List.Add fast path and the grow path.

Lines 307-318: restore registers and return. Lines 319-330 (mix text): call the mix parser `0x215C750` with the trimmed text and the tick; false means exit. Lines 331-335: take the parsed difficulty byte and compare it with the track's difficulty byte (+0x59, the check at 0x213D076); different means exit, so another difficulty's marker is dropped. Lines 336-385: take a mix-event record from the track's pool (track +0x28), write tick (+0x10), difficulty byte (+0x18) and the text string (+0x20), and add it to the track's mix-event list (+0x90). Lines 386-390: the null-reference and out-of-range throw stubs.
