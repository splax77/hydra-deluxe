# lane_sprite_spawn_41BE70.asm
A shared generic method of BaseNoteRenderer that puts one sprite per pad for each object in a list. The lane draw (lane_draw_1166890.asm) calls it with the engine's lane list. Line 65 takes the next object from the list. Lines 69 to 74 call slot 3 of interface 8266 on it (0x2C44210 is the call helper; the slot is in ecx and the interface's TypeInfo in rdx), and keep the 16-bit result; on a lane that slot is lane_pad_mask_216A440.asm. Lines 78 to 93 pass that word to 0x20FE7E0 and step through what it returns with 0x20FC610 and 0x20FC5F0, one pad word at a time; this pass reads that as walking the word's set bits from how the result is used, without listing those helpers. For each pad, lines 97 to 101 call the renderer's virtual at vtable +0x1E8, which DrumsNoteRenderer fills with its slot-11 method (dump.cs line 33356, a column from a pad word). Lines 106 to 112 switch on a pooled sprite object, lines 131 to 142 size it from the object's interface slot 5 (a float), lines 143 to 148 get a colour from the virtual at +0x208 for that pad, line 150 sets its alpha to 0.75, and line 159 applies it. So the game draws one strip for each pad the lane's pad word yields, and reads no other pads. Page 2's NL-57 cites this listing.
