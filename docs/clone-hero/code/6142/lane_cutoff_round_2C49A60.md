# lane_cutoff_round_2C49A60.asm
The method the lane builder calls on its cut-off value just after loading System.Math's TypeInfo (docs/audit/drum-lanes/f20d12c0.asm lines 91 to 99). Neither dump.cs nor script.json names a method at this RVA, so its name is unread; this note describes what the code does. Lines 4 and 7 split on the sign. For a value of zero or more, line 8 calls a helper that leaves the whole part at [rsp+0x40] and returns the fraction in xmm0 (the listing does not include the helper). When the fraction is exactly 0.5 (lines 9 to 12), the whole part is kept if it is even and raised by 1 if it is odd (lines 13 to 17); any other fraction adds 0.5 and jumps to a second helper (lines 21 to 25). Negative values take the mirror path (lines 26 to 40), subtracting where the other path adds. This is round-half-to-even, the behaviour of .NET's `Math.Round(double)`. Page 2's NL-58 cites this listing.
