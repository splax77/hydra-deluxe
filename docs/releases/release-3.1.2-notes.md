Hydra Deluxe 3.1.2 makes the early fill window a setting, `Early fill window`, set to 60 ms by default. It also trims the squeeze boxes in the Paths tab to one sentence each, and a library analysis no longer slows down with every song it saves. Your saved results read `Stale` once: every result saved by 3.1.1 or earlier is marked `Stale` until you open the song or run `Analyze library...`. No scan starts, and your library and settings carry over.

**Update from the app.** If you run 2.12.0 or later, the bar at the top of the window offers this release the next time Hydra Deluxe starts; click `Update`. If you run 2.11.0 or 2.11.1 with its update check on, a line under the toolbar offers it once its daily check runs. From 2.10.2 or earlier, download the `-setup.exe` file below and run it.

**The early fill window is one setting.** `Analysis settings` has a new `Early fill window` box under `Clone Hero rules`, in ms. It sets how far from a fill's deadline your Star Power may come ready and still count as an early fill, and the same number applies on both sides of the deadline. If Star Power comes ready up to that many ms after the deadline, you can still summon the fill by hitting early. If it comes ready less than that many ms before the deadline, the activation is marked `E`. It starts at 60 ms and goes from 0 to 85 ms, the hit window. At 0, no activation is an early fill. In `hydra_settings.ini` it is the `early_fill_window_ms` line.

**Early fills reach 60 ms by default, down from 85 ms.** In 3.1.1 an early hit could summon a fill up to 85 ms after its deadline, while the `E` mark used 60 ms. Both sides now follow the one setting. So at the default, when Star Power comes ready more than 60 ms after a fill's deadline, that fill never spawns, and a path that used it is no longer found. To reach as far as 3.1.1 did, set `Early fill window` to 85; an activation then also reads `E` when it has less than 85 ms to spare. Results are saved separately for each window, so changing it keeps the results you saved under the old one. The `Analyze library` confirm window lists `Early fill window` with the other settings it uses, and `Reset to defaults` puts it back to 60 ms.

**Each squeeze box says one sentence.** A squeeze-out box now reads only "Hit ... so it lands after Star Power ends." The second sentence, about the points it costs and the SP phrase banking for later, is gone. A squeeze-in box reads only "Hit the SP phrase's last note ... so it lands before Star Power ends." What a squeeze-out costs still shows on its row in `Backend timings`, as `<-- squeezed out (-N)`.

**The SqIn's timing scale gets its own line.** When an activation's squeeze-in reads a different frontend timing scale from its SP end, the scale line splits in two. The squeeze-in's line comes first, such as "Frontend timing scales ... at the SqIn's SP end.", and the SP end's line follows it, "Frontend timing scales ... at the SP end." Before, both were one sentence.

**A library analysis no longer slows down on each save.** After every song it saved, Hydra Deluxe cleared out empty settings profiles by searching your stored results, which got slow on a large library. It now does that once, when it opens your library. While a batch runs, the library window also no longer waits for the batch's saves: the rows fill in from the batch's own answers once a second, so the window doesn't pause while songs are saved. Clicking a song and building a report during a batch also no longer make the window wait for the batch's saves.
