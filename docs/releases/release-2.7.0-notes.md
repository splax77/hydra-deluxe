Hydra Deluxe 2.7.0 gives the Preview's four text boxes one look and ends its scrubber where playback ends. The dmleaderboards comparison, the song panel and the command-line tools now use the same words as the rest of the app.

**Your saved results carry over.** Nothing in this release changes how a chart is analyzed or scored, so every saved result stays as it was, and nothing reads `Stale`. The first scan after you update does read every chart file once, so it takes longer than usual. That scan is what trims the names in .sng and .srb files (see below). Until you run it, the library shows the names the last scan saved, and opening a song reads its stated length and delay straight from the chart's own files. Those are the same values the scan would save, so nothing on screen changes.

**The Preview's text boxes share one look.** The time box, the score box, the drain box and the next activation box now all left-align their text, with the same space between the text and every edge of the box. The drain box used to right-align its text, and each box had its own margins. Where each box sits, its colours and its text size stay the same.

**The scrubber ends where playback ends.** When a song's stated length runs past its last note and its audio, the scrubber under the highway used to reach past the point where playback stops. It now ends where playback ends. The gold activation marks still sit by the song's length, so they line up with the Paths timeline as before. While a song loads, `< Act` and `Act >` are greyed out; they used to look live and do nothing.

**Clearer words in the dmleaderboards comparison.** A chart in your library with no result for this mode at SP cap 4 now reads `no current result` in the table, in place of "not analyzed". Its tile reads `No current result` and its dropdown entry `No current result (in your library)`. A Stale chart still counts there. The tile that read "Not in library" now reads `Not in your library`, like the dropdown and the row hover; the table cell still reads `not in library`. When a comparison fails, the window says `The comparison could not be built.`

**The comparison stays on Expert.** `Compare with dmleaderboards...` was already greyed out below Expert, but if you changed the difficulty with the comparison window open, `Refresh`, `Try again` and `Compare another player...` built a comparison anyway, against that difficulty's optimals. They now stop with the toolbar's reason, `Needs Expert: the leaderboard only has Expert scores.`

**Smaller changes.** When `hydra_rules.ini` has an error, the song panel shows the toolbar's sentence, `hydra_rules.ini has an error, so analysis is off until the file is fixed and Hydra is restarted.` After a rescan, the open song panel picks up its chart's new name, artist and charter, so it matches its library row. While a batch runs, the greyed buttons' tooltip reads `A batch is running.`, the same sentence as the status line, in place of "Busy: a batch is running." The library sorts names by the text each cell shows, so a song whose title shows `(unknown)` sorts with that text, and a name that starts with a space no longer moves its row. In `hydra_rules.ini`, a decimal key set to `nan`, `inf` or a hex number such as `0x10` is now an error, where it used to load. A whole-number key accepts any whole number however it is written, so `4.0` loads as 4 and `1e1` as 10; a fraction such as `2.5` is still an error. The scan trims spaces from the ends of the title, artist and charter in .sng and .srb files, as it already did for song.ini, so a charter made only of spaces reads `<unknown charter>` after the first scan.

**Command-line tools.** `hydra_batch`'s header uses the app's names for its settings: `Score range` (written like `4 scores`), `Path limit` (`off` when it is off) and `Fills`, where it used to print "Depth", "Timing cap" and "Fill rule". Its summary line, printed before any list of failures, counts the run in the app's words and order: analyzed, failed, then skipped `(already had a result)`, and then the time taken. When `hydra_rules.ini` has an error, `hydra_batch` and `hydra_fillcompare` print `hydra_rules.ini has an error:` and then the line that failed, where they used to print only that line. `hydra_fillcompare`'s summary line says `in both, not both scored` for charts in both databases without a score on both sides, in place of "with a score on one side only", and the page's tile for them reads `In both, not both scored` in place of "Score on one side only". The page's count line reads `1 of 1 chart` for a single chart, and its text columns sort the same way the app's report windows do.
