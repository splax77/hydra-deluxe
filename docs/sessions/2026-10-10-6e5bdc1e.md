# Doc-review submit gate: accept CRLF review files (2026-10-10)

## Goal
Fix the bug where the doc-review submit gate ignored the Base line in a review file that had Windows (CRLF) line endings, so a valid review was refused. The fix was handed over from another session's background task. The user then sent one word, merge, to land it.

## Topics
doc-review submit gate, CRLF line endings, Base line regex, hook test file, one fresh reviewer, worktree merge, fast-forward of main

## Roadblocks
- The gate refused a valid CRLF review with a misleading no-sources-file message -> the Base regex ended in a dollar sign, which in multiline mode matches only before LF, so the trailing CR blocked it and the gate saw no Base line -> fixed: the gate converts CRLF to LF once, right after it reads the file, and the file hash is still taken from the raw bytes.
- The first fix still missed a Base line ending in two CRs -> one CR survived the conversion, so the line was quietly skipped and the review was recorded with no Base -> fixed: any line starting with Base now counts, a malformed one is refused, and the reviewer added a test that failed before the fix.
