# Port Hydra path search to C++ (2026-08-11)
session: 439d9689-261d-4f85-a3e5-cabf118830eb | project: hydra-test | commits: none | D: none | tags: path, performance, tests, agents, review | agents: 5

## Goal
Port the path search (GraphPather.read and the GraphPath state machine in hydra/hypath.py) to a native C++ engine, behind the same opt-in gate the existing native core uses. The paths had to stay identical to the Python version, and the engine was to stay off unless it was both correct and faster.

## Topics
path search port, flat graph arrays (hyflat), C ABI and ctypes binding, MSVC build fix, golden diff of paths, parity tests, time-budget cancel, benchmark, review agents

## Roadblocks
- The native build could not find MSVC -> vcvars64.bat looked for vswhere.exe on the PATH, but VS 2026 keeps its tools under Program Files while its Installer stays in Program Files (x86) -> fixed: build_native.py adds the Installer folder to the PATH it passes to cmd, and the build now uses MSVC.
- The uncapped regression test failed with the engine on, though the golden diff showed zero differences -> the time-budget abort was raised from the progress callback, and ctypes swallows exceptions that cross back into C, so an overrunning rung was never stopped -> fixed: cancellation is now an explicit flag in the C ABI, with a parity test that checks cancel stops the engine.
- The long auto-reduction test held the DLL, so the rebuild with cancel support failed to link and the tests ran against the old library -> the test was still running in the background -> worked around: waited for it to finish instead of killing it, then rebuilt and reran.
- The auto-reduction test came back with 229 failures, not the baseline 46 -> the run shared the CPU with other heavy runs -> worked around: reran it alone with nothing else running.

## Outcome
The session was cut off at 03:29 UTC before its final report, with the review fixes still in progress and nothing committed.
The native search engine was built and runs. It was 1.59 times faster end to end, against a ceiling of about 1.62, and the search stage fell from 45.8 percent to 8.6 percent of the time.
The golden diff on 98 charts showed zero differences, in both the capped and the uncapped edition. An independent re-run confirmed it, with a negative control showing the DLL does the work.
The flat-array extension (hyflat) passed the round trip on all 98 charts at about 0.43 ms per chart. The new test is test/test_search_parity.py, and the engine stays behind the HYDRA_NATIVE gate.
test_regression stayed at its baseline of 29 failures, and the other modules passed, with the engine on as well as off.
Both exes were rebuilt, and the database check showed 18,022 records intact.
The two native memory notes were rewritten, because they were out of date.
