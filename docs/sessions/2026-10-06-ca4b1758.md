## Goal
Find out whether other users hit trouble with Claude Code's Bash tool on Windows and how they fix it. Then audit this project's recent shell calls, build hook gates to stop the avoidable mistakes, and launch four follow-ups.

## Topics
Git Bash versus PowerShell on Windows, shell-read gate, Windows-path gate, recursive rm rule, replay of past shell calls, suite gate test-run limit, merged refusals in the dispatchers, scratch-path rule, brief preamble

## Roadblocks
- Claude read files with sed, cat and head, and the old sed block told it to use Edit or a node script -> the sed rule was a plain text match that fired on reads and gave advice meant for edits -> fixed: a new shell-read gate names the exact Read call to make instead.
- The first path gate would have blocked 39 ordinary commands, such as awk programs and grep patterns that only looked like Windows paths -> the check matched path-looking text without knowing how each word was quoted -> fixed: the gate now asks the shared scanner about quoting, and those 39 commands are in its test.
- Agents stopped as blocked after two runs of their own test file -> the suite gate counted runs, not distinct files, so a fail-then-pass cycle used up the limit -> fixed: the limit now counts different test files.
- The dispatchers showed only the first refusal, so a second problem came one retry later -> each dispatcher had its own copy of the merge logic, which stopped at the first block -> fixed: one shared helper keeps every reason.
- The audit undercounted failed Windows-path commands -> Claude Code often does not set the error flag on a failed Bash command -> worked around: the new path gate blocks the bad paths before they run.
- A deletion guard refused an edit that removed a duplicate rule from the risky gate -> the guard reads the first message of a workflow agent, which is a relay of the user's request, so it thinks the agent owns no files -> worked around: the main session made the edit itself.
