# Hydra score count issue (2026-08-23)
session: 29cb992b-9c4f-4922-8a10-9e8d370a1412 | project: hydra-test | commits: none | D: none | tags: sp-cap, record, analyze, tests, docs | agents: 0

## Goal
The user sent a screen recording and asked why Hydra did not give 4 scores when the score-number option was set to 4. The session ran the diagnosing-bugs skill.

## Topics
score count versus paths kept, Auto SP cap row choice, record store lookup, ADR-0003, regression test

## Roadblocks
- Only one score showed even though the setting was 4 -> the video's "Paths kept: 4" counts tied paths of one score, and the real cause was that Auto picked the stored row with the highest SP cap, so an old imported uncapped row always beat a fresh run -> fixed: Auto now picks the newest row above cap 4 (two-line ordering change in record_store.cpp, test written first and seen failing)
- ADR-0003 called the leftover high-cap row harmless -> that claim was never tested and the old row came from different depth and ms settings -> fixed: ADR wording updated and a test now pins the real sequence

## Rulings
- none

## Outcome
Claude found the cause in the record store and fixed it in the working tree, but nothing was committed.
The fix, a regression test and an ADR-0003 edit passed the full suite (170 cases). A throwaway test harness was built and deleted. On a copy of the installed DB, the old rule gave cap 1728 with 4 paths and the new rule gave cap 64 with 12 paths and 5 scores. Claude also wrote a memory file about the rule.
