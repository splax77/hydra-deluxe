## Goal
The user wanted Claude to test the real Hydra GUI by reading text, not by taking and judging screenshots. The session chose a design through a question round, then built it: a headless runner called hydra_uitest, which drives the ImGui interface by widget label and prints text.

## Topics
GUI test automation, Dear ImGui Test Engine (vendored), headless and attached modes, the hydra_uitest runner, command-file scripts, main.cpp split into app_shell, fetch seam for DM network calls, DmReportJob browser fix, ui-testing docs

## Roadblocks
- The first plan read like a spec sheet, and the user refused the tool call that wrote it -> the plan ignored the user's rule for plain writing -> fixed: the plan was rewritten as one plain line per step, then approved.
- The first scan test segfaulted with no output -> cause not found (the session checked the coroutine wiring and ran cdb on a build with symbols) -> fixed: guard helpers were added, the build was rerun, and the scan test passed.
- The plan assumed the Preview had a Stop button -> the Preview has only Play and Pause -> fixed: the plan was adjusted to Play and Pause.
- A CMake deprecation warning on stderr made the PowerShell build fail -> PowerShell 5.1 treats stderr output as an error -> worked around: the build was rerun from Bash with output sent to a log.

## Outcome
Ended at 22:13 UTC with the feature built and checked. hydra_uitest --all passes four flows (scan, analyze, preview, settings-and-reports) in about 1.3 seconds. Attached mode runs the same test inside the real Hydra window and writes a log. The existing doctest suite passed 147 cases.
Two choices differed from the plan. Scratch paths are set by one process-wide override, not passed through each function. Attached mode uses scratch files, not the real hydra.db, because the tests wipe their database at start. One app bug was fixed on the way: DmReportJob always opened a browser, and now honours the Open automatically setting.
Nothing was committed. The Preview work was already uncommitted in the tree.
