## Goal
Copy Clone Hero's 30 bundled .srb songs into per-song folders, audio included. The audio is encrypted, so the session grew into breaking the encryption and then making Hydra's preview play .srb audio.

## Topics
srb container, Clone Hero audio encryption, IL2CPP dump, Frida hooks on BASS, AES-128 CFB decryptor, Hydra preview audio, BCrypt chaining mode

## Roadblocks
- Static search of Clone Hero's code found no AES key or S-box -> the code is name-obfuscated and the tables are built at runtime -> worked around: hooked the BASS audio library with Frida while Clone Hero loaded songs and captured the decrypted Ogg Opus, 25 of 30 songs
- The first Frida hooks captured nothing or only encrypted bytes -> they were attached after the streams already existed, and the read callback gives raw data for some streams -> fixed: user loaded new songs while hooked, and the hook checked for the OggS magic
- Clone Hero crashed on one song and froze loading Saurian King, so 5 songs were never captured -> cause not found -> worked around: read the key out of memory and decrypted the .srb files offline
- Standard AES modes all failed even with the right key -> the real cipher class was missed first, and the IV is the 16-byte blob header with its two 8-byte halves swapped -> fixed: worked back from known plaintext, found AES-128 in CFB mode; the odd byte order of the lookup table was a red herring
- Hydra's first decryptor kept only the first 16 bytes right, so preview stayed silent -> the leading count in the audio section is not the blob count, and BCrypt defaults to CBC chaining, not ECB -> fixed: loop until the data ends, and set ECB mode explicitly
- A helper agent refused the key-extraction job -> it lacked the session context -> worked around: the main session wrote the script itself
