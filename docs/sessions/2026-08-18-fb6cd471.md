## Goal
The user asked for an audit of the whole codebase: what to refactor, remove or improve, including why the golden/ folder exists. The user approved a plan, and the session carried it out in phases, one commit per phase, with the tests green after each phase.

## Topics
dead engine code, the golden/ parity corpus, stale worktree and build artifacts, fresh-clone build, shared UTF-8 module, shared HTML page module, JobBase thread refactor, shared UI widgets, version string, dmbot parser split, new tests, docs

## Roadblocks
- The first plan kept a throwaway baseline commit and two golden copies for safety, and it still framed the work around Python recovery -> Claude kept safety copies that the user's goal did not want -> fixed: the user corrected it at 22:19 and 22:22 UTC, and the plan was rewritten with no throwaway commit and no archive before approval.
- A stale worktree looked like junk, but it held one real unmerged fix (font and icon loading relative to the exe) -> nobody had merged that fix -> fixed: the fix was ported into the main tree, and then the worktree was removed.
- The GUI build could not link because a running Hydra.exe locked the file -> the running app held its own exe open -> worked around: closed the running Hydra window gracefully (the app saves its settings on exit), then rebuilt.
- Two new test assertions failed -> measures_decimal drops at a mid-measure meter change, so the monotonic assumption was wrong, and collect_rows emits one row per path, not per record -> fixed: dropped the wrong check and counted the rank-1 rows instead.
- The fresh-clone build failed under Windows path limits -> the scratchpad path was too deep, and MAX_PATH breaks both the checkout and the compiler -> worked around: reran the clone in a short temp folder, then deleted it.
- One test failed in the fresh clone because chart bytes differed -> the old .gitattributes text=auto rule rewrote .chart files to LF endings, so each clone got different bytes -> fixed: binary rules in .gitattributes plus a renormalize commit that corrected 32 chart files.

## Outcome
The session ended with the audit plan carried out in full, in nine commits, and a fresh clone that builds and passes all 51 test cases (5,700 assertions).
The golden/ folder (124 MB, a gitignored parity corpus from the Python port) was deleted entirely, with no archive. The tests now read the checked-in testdata/input corpus and check structure and round-trips.
About 3,000 lines of dead engine code were deleted: the native/ ctypes copy, the activation-DP path, the disabled bound prune, and an unused difficulty parameter. hydra_batch over 97 charts gave identical scores and paths before and after. The green baseline commit is 21ddf53.
About 1 GB of disk was reclaimed by removing dist/, build/ and the stale worktree. The repo went from about 1.7 GB to about 600 MB.
Duplicated code moved into shared modules: one UTF-8 module, one HTML page module, one JobBase for the six thread jobs, shared UI widgets, and one version definition. Test cases went from 46 to 51.
Two problems were found on the way: the repo did not build from a fresh clone, because nine referenced files were never committed, and the chart corpus had been stored with altered line endings.
