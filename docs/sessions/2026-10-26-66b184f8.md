## Goal
The user asked why Analyze All gives no album names on an old database, and whether analysis could fill them in without a scan. After the answer, the user approved a change so that an older library rescans itself when Hydra opens it.

## Topics
album data in old databases, Analyze All versus scan, scan version stamp, rescan on open, unreadable song folder guard, scan window notice and wrapping, real-app check on a snapshot copy of the library, push of main

## Roadblocks
- Analyze All left albums blank on an old database -> analysis reads song.ini but keeps only the timing, and only the scan writes the charts table; charts with current results were skipped entirely -> fixed: rescan on open, which starts the usual scan when an older library opens.
- Having analysis save the album it reads -> it would fill only the charts it re-analyzes, and it breaks the rule that only the scan writes the charts table -> dead end: considered and not built.
- The scan window notice line was clipped at the right edge -> it was drawn as plain text that never wraps inside a fixed-width box, and the tests read the text, not the drawn pixels -> fixed: drawn as wrapping text in render_scan_modal.
- The scan window Continue button looked cut off in one screenshot -> the window resizes one frame late, and the screenshot caught the frame before it grew -> worked around: a second screenshot after the scan finished showed the whole button.
- A database-check executor was launched with an extra isolation option by mistake -> it got a second worktree, and the folder hook blocked it -> worked around: the stray worktree was removed and a new executor ran in the rso-t1 worktree.
- A GUI cancel test was flaky -> it failed 1 run in 3, because the scan sometimes finished before the Cancel click landed -> fixed: the test accepts either end of the scan, and the unit cancel test now cancels before the scan starts.
- The older-version line stayed armed when an automatic scan was refused -> a later scan the user started would have shown it wrongly -> fixed: the line is cleared when the scan is refused.
- The real-app check script crashed a few seconds into the scan -> two of its arguments had the same name -> fixed: script corrected and the check run again.
