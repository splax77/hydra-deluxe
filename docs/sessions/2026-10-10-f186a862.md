## Goal
The user wanted the CI coverage job fixed. Its collector step hung, so the job never finished. The session fixed the hang, found and fixed a second failure, and merged the fix to main.

## Topics
CI coverage job, Microsoft code coverage console, wrapping test steps in collect, mimalloc runtime injection, coverage settings file, derive-once review, branch merge and push, job time caps

## Roadblocks
- The coverage job hung at its collector step -> Start-Process -Wait also waited for the coverage server it had started, so the step never ended -> fixed: each test step now runs its command inside the tool's collect command, which ends when that command ends and passes on its exit code.
- Three mimalloc tests failed only under the collector -> the collector injects itself into each process first, so the C runtime loaded before mimalloc could take over malloc -> fixed: in tools\coverage.settings.xml, EnableDynamicNativeInstrumentation is now False and EnableStaticNativeInstrumentation is True, since the exes are already instrumented on disk.
- The same collector launch was repeated with no change, and the grandchild case (how ctest starts the test exe) was not checked with injection off -> the agent kept rerunning instead of changing the setup -> fixed: the user stopped it; the agent named the unproven check and ran it locally.
- The first collector call failed on argument order -> the tool's options must come before the wrapped command, or be cut off with -- -> fixed: added the -- separator.
- The revert commit was blocked by a hook -> git's default revert message had no trailers -> fixed: committed the revert with the trailers.
- Main moved between the user's question and the push -> another session merged two commits to local main, and the push carried them along -> worked around: left them in place, since undoing would need a force-push of main; the agent had not rechecked main before pushing.
