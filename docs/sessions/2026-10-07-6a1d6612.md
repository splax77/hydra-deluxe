# Stop stale link state breaking Hydra builds (2026-10-07)
session: 6a1d6612-5280-4ad4-9e3c-9661cc270acb | project: hydra-test | commits: 0fbc280, 522be91 | D: D99 | tags: performance, installer, tests, docs, agents | agents: 1

## Goal
Builds of Hydra kept breaking from stale link cache files, and the user wanted it fixed without more repro runs. The session traced the cause to link-time code generation (LTCG, where the linker optimizes the whole program at once) and its incremental mode, fixed it on a branch, and timed the build modes so the user could choose the dev-build setting.

## Topics
LTCG and incremental linking, .iobj and .ipdb cache files, CMake and MSBuild defaults, repro scripts, build timing, dev and ship presets, a Preview test flake, agent briefs

## Roadblocks
- The header-change repro did not reproduce the failure: three full rounds passed, and part of a fourth -> the trigger was not a shared-header change and a normal rebuild -> dead end: the session's main suspect, a build cut off mid-link, was never tested because the user stopped the run.
- A wait command and two log watchers ran for 11 minutes and replayed old log lines -> the session waited for a word in a log file instead of using the completion notice -> worked around: the user stopped everything.

- The docs check failed on a backticked name, HYDRA_LTCG, that exists only in CMakeLists.txt -> the docs test requires every backticked code name to exist under src, tools or tests -> fixed: the name is written in plain text.
- One full-suite run failed a Preview test (a load cancelled while opening a 300 MB stem) -> cause not found; it looks like a race under machine load -> worked around: the test passed 10 of 10 runs on its own and in a later full run, and it is flagged for a separate look.

## Outcome
The session ended with the fix committed on branch claude/ltcg-repro (commits 522be91 and 0fbc280), not yet merged to main.
Cause: LTCG was turned on in an earlier session's commit, late on 2026-10-06. With the Visual Studio generator, MSBuild then picked incremental mode, which keeps a cache of .iobj and .ipdb files and trusts it on the next link. The session did not find what makes the cache go stale in normal use. A garbage .ipdb made a link fail with C1301.
Fix: a new HYDRA_LTCG switch in CMakeLists.txt is off by default and on in the ship preset. The installer gets plain /LTCG, which never reads the cache. build_cpp.ps1 always configures the ship preset. docs/development.md explains it.
Timing with tools\bench_run.ps1 after a one-file edit in src\core, with no other compiler running: incremental took 17.7 s to rebuild hydra_tests and 18.8 s for every exe; plain /LTCG took 56.7 s and 90.5 s; off took 2.9 s and 4.6 s. The dev build is now off.
Tests: the full suite on the dev build passed 1143 of 1144. The one failure was the docs check, which passes after the fix; the full suite was not rerun after that fix.
