## Roadblocks
- Launching a song from the command line with no player stops on a No players were loaded error and never reaches the menu -> the game will not load a chart without a player -> dead end: no bot-free launch route; the planned no-player launch was dropped.
- Key presses reach the game only from the front window, and a probe capture showed another app in front -> SendInput goes to whichever window has focus, and Unity reads keys only while focused -> worked around: the first key-press step was paused before any press, and the route was rebuilt to press from inside the game.
- The probe's capture step un-minimized the game, and Windows gave it focus anyway -> the no-activate request did not stop the focus change -> fixed: the game was minimized again within a second.
- Setting pause_on_focus_lost to 1 in settings.ini would likely pause the game when its window is in the back -> the game pauses itself when unfocused -> worked around: each run sets it to 0 in the game's copy only, and the user's file is restored after.
- A plan assumption was wrong: the SongSelect state is live at the main menu too, so a live SongSelect does not mean the song list is open -> the check was guessed, not read -> worked around: that step needs a different read.
- Old six-column press logs were refused by the score check once the log grew to ten columns -> the column count changed -> fixed: K9 reads both layouts, as the user chose.
- Main's docs-vs-code check failed on a kHitWindowMs marker in CONTEXT.md, which came in with another session's hit-window change -> the check did not know the marker -> worked around: left for that session; the K1 and K2 merges went on.
