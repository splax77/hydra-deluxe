## Goal
The user asked why the path report window runs off the screen and why the Hardest ms column is wide while the Timing column is cramped. The user then asked for a handoff so the next session can plan the fix. No code was changed.

## Topics
path report window placement, saved window size in hydra_ui.ini, ImGui column stretch weights, number cells versus the Timing chip, one width rule for every column, handoff writing

## Roadblocks
- The report window opened bigger than the screen -> the first open copied the maximized main window's inside size, and Windows added a frame of about 8 px, so the report came out 16 px wider and 8 px taller than the monitor -> worked around: diagnosed from app_shell.cpp and the saved Size=2560,1417 entry; the fix was not built and is written into the handoff.
- The Hardest ms column was too wide and the Timing column too narrow -> number cells always report their full width, while the Timing chip shrinks and cuts its text, so each column reports a different width to ImGui -> worked around: diagnosed from the code and the saved weights (1.46 and 0.62); the fix was not built and is written into the handoff.
- Column widths were set by different rules in different places -> ImGui sets each column's share from how its cells drew on the first frame, and no Hydra code picks widths -> worked around: the proposed fix (one width rule decided in one place, plus a new table ID) is written into the handoff.
