## Roadblocks
- An agent ran build_cpp.ps1 from another worktree, and it rebuilt the main checkout's build-cpp -> the cmake preset calls read CMakePresets.json from the caller's folder, not the script's folder -> fixed: the cmake calls now run inside Push-Location on the script's folder, and Pop-Location restores the caller's folder even when the build fails.
- Passing the source folder straight to cmake -> cmake --build --preset has no option for a source folder, so the build step would still look in the wrong place -> dead end: dropped in favour of changing folders for the cmake calls.
- The first review found the new helper handled relative paths and $env{...} placeholders differently from cmake -> the helper was written by hand and not checked against cmake -> fixed: both cases now match cmake. No current preset uses either.
- The first review found the Release part of the build path typed in three places -> the names were copied by hand from CMakePresets.json -> fixed: the build script and the installer script now read it from CMakePresets.json.
