# Hydra backend calculation beyond squeeze (2026-08-29)
session: 99e42ceb-4436-4dda-89b1-1aec573c1a3f | project: hydra-test | commits: 8668c04, ab94692 | D: none | tags: squeeze, sqin-sqout, record, release, tests | agents: 1

## Goal
The user wanted Hydra to stop showing backend rows that come after a squeeze-out. The user asked for the fix in the engine that builds the records, not in the display. The session then shipped the fix as version 1.7.4.

## Topics
squeeze-out backend rows, record building in the engine (rebuild), display guard in display_backends(), regression tests, real-app check of the details view, v1.7.4 release

## Roadblocks
- Backend rows past a squeeze-out were stored and shown -> rebuild copied the deactivation edge's whole backend list into each activation, including activations that squeezed a note out -> fixed: rebuild drops the rows past the squeezed-out note's tick (src/search/engine.cpp), and display_backends() got the same rule for records stored before the fix.
- An old test fixture in tests/test_path_view.cpp had rows after the squeeze-out note, which the new rule calls impossible -> the fixture was hand-built before the rule existed -> worked around: reshuffled the rows into a legal order; what the test checks did not change.
- The squeeze-out paths did not show in the GUI check -> the 10 ms path limit filtered them out -> worked around: reran the analysis with the path limit unchecked, then selected the 1- 2 0 path.
