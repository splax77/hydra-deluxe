## Goal
Driven by another session with no user messages. The task was to find out why the panel-split UI test failed now and then, fix it, and commit the fix to main.

## Topics
panel-split UI test flake, open_details helper, song headline and tab bar layout, analysis timing, headless UI test runner, CPU load for timing, derive-once review, commit to main

## Roadblocks
- The panel-split test failed 7 times in 200 runs under load, with an Unable to Hover error on the Paths tab -> the song headline appeared when the analysis finished and pushed the tab bar down 62 px, but open_details clicked after a fixed 3-frame wait -> fixed: a new helper, wait_tabs_placed in tests/ui/uitest_harness.cpp, waits for the analysis to settle or for a closed view gate before the click. wait_song_analyzed now waits before it clicks.
- The UI test runner build failed because mimalloc-redirect.dll was locked -> the session guessed another session's run held it at that moment -> worked around: nothing held the file on retry, so the build was run again and passed.
- The full suite took 87 s against the documented 14 s, under CPU load -> another session was linking a build, so the timing could not be trusted -> worked around: an old copy of the harness was built beside the new one, and the two were timed back to back, alternating.
- The review precheck wants commits, but the staged change was a tree -> the precheck was written for commits, not trees -> worked around: the tree was wrapped in a throwaway commit object, and no branch moved.

## Rulings
- none

## Outcome
The session ended with the panel-split flake fixed and committed to main as 0a74091, not pushed. A fresh Sonnet reviewer checked it for derive-once and found nothing.
Results: panel-split failed 7 of 200 runs before the fix. After the fix it failed 0 of 200 (only the first part of that loop ran under load), and 0 of 50 with load for the whole loop. The full suite with --all --jobs 4 passed 70 of 70.
Cost: panel-split now takes about 0.7 to 1.2 s on an idle machine, against 0.43 s before, because it waits for its three analyses. The whole-suite effect was not measured, since another session was building at the same time.
The session also added one rule-of-thumb line to docs/agents/ui-testing.md.
