## Goal
The user wanted an image model to make the art assets for the Phase 5 Preview renderer. Claude found that the renderer needs textured 3D meshes, not flat images. The session installed Hunyuan3D on the local GPU, tried it, and ended with five mesh files in assets/preview/.

## Topics
image and 3D model research, Hunyuan3D 2.1 and 2.0 install, CUDA and compiler setup, model weight downloads, the local API server, gem and cymbal from reference screenshots, parametric modeling, UVs for the flat pieces, texture handoff

## Roadblocks
- The texture extension would not compile -> CUDA 12.9 rejects the VS 2026 compiler, and the override let it reach a crash in cudafe++, the CUDA front end -> fixed: installed the VS 2022 C++ Build Tools (MSVC 14.44) and rebuilt the extension with them.
- The 2.1 API server would not start -> a log file was opened before its folder existed, a compiled module sat in the wrong folder, and a cleanup step tried to delete a log that Windows had locked -> fixed: made the folder, put the module beside its import, and gave the server its own cache folder.
- The shape model failed to load ("invalid header or archive is corrupted") -> an earlier download was cut off by a network retry, and the Windows copy of the cache was bad too, as was a second copy at a direct path -> fixed: re-downloaded over plain HTTPS, checked each file against its expected hash, and hardlinked the good copy over the bad ones.
- Hunyuan3D 2.1 "standard" ran at about 112 seconds per step, or about 90 minutes per model -> the GPU was full (96 percent of memory), both the shape and paint models were loaded, and the fast attention libraries were off -> worked around: the user chose 2.0 mini+turbo, and shape generation fell to about 2 to 3 seconds.
- The texture bake ran for more than 12 minutes on one CPU core with no progress -> the texture stage does its bake on the CPU while the GPU sits idle -> dead end: the AI texture bake was stopped, and textures were deferred.
- Single-view image-to-3D gave a long blade for the gem and a paper-thin sheet for the cymbal -> the model guessed depth from one angled view of flat art -> dead end: image-to-3D was dropped for the gem and cymbal, and both were modeled parametrically.
- The first flat pieces had no normals, so the renderer would draw them unlit -> the export path left normals out for them -> fixed: regenerated the flats with explicit normals.
- The pasted reference images were not on disk, so the API could not read them -> a chat paste does not save a file -> worked around: the user saved the screenshots into C:\AI\HY3D2\refs.
