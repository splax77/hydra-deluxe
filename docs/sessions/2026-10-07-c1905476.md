## Goal
No user wrote in this session; another session drove it. The goal was Track R: make hydra_replay score with the engine's own rules instead of a copy of them, and make hydra_replay target finish on long charts.

## Topics
hydra_replay score and target, chord-score table in src/core/scoring, whole-path pins, failing-window search, selfcheck, byte-for-byte snapshot checks, derive-once reviews, worktree guard, MSVC linker crashes

## Roadblocks
- Target on blink-182's Discography never finished (still running at 60 s) -> the search kept every squeeze variant, and the failing-window search re-ran once per prefix -> fixed: target --path takes one stored path, and the failing window is found by binary search over one graph.
- Executor R1 was blocked from writing into its worktree -> the app stops a session from writing into worktrees it did not start in -> fixed: each executor was relaunched in a pinned worktree of its own, and the unused track-r1 folder was removed.
- The first snapshot compare showed every score file as different -> the score JSON echoes the --path file name, which differed between the two folders -> fixed: the compare ignores only path_source.file; two runs then matched on 198 of 198 files.
- Executor R2 stopped on an API error -> a safety filter flagged a request by mistake, and nothing in the code caused it -> worked around: its pather.h draft was saved, and a relaunch in the same worktree continued from it.
- R2's review raised a finding that needed core/replay and cmd_score -> those were files R2 could not touch while R1 edited them in parallel -> worked around: once R1 was finished, R2's scope was widened, and a fresh finisher fixed the shared reader in ec75f02.
- The MSVC linker crashed several times under heavy build load (C1001 and LNK1000) -> cause not found -> fixed: deleting hydra_tests.iobj and hydra_tests.ipdb.

## Outcome
The session ended with Track R merged to main as 3083155 (R1 came in as fb7b94e, then R2), after one full-suite run on the joined build passed.
hydra_replay score now reads one chord-score table in src/core/scoring, so the engine and the replay share one set of rules. target takes a whole path from a dump (--path) or typed windows (--acts). On blink-182's Discography, target went from still running at 60 s to 0.10 s. dump and score output was byte-identical on all 99 testdata charts (198 files). The suite passed: 1,155 hydra_tests cases and 70 of 70 hydra_uitest scripts.
