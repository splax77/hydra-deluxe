# Hydra timing and backend limits (2026-08-29)
session: 6e7764db-9da3-4628-bc03-cd1169e3cde6 | project: hydra-test | commits: 46e85cc, 9a77258, bab73d8, becf4d6 | D: none | tags: hit-window, ui-timings, release, installer, tests | agents: 2

## Goal
Widen the Path limit and Backend limit settings from 200 ms to the full 500 ms window the engine supports. After a user report that more backends were missing, fix the trim that hid them. Ship the result as 1.7.1, then as 1.7.2.

## Topics
Path limit and Backend limit input clamps, backend trim at store time, the ±170 ms constant, corpus round-trip test, dangling references in the store test, version bumps, installer and GitHub releases

## Roadblocks
- The Backend limit box showed only a few rows, even when set to the full range -> the store-time trim kept backends only to ±170 ms, an old constant -> fixed: changed the trim constant in model.h to 500 and updated the user guide line; shipped as 1.7.2.
- Widening the window made the corpus round-trip test fail on 7 of 970 charts -> the test bound references into a temporary vector that all_activations() returns by value, so the references dangled -> fixed: the test now builds the vector before taking references, in five places in test_store.cpp.

## Rulings
- "timing and backend limit should not be limited to 200ms. they should reach the full 500 ms hydra supports" (02:45 UTC, sets the new range for both limits)
- "build and push to release 1.7.1" (02:47 UTC, approves release 1.7.1)
- "ship as 1.7.2" (03:04 UTC, approves release 1.7.2 with the backend fix)

## Outcome
Ended with Hydra 1.7.2 live on GitHub, with Hydra-1.7.2-setup.exe attached and tag v1.7.2 pushed.
The session made two releases. The first (1.7.1) widened the input clamps. Its release notes went out before the user's backend report, and that report led to the 1.7.2 fix.
Each release went out as two commits: the change, then the version bump. The full C++ suite passed on both (199 cases, then 200 cases), and all 12 headless UI tests passed on 1.7.2.

## Open threads
- Records analyzed by 1.7.1 hold only ±170 ms of backends. Under 1.7.2 they read as out of date, so each library needs a re-analysis to fill the full window. The release notes say so.
