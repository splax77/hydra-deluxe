# Clone Hero SRB chart format (2026-09-29)
session: 7c71d4dd-8274-4d9c-a9d1-4224c21e4ad1 | project: hydra-test | commits: none | D: none | tags: clone-hero, stem, preview, chart, docs | agents: 0

## Goal
The user wanted a document that explains Clone Hero's .srb song file format and how Hydra reads it. The work grew into a standalone format spec for any developer, built by reading the game's own code. A later report that Saurian King would not play led to a check of the game log.

## Topics
.srb layout, header scrambling, AES audio decryption and its key, stem type tags, the Saurian King audio failure, four checksum mismatches, the published spec page, comments in srb.h and preview_source.cpp

## Roadblocks
- The game's class names are scrambled -> the .srb reader was hard to find by name -> fixed: Claude ran Il2CppDumper, a tool that recovers names from Unity IL2CPP builds (IL2CPP is Unity's way of compiling C# to native code), then read the disassembled functions that open .srb files.
- Il2CppDumper needs .NET 7, but only .NET 8 is installed -> the tool would not start -> worked around: ran it once with DOTNET_ROLL_FORWARD=Major, which changes nothing on the system.
- The AES key is not stored anywhere in the game files -> the game builds it at run time from two constants -> fixed: Claude copied the game's 41-step key loop into Python, and it reproduces the key exactly.
- The earlier doc and code comments called the number before the audio section "purpose unclear" -> an earlier writer read the first audio piece as having no tag and never compared the number with the tags on later pieces -> worked around: the doc now shows a tag on every piece and says the first one is most likely the same kind of tag; this is not confirmed.
- The draft page had wrong facts -> it gave 368 bytes as the smallest metadata block and assumed song length matches audio, but the shipped files say 353 bytes, and Pressure stores 273 s against 223 s of audio -> fixed: corrected from the real files before publishing.
- The .NET one-line decrypt failed -> Aes.DecryptCfb in .NET refuses data that ends in a partial 16-byte block, and 151 of the 152 stems end that way -> fixed: the page now pads the data, decrypts, then trims it, and the C# reader does the same.
- Saurian King gave no preview sound and froze on a black screen in gameplay -> two audio pieces in the shipped file are labelled -1, which the game's type reader refuses to read -> worked around: the spec now shows how to change those two labels in a copy; the copy passes the game's checks but has not been played. The audio thread catches the preview error, but gameplay setup has no catch, so the game freezes.
- Four bundled songs have stored checksums that do not match their charts -> cause not found -> dead end: line endings, byte-order marks and dropped MIDI tracks were ruled out, and Chorus Encore does not host the built-in songs, so it cannot date them.
