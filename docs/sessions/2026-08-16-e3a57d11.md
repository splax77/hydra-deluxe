# Score scraping and Hydra comparison (2026-08-16)
session: e3a57d11-7b01-4c77-b55b-0f7e7f148e14 | project: hydra-test | commits: none | D: none | tags: leaderboards, planning, library, report-table | agents: 2

## Goal
The user wanted their dmleaderboards scores pulled and compared with Hydra's optimal scores. The session found that no scraping was needed, planned the feature, and built it into Hydra as a comparison button, a searchable user picker and an HTML report.

## Topics
dmleaderboards site and DMBot API, chart MD5 join with hyhash, library button and picker modal, WinHTTP client, comparison HTML report, above-optimal labelling, MSVC UTF-8 source glyphs, build locks

## Roadblocks
- WebFetch on dmleaderboards.com returned 403 -> the static site sits behind Cloudflare, which blocks automated fetches -> worked around: the browser read the page's network calls and found the JSON API behind it (dmbot-kb5j.onrender.com).
- The plan labelled scores above Hydra's optimum as impossible -> the plan treated Hydra's optimum as complete, but it excludes many backends and old Clone Hero fill logic -> fixed: the user corrected it, and the plan and memory now say above optimal.
- The DM report template's em-dashes and arrows came out mangled -> MSVC reads source without the /utf-8 flag, and the Edit tool normalised the glyphs -> fixed: added /utf-8 for hydra_core in CMakeLists.txt instead of escaping every glyph.
- Hydra.exe would not relink (LNK1104) -> the user's running Hydra held the file lock -> worked around: built HydraUncapped from the same sources to verify; after the user closed Hydra, the full rebuild linked Hydra.exe.
