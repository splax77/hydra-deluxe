## Goal
Find out why Hydra froze during Analyze library, fix it, and fix the eight charts that failed with one error. Later the user asked for a way to sort stored paths by key numbers, and the session built a sortable path report.

## Topics
batch freeze, render thread, worker processes, tied-path cap, empty-chart error, progress counter, frozen build worker check, path report sorting, report column layout, colour markup in names

## Roadblocks
- Analyze library froze the window -> batch analysis ran on the render thread, so the frame rate was the chart rate, and album and discography charts took 5 seconds to over 11 minutes each -> fixed: batch analysis moved to its own thread, which hands charts to a pool of up to 8 worker processes
- The eight failing charts all raised IndexError -> the parse had no Expert pro drums notes (no drums track, or an empty Expert track), and the error text did not say so -> fixed: an empty-chart guard now reports "No Expert pro drums notes in this chart."
- The freeze looked like a path-tie problem -> ties were not the cost, since a full album chart still took about 41 seconds -> dead end: capping tied paths alone, which helped tie-heavy charts but did not stop the freeze
- The progress counter sat at 14 of 30 for 25 seconds -> results were counted in submission order, so a slow first chart hid the finished ones -> fixed: each result is counted as its worker returns
- The sort report looked empty at normal width -> the Path and Charter cells did not wrap, so one long Path cell pushed Score off-screen -> fixed: text columns capped with ellipsis, colour markup stripped, a Sort by control added, and a sort arrow on every header
- The tie cap changed results in test_path_reduction_auto, from 4 failures to 46 -> the change only shows for synthetic test values with 6 or more tiers and negative ms filters -> worked around: showed the best path and score were unchanged on every test chart, and left the 42 extra failures in place
