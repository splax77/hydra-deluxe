## Goal
Find why Hydra 3.0.0 froze for over a minute during a whole-library re-analysis, and why a first analysis can take 30 to 90 seconds while a repeat takes 3 seconds. No code was changed.

## Topics
library startup and re-analysis, window responsiveness, the Windows file cache and cold reads, antivirus first scans, test copies of the library

## Roadblocks
- The agent first said nothing needed analysing -> it read the database after the user's re-analysis had already rewritten every result, and took the fresh results to mean nothing was stale -> worked around: the user corrected it, and the agent then worked from the corrected picture, in which all 19,704 charts had been Stale.
- The window's once-a-second library refresh looked like the cause -> the code suggested it, and it shares the database lock with the batch's saves -> dead end: with every result Stale, the full run took 3 seconds and the window's slowest reply was 0.2 seconds, so the refresh did not reproduce the freeze.
- The first measurement used an old dev build -> the agent ran a build that was not the 3.0.0 code -> fixed: the agent rebuilt the GUI exe from main and measured again.
- The Windows file cache looked like the reason for the slow first run -> the test dropped 41,690 chart files from the cache with a no-buffering open -> dead end: the cold run finished in 5 seconds with no freeze, so the cache does not explain a 30 to 90 second first run.
- The test copy's results were made Stale by changing a version stamp, which may not match the state the upgrade left -> the agent could not reproduce the real upgrade state -> worked around: the next step is to catch a slow run on the real install.

## Outcome
Ended at 01:08 UTC with the cause not found, and the agent waiting on the user's answer about catching a slow run live on the real Hydra.
No code was changed and nothing was committed. The real library and the running Hydra were not touched; all tests ran on a scratch copy with all 19,704 charts marked Stale.
On the copy, the full analysis took 3 seconds with the files cached and 5 seconds after a cache drop, and the window never froze (slowest reply 0.2 seconds). Each run read about 2.2 GB from the chart files.
The 30 to 90 second first analysis the user sees is still unexplained.
