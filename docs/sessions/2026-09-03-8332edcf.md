# Hydra freeze after path analysis (2026-09-03)
session: 8332edcf-d030-4493-bb4f-d40d02600a42 | project: hydra-test | commits: none | D: none | tags: performance, report-table, batch-running | agents: 7

## Goal
Find out why Hydra freezes for about a second after a path analysis finishes, using the user's screen recording, and fix it so the window stays usable while the path report builds in the background.

## Topics
store lock held during the report walk, the Continue button and the page refresh waiting on that lock, per-record locking in for_each_blob, report cancel on app close, temp-file swap for the report page, the greyed "Building path report..." button, search for outside fixes, timing on a copy of the library

## Roadblocks
- Hydra froze when Continue was clicked -> the report thread held the store lock for the whole walk over every record (about 1.4 s on the user's 18,559-record library), and Continue's page refresh needed that same lock -> fixed: the walk takes the lock once per record, so the window waits at most one record's query.
- The first executor was interrupted, and one of its build or timing workers stalled -> cause not found -> worked around: the session checked the working tree and found no damage or leftover processes, then finished the build, tests and timing itself.
- The before-and-after timing could not use the installed 1.7.6 build against the working tree -> the working tree writes a newer path-structure format, so the old build saw every stored record as stale -> worked around: only the lock change was copied onto the 1.7.6 commit in a throwaway worktree, which was removed afterwards.

## Rulings
- "plan out a good fix. the ui should remain functional while the report runs in the background." (03:44 UTC, the window must stay usable during the report)
- "search github and stackoverflow for solutions before finalizing the plan" (03:59 UTC, asks for outside prior art before the plan is final)
- "address and fix these" (04:02 UTC, asks that two known leftovers be fixed in the same plan: the report ignoring cancel, and the open-report button vanishing when the modal is left early)

## Outcome
Ended with the freeze fixed and every test green, with all changes uncommitted in the working tree next to the user's unrelated edits.
The changes are: for_each_blob in src/store/record_store.cpp, which now locks per record; a cancel flag in src/ui/library_jobs.cpp and src/app/report.h; a temp-file rename in src/app/report_files.cpp so a half-written page never opens; and a greyed "Building path report..." button in src/ui/library_view.cpp. The full C++ suite passed at 253 cases and 33,939 assertions, and all 12 hydra_uitest scenarios passed. On the library copy, the walk took 1.23 s, against 1.33 s in the shipped 1.7.6 build, and the HTML was byte-identical.
