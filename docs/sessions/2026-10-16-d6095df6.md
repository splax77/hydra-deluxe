## Topics
guitar engine feasibility, CHOpt whammy model, Clone Hero Star Power meter clock, guitar scoring and HOPO rules, sustain cutoff, whammy input signal, activation sentences, PART DRUM track name bug

## Roadblocks
- The planning draft could not write the activation sentences -> it only recorded each activation's score and window, with no step that made the text -> fixed: a new plan section where each sentence fills a fixed template from facts the search records, the way Hydra's drum squeeze sentences already work.
- A whammy scout said a full meter always drains in 30 beats, whatever the time signature -> that clashed with Hydra's drum rule (one bar of Star Power lasts two measures), which was proven on video -> fixed: a second scout and a check of the game's constants showed the game drains on a measure-based clock, two measures per phrase, while whammy counts in raw beats.
- The decoded copy of the game's code from an earlier session was already deleted -> no copy was left to read -> worked around: re-ran Il2CppDumper into the session's scratch folder and wrote a small disassembler helper (chdis.py), which needed two fixes before it worked.

## Outcome
Ended with the four game facts found in the game's code and reported to the user, with no change to the repo.
The guitar plan lives in the session's scratch file, not the repo. No guitar code was written, and the build waits for the user's yes.
The four facts: a hidden score bonus of +2 per note on a perfect run (it does not count toward stars), the natural HOPO distance rules, the sustain cutoff, and the whammy signal (any change in the 0 to 255 bar reading counts, and each change keeps Star Power flowing for 0.25 s).
While checking, the session found a separate drum bug: Hydra read only the track name PART DRUMS, while Clone Hero also accepts PART DRUM. A side session merged the fix to main (the merge is not pushed, and no hash is recorded here). A second side session wrote a plan for matching Clone Hero's track choice and is waiting for a yes.
