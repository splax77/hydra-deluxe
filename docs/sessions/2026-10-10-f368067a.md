## Goal
Driven by another session, with no user messages. The goal was to fix a hang in the .srb parser (the bundled-song container) that the fuzzer found: a damaged file made the loader inflate data until a 1 GB cap.

## Topics
.srb container parsing, deflate stream inflation with miniz, size cap and corrupt-file error, fuzz regression file, ASan build, bundled Clone Hero songs check, derive-once review

## Roadblocks
- The loader spun on a damaged compressed stream -> the stream had an unassigned code, which miniz reads as "write a 0 byte, read no input", so output never stopped and only the 1 GB size cap ended it (about 3 s per load in release, over 30 s under fuzzing) -> fixed: the read loop throws the existing "SRB stream is corrupt." error once output passes 1,032 bytes per input byte, the most deflate can produce
- The cause was hard to see from the error text -> the file failed with "exceeds size limit" instead of "corrupt" -> worked around: the session decoded the file by hand and read miniz's decode macro to confirm the cause, then the red test showed the wrong error
