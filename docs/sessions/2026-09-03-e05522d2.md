# Video download optimization analysis (2026-09-03)
session: e05522d2-7685-4dc5-9781-92dd140f9e3d | project: hydra-test | commits: none | D: none | tags: video, activation, path, hit-window | agents: 0

## Goal
The user gave a YouTube link to a Clone Hero drums play video and asked for the difference between that play and the optimal score. The session pulled the video with ytdl and ran the video analysis workflow on it.

## Topics
fcvideo score-loss analysis, half-speed video and audio alignment, 2x re-encode, HUD box placement, digit template reading, Star Power disc detection, hit-order loss, path choice versus execution loss

## Roadblocks
- Audio alignment failed on both charts tried (Bloodline 2x and Inventor 1xBP) -> the game time-stretches the audio at 50% speed, so the audio cannot line up with the video -> worked around: the video was re-encoded to real speed and the offset was taken from the frames where the score changes.
- Auto HUD detection failed on this layout -> the detector did not fit the video's HUD -> worked around: the two score boxes were placed by hand.
- The first offset search hung -> one sampled score probably matched several chords, so the search range was unbounded -> fixed: the search was re-run with a bounded fallback range and unbuffered output.
- The digit reader misread scores (3,250 read as 41,480; 9,115 read as 8,115) -> the chart is so dense that digits 0, 2, 3 and 9 never appeared in a quiet frame before the first activation, so the learned templates were wrong -> fixed: a --teach VIDEO_MS:SCORE flag lets frames read by eye teach the templates.
- A hit-order loss was read as a digit error (9 read as 8) -> the tool had no model for the loss -> fixed: a --known-loss CHORD:POINTS flag declares it.
- Star Power was never detected -> the bright yellow x2 lit fewer pixels than the purple x8, and one threshold was used for all colours -> fixed: the disc reader now judges fat glyphs per colour tier.
- The 120 fps re-encode read worse than 60 fps -> half-paid chords held two frames and broke the chord matching -> dead end: 120 fps was dropped in favour of 60 fps.

## Outcome
Ended normally at 22:00 UTC with the answer: the play was 5,815 points below optimal.
The video is Splax's "The Violation (B)" by Fleshgod Apocalypse, Bloodline's 2x-kick chart, played at 50% speed (the on-screen title says so). The results screen shows 5,642 notes hit, 0 missed, and a final score of 1,638,455.
Hydra's optimal path (path 0) scores 1,644,270. The best score on the path that was played scores 1,640,910, so path choice cost 3,360. The actual score is 2,455 below that, all in execution losses (figures from Hydra's engine and the screen).
The execution losses: 1,840 on the backend (the window ran out one chord early on four activations), 600 on the frontend (two activations had a note outside the window), and 15 from a new loss kind. The new kind is a hit-order loss: on the chord where the combo crosses 10, the game doubles the note hit last, and Hydra assumes the better order.
Speed penalty at 50%: none. The screen matched the engine's curve point for point.
The full report file is kept locally. The video-tools changes are uncommitted in a local folder, not in the repo.
