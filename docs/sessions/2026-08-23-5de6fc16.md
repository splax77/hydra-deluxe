## Topics

## Roadblocks
- The first plan hook was pointed at ExitPlanMode, assumed to carry the plan text -> ExitPlanMode only says "done" and reads a plan file already on disk, so the hook would never see the text -> fixed: moved the hook onto the Write and Edit calls that touch the plan file
- The Stop hook's input had no documented field list -> the session could not see the fields without guessing -> fixed: a one-shot diagnostic Stop hook dumped its input; it carries last_assistant_message, and the diagnostic hook removed itself
- The first live test of the chat hook did not block -> likely a settings-reload race: the hook was edited and fired in the same turn, before the config watcher reloaded it -> fixed: the same test a turn later blocked correctly
- An edit to the hook config was blocked by the auto-mode classifier -> hook config that runs shell commands counts as a sensitive change -> worked around: the user typed "continue" and the edit went through

## Outcome

Both hooks are personal to the user and not committed. CLAUDE.md got a bad and good example of a plan, and that was the first fix tried.
