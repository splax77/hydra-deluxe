## Goal
The user wanted Hydra's dmleaderboards comparison to match the Clone Hero base-game songs (.srb files), which it was silently dropping. The session found that Hydra gave these songs the wrong id, fixed it, and merged the fix to main locally.

## Topics
.srb and .sng song ids, Clone Hero's songcache.bin, dmleaderboards join, ADR 0028, scan version stamp, review gate and review cost

## Roadblocks
- Base-game .srb songs and .sng songs never matched on dmleaderboards -> Hydra keyed them by the MD5 of the whole file, but Clone Hero uses the notes-file MD5 for .sng and a stored checksum for .srb -> fixed: one song-id function (song_id_read in src/app/analysis.cpp) now gives Clone Hero's id, recorded in ADR 0028; checked on No Known Suspects and Galaxies in Harmony in a scratch database.
- The merge gate wanted a fresh code review after a docs-only commit -> the gate ties the code sign-off to the exact tip hash, so the two doc fixes on top changed the key -> worked around: a sixth reviewer agent checked the docs-only diff.
- A refused fast-forward into main left 12 to 15 files staged in the shared main checkout -> the merge hook changes the checkout before it refuses -> worked around: the session restored main's files by hand, twice.
- Trial merge on main to learn the review keys -> the session did not check the notes, which say the code key is the branch tip and the doc keys come from helper scripts -> dead end: the trial merge; it was refused and caused the staged-files mess above.
- A test fixture (a .sng with no notes file) failed after the change -> that was the intended new behavior, a missing notes file is now a scan error -> fixed: the fixture got a notes file.
