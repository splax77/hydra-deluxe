# Preview loading performance audit (2026-10-03)
session: dadb77f5-cb30-4eed-afff-33e0d1671c66 | project: hydra-test | commits: 02976c1, 11db329, d33c3cd | D: D120, D121, D122, D123, D124 | tags: performance, preview, stem, library, agents | agents: 30

## Goal
The user asked the session to audit Hydra's preview loading, because the Preview sat at 48 percent for minutes, and to find faster ways to load it. After those fixes, the user asked for long-path support across all of Hydra, and a way to open reports at long paths.

## Topics
preview loading audit, streaming audio decode (Opus, Vorbis, MP3), MP3 seek points, progress bar and cancel, one-pass highway timeline, replay and chart parsing speed, long paths (win32_path), Open report and Show in folder, a flaky GUI test, browser test tabs

## Roadblocks
- The Preview stalled at 48 percent for minutes -> the whole 8.6-hour song was unpacked into memory before anything played, and the unpacked audio peaked near 36 GB on a 31 GB machine, so Windows swapped to disk -> fixed: the Preview now streams from the compressed file a few seconds ahead of the playhead (tasks 2, 3 and 4).
- Splitting the decode across 8 cores cut the time from 51 s to 7 s -> each core needed warm-up to avoid a click, and the buffer still took about 12 GB -> dead end: a parallel whole-song decode, dropped in favor of streaming.
- miniaudio's MP3 seek landed about 1,105 frames off -> its seek table skips the MP3 bit reservoir (a buffer MP3 frames borrow from) and the encoder delay, so the agent decoded forward from the start, which took 624 ms on a 21.6-minute file -> fixed: Hydra builds its own MP3 seek points. Seeks now take about 0.23 ms and match a straight decode bit for bit (task 2b).
- miniaudio's resampler reset left its low-pass filter dirty, so a seek could come out slightly off -> the reset call does not fully clear the filter -> fixed: the converter is re-created at each seek, using memory set aside up front, so the audio thread never allocates.
- The GUI test batch-pause-stop failed about 4 times in 16 runs -> the session's best guess was that the faster chart parsing finished each chart almost at once, so Pause often came too late -> fixed: a test-only hook holds the first chart in its analyzer, and the test then passed 16 of 16 runs.
- Files over 2 GB read back empty, and an Ogg Vorbis song past about 3.1 hours plays silent -> on Windows a long is 32 bits, so ftell fails past 2 GB, and a counter overflows inside the Vorbis library -> fixed: task 1 fixed the 2 GB case, and the streaming reader replaced the whole-file Vorbis decode. The final summary says the one Nirvana setlist .ogg that was silent before now plays, but it names no test of a 3.1-hour file specifically.
- A 335-character path (guitar.ogg in the Imperial Circus chart) would not open -> Windows caps plain paths at 260 characters, Hydra had no long-path manifest flag, and its 66 file calls used plain paths -> fixed: one win32_path function in core/winstr that the shared file helpers use, plus the manifest line. ImGui, SQLite and the two dev tools were routed through it too (11db329).
- The Open report and Show in folder buttons failed on long paths -> the Windows shell does not accept the long-path prefix, and the new manifest removed the shell's quiet path rewriting -> dead end: handing the shell a long path or a long-path-prefixed path, which Edge, Chrome and Explorer all reject. The fix that works is the old DOS-style short name, or a temp copy when a drive has no short names (02976c1).
- The browser checks opened a new tab for each test and never closed one, and a measuring mistake made the first round run twice -> the session did not check one tab first or use a separate profile -> worked around: the tabs were throwaway, and the lesson is saved to memory.
