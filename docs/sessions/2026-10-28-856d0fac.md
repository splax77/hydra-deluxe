## Goal
The user wanted a feasibility study for a full MCP server for Clone Hero (a plug-in that lets an AI tool read and drive the game), because the earlier probe work was too small for proper testing. The session then planned four tests that would settle the study's open questions.

## Topics
Clone Hero install and Unity build, Il2CppDumper class dumps, Beebyte name scrambling, Frida live hooks, the game's bot launch from the command line, scorestats.json end-of-song file, EULA limits on reverse engineering, mod loaders, the four-test plan, the handoff.

## Outcome
Ended with a handoff for the next session, after the study and the four-test plan were reviewed and signed off. Nothing is built or merged.
The study and plan are on branch claude/ch-mcp-tests-plan at commit fe4b6432. They are not merged to main.
The study's answer is that a full MCP is feasible, and most of it can use tools already on the machine. The free layer is Clone Hero's own bot, which plays a chosen chart when launched with --song and --player, plus scorestats.json, the end-of-song file with about 45 fields per player.
Frida (a tool that attaches to the running game) is the next layer. The hardest unknown is per-note hit results, which the obfuscation scout rated about a coin flip.
Scrambling is smaller than it looked. The class dump (made with Il2CppDumper, a tool that rebuilds class names from a Unity game) shows four of the game's code libraries scrambled. The classes an MCP reads first, such as GameManager, ScoreManager, SongSelect and the end-of-song stats box, kept their real names.
The handoff is docs/handoffs/2026-10-28-ch-mcp-feasibility-tests-handoff.md. It is left untracked so the reviewed branch tip does not move. A memory note points future sessions to it. The untracked copy of the study in the main checkout was deleted; the corrected copy is on the branch.
