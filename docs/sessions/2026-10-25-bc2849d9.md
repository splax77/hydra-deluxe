## Goal
The user wanted the AddressSanitizer job (ASan, a memory-error checker that makes tests run much slower) audited and brought down from its roughly 20 minutes. The job runs only on manual and nightly runs, so a normal push never pays for it. The user then asked for a plan with real CI numbers, and no merge before those numbers came in.

## Topics
ASan CI job timing, the track_state test shard, TrackState::synthesize lookup cost, shard rebalancing, GUI tests in their own job, sccache compiler cache trial, doc-review gate refusal of a reviewer sign-off, docs/development.md timing

## Roadblocks
- The job took about 26 minutes, not 20 -> one shard, track_state, ran alone for about 10 minutes -> fixed: the Task 1 lookup change (merged to main) replaced the per-call rebuild with a binary-search lookup, and the ASan test step fell from 831 s to 222 s on CI.
- The doc-review gate refused the reviewer's sign-off on the ASan plan -> the gate treated the reviewer's own fix commits as the author of the text it reviewed, because it only exempts the commit that makes the final text -> worked around: the user typed a waiver for the final text, and the hook fix is written up in a handoff but not built.
- sccache refused all 447 compiles as "multiple input files" -> the /d1trimfile flag starts with "/", which sccache's MSVC flag table does not know, so it counted the flag as a second input (an upstream sccache issue) -> dead end: the trial cached nothing as written; the fix of spelling the flag -d1trimfile: is proposed but not tried.
- The normal job's test step went from 55 s to 99 s after the shard rebalance, against a 112 s limit -> likely CPU contention from four equal groups on four cores, seen in one run only -> dead end: Task 2 is not merged and is held for the user's judgment.
- A fixed 60 s limit on the normal test step would have failed on today's layout -> that step already ran 30 to 85 s, and one group swung from 23 s to 54 s on runner noise alone -> worked around: the user chose total test CPU as the yardstick.
