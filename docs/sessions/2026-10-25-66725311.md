## Goal
The user wanted CI runs to take less time. The session measured the options, wrote a plan, then built it: a saved build folder reused between CI runs, and the GUI tests moved into their own job. The plan's policy questions were answered by the user.

## Topics
CI build time, Visual Studio versus Ninja, sccache, third-party library prebuilds, saved build folder, GUI test job, Coverage schedule, cancel-in-progress rule, YAML syntax error, proving runs on GitHub, merge of ci-speed into main

## Roadblocks
- The Ninja build was slower than the Visual Studio build on the same 4 cores (312 s against 193 s) -> the session did not find the cause in the transcript; a re-timing with /Z7 debug info gave 257 s -> dead end: sccache (a compiler cache) needs Ninja and /Z7, so the one push in seven that misses the cache would get slower.
- Prebuilding third-party libraries was considered -> they are about 10% of the compile work, and the build waits on hydra_tests alone -> dead end: prebuilding dropped.
- A timed header touch on the saved folder finished in 4 to 5 s, which looked like a missed rebuild -> cause not found -> fixed: a later timing.h change rebuilt correctly in 210 s, and the 45 s first build after a restore was a one-off.
- The saved-folder prune counted folders from every branch, so manual runs on another branch could delete main's folders -> the prune did not split by branch -> fixed: the review caught it, and pruning now counts per branch.
- The first proving run failed about 15 seconds in with a YAML syntax error in the shared restore step -> an unquoted line held colons, and no YAML checker runs in this repo -> fixed: the line was made a block, and a scan of all three workflow files found no other cases. Two executors and two reviewers had read past it.
- A reviewer returned without recording its review, so the gate had no record -> the reviewer did not submit -> worked around: a fresh reviewer re-reviewed the fix and recorded it.
- The cold proving run ran past 10 minutes, and the session first called that expected without reading the run -> manual runs also start the 20-minute sanitizer job and the Coverage job, and the broken step meant the change never ran -> fixed: the run was cancelled, and the proving runs were judged on the two jobs that matter.

## Rulings
