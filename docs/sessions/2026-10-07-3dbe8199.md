## Outcome
The session ended at 03:47 UTC with the storage handoff written. Nothing is committed.
The installed database is 338 MB: a 292 MB hydra.db and a 46 MB write-ahead log. It covers about 19,000 charts. Path data is 69% of the file. Backend squeeze rows make up 63% of path bytes, 2.6 million rows, and the details view is their only use.
Measured on the real data: zlib on path blobs would cut path data from 145 MB to about 49 MB, and zstd with a trained dictionary to 37 to 45 MB.
Verdict: keep SQLite. Re-analyzing 74 charts gave identical rows in every table, and a typical chart analyzes in about 2 ms. The proposal is to store only the library list and one summary row per result, and run the engine when a song opens. That would shrink the database from 292 MB to about 20 MB. The user has not answered its four trade-offs.
