## Goal
Finish phase 6 of the C++ port, which meant cutting over to a single C++ codebase and deleting the Python tree. Then, in the same session, make the library's first scan faster on the user's real chart folder, and make re-scans incremental.

## Topics
C++ port cutover, the batch and report command-line tools, the report HTML parity test against Python goldens, git checkpoint and tag, deleting the Python tree, README and .gitignore rewrite, library scan speed, incremental re-scan, scan progress and Cancel button.

## Roadblocks
- The first full scan of the real library never finished (killed after 10 minutes) -> the old scanner was serial, walked the tree three times, hashed one file at a time and read every .sng file twice; the slow cold cache was probably per-file first-touch cost, not confirmed -> fixed: one walk, a worker pool that hashes in 1 MB chunks, each .sng read once, and a size-and-time cache so re-scans skip unchanged charts.
- The C++ scanner read a frets key as a charter alias -> a corpus ini held both charter and frets with different values, and Python only reads charter -> fixed: the alias was dropped, since Python is the spec.
- The report template's arrow characters came out as real arrows, not the literal backslash-u escapes Python writes -> a C++ raw string does not unescape, and the edit tool's JSON quoting dropped a backslash level -> fixed: the arrows were replaced with literal backslash-u escapes so the page matches the Python bytes.
- The old and new scan dumps looked different -> the scan dump wrote forward slashes and the database dump kept backslashes -> worked around: both separators were normalized before comparing, and the rows then matched exactly.
