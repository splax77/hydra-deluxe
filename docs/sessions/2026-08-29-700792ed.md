## Goal
Find out why the 4.45 timing scale did not apply to the final backend row of a squeezed-out (SqOut) phrase, fix it, and then commit, push and release it as v1.7.5. The session started by investigating the user's question, then implemented the fix the user approved.

## Topics
squeeze scale direction, SqOut and SqIn squeezes, activation rating, phrase-note warning loop, regression test, version bump, installer build, GitHub release

## Roadblocks
- The SqOut row showed an effective time of 333.2 ms, so it looked freer than its raw 331.3 ms -> the scale direction was chosen by squeeze kind (every SqOut got the early scale), not by the sign of the offset -> fixed: the direction now follows the offset sign. A free squeeze gets the late scale, a difficult one keeps the early scale, and the SqIn warning loop got the mirror rule. A regression test covers the three directions. The session's own arithmetic gives about 122 ms for this row.
- The commit message had embedded quotes, and they broke the PowerShell argument passing -> the quotes were not handled by PowerShell -> worked around: the message went into a file, and a hook then objected to writing a file that size, so the commit was made from Bash with a heredoc.
