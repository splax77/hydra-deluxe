## Goal
Driven by another session, with no user message. The task was to make the path report's building progress bar count records the same way the finished report header does, so the bar and the header end on the same number.

## Topics
path report progress bar, record counts, library copies of a chart, seeded rows from a finished batch, derive-once review, merge of the rec-bar branch, User Guide wording, D103 decision record and ADR 0027

## Roadblocks
- The bar and the header showed different totals for records (the header said 38,883 on the user's library, and the bar ended lower) -> the bar counted each distinct chart-and-mode once, while the header counted every library copy -> fixed: the bar now weighs each slot by its copy count, and rows a finished batch already handed over count as done from the start.
- A chart that fails to analyze, or finds no path, still moves the bar but adds no record to the page -> the failed chart lists no rows, so the header can end lower than the bar by that chart's copies -> worked around: written into the code comment and the decision record, not fixed.
- The executor's change left stale comments and repeated the copy-count fallback rule as a default value -> the first build did not tidy its own comments -> fixed: the one fresh reviewer corrected five comments and the duplicate default before signing off.
