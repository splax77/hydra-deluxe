## Outcome
Ended with the uncapped edition merged into the main app and checked, with 51 files changed and nothing committed.
Hydra Uncapped is gone as a separate program. The SP cap is one setting in a song's details: a number box (default 4) plus an Auto checkbox that runs the old raise-until-it-settles ladder.
Records are stored one per cap, so a 4-bar result and a 64-bar what-if for one song sit side by side. Changing the cap changes which record shows; a song re-analyzes only when it has nothing at the current cap.
The leaderboard compare refuses unless the cap is 4. The CLIs read the cap from the INI file, and --uncapped is gone. The installer drops the second shortcut and deletes the old HydraUncapped.exe on upgrade. The records table is rebuilt once on first open, and a one-time import copies current-version records from hydra_uncapped.db (left unchanged) into hydra.db.
Two older bugs were fixed on the way: "Analyze library" used to skip stale records, and --reindex would have spread one cap's summary over all caps.
The agent reported hydra_tests at 152 of 152 cases and hydra_uitest --all at 4 of 4, including a new cap-switch check. Migration was checked on copies of the real databases.
edition.h was deleted, and ADR 0003 was added.
