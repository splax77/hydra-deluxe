## Goal
Review the Hydra interface as a UX designer would, and rank its problems by impact. After the user approved the plan, build the fixes and verify them in the real app.

## Topics
wrong-song result saving, cancel for single-song analysis, disabled controls that look enabled, pagination off-by-one, missing confirmations, UI-thread stalls, search scope, folder management, text contrast, Japanese font fallback, high-DPI sizes, clipped text with ellipsis and tooltips

- The linker failed again, this time on Hydra.exe -> the same running window held the file -> worked around: closed the idle window and rebuilt, and told the user to relaunch from build-cpp\Release.
- A PowerShell rewrite of details_view.cpp turned the em dashes into garbled characters and left a byte order mark at the top -> the file went through a PowerShell encoding round trip -> fixed: the assistant found the garbled characters and the byte order mark, then removed both.
- Long titles were cut off mid-word in the song info panel and the library table, with no ellipsis -> the cells were narrower than the text, and ImGui clips without marking it -> fixed: a shared text_ellipsized helper draws an ellipsis and shows the full title on hover.
