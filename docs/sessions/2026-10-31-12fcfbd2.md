## Outcome
Ended at 03:46 UTC with a handoff written for a planning session, not committed, and the patched SignalRGB test still running.
SignalRGB's own log shows about 61 MB of growth per awake hour across four runs since September. The session's conclusion is that the leak sits in mimalloc 1.7 inside Ultralight 1.4.0, the HTML engine SignalRGB uses to draw effects, which keeps freed memory charged to the program by default.
A patched run (three environment variables set for one launch, no files changed) held roughly flat for an hour: about 16 MB in 55 minutes, against about 141 MB in a normal first hour. One hour cannot show a slow leak over days, and the setting is lost on a normal restart. Making it permanent means changing bytes in our copy of UltralightCore.dll, which waits for the user's yes.
Hydra uses mimalloc 3.5.3, whose defaults give freed memory back, so the session ruled this leak out for Hydra on paper. Hydra was not run or measured.
The scouts' findings: the motherboard has a plain, documented USB protocol; the mouse needs Logitech's protocol; RAM lighting needs a kernel driver (PawnIO was named as the signed option); Windows Dynamic Lighting reaches only part of the hardware. No code was written.
Security: the session reported that Gigabyte Control Center's kernel driver has a known flaw fixed in a later version (the fixed version came from press reports, not the vendor page), and that a Corsair service is installed with no Corsair hardware. The user has not decided on either; nothing was touched.
