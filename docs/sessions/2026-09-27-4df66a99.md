# Let a cancelled leaderboard download stop at once (2026-09-27)

## Goal
A cancelled leaderboard download could keep the window waiting for up to two minutes, and closing Hydra could wait on the network too. The user wanted a cancel to stop the request within about 100 ms, with the "cancelled" error text unchanged. The session explained the plan first, built it on the user's yes, and merged it on a second yes.

## Topics
dmbot_client http_get cancel flag, WinHTTP synchronous and asynchronous requests, WinHttpCloseHandle rules, Handle RAII wrapper, local test server on 127.0.0.1, redesign wave 3 coordination, merge into hydra-test

## Roadblocks
- The suggested fix was to close the request handle from another thread on cancel -> Microsoft's docs forbid closing a synchronous request's handle that way, because it is a race condition and a late call can hit a reused handle value -> worked around: the request now runs in WinHTTP's asynchronous mode inside, and the same thread waits in 50 ms steps and closes the handle itself on cancel.
