## Goal
The user asked why the Star Power meter in the Preview misbehaved in a video he recorded, and how to fix it. After the diagnosis, he asked why the Preview was guessing at all. The session moved the fix to the engine, which now stores where Star Power ends.

## Topics

## Roadblocks
- The Preview drained the meter two measures early and then banked a phantom bar -> the activation had no backend rows, so the squeeze-only fallback guessed the end and missed the mid-Star-Power phrase -> fixed: the engine stores the deactivation tick on each activation (ADR 0011), and the guess and the chart rebuild in the replay module were deleted.
- Records from the released 1.7.6 build read as Ready with no stored end -> readiness checked only the app version string -> fixed: readiness now also checks the stored path-structure format number, so older records read as Stale.
- The executor ran hydra_batch with no arguments to read usage text, which starts a full-library analysis -> the executor ran it while probing for usage text, and a no-argument run analyzes the whole library -> worked around: it was killed after two minutes, but it wrote rows into the build-cpp copy of the database, which was left in place.

## Outcome
