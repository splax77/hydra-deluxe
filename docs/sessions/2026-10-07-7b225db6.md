# Fix agent call counter resetting mid-run (2026-10-07)

## Goal
The agent call counter kept resetting during parallel tool calls, so the gates lost count of how many calls an agent had made. The session found the cause in the user-scope hooks, fixed it with one shared helper, and ran the affected hook tests.

## Topics
hook state files, parallel tool-call counting, file locking and atomic rename, PowerShell Set-Content, progress gate, suite run gate, deletion shrink gate, fable delegate budget, stall watchdog, rerun gate misreading a command

## Roadblocks
- The agent call counter reset to 0 during parallel tool calls -> every gate rewrote its state file with Set-Content, which empties the file first, so a parallel run could read it empty and start at 0; two runs that both read N also both wrote N+1 -> fixed: one shared helper, hooks\lib\state_file.ps1, with a lock, an atomic swap and loud read errors, used by nine hooks.
- The first race test passed for the wrong reason -> the writer was failing every write, so the test saw no change -> fixed: the test now also checks that all 300 writes finished.
- Readers that skipped the lock saw brief errors during the swap -> [IO.File]::Replace left the file missing for a moment (47 times in one run) -> dead end: Replace was dropped, and a true rename was used instead, with zero missing or failed reads across 9,149 reads.
- test_h19 failed after the fix -> it keeps a list of file reads that may skip their encoding check, and six listed reads had been replaced -> fixed: the six stale entries were removed, and the test passed 22 of 22 on rerun.
- The assistant re-ran the same wait loop a third time, and the rerun gate read the loop's command as one named $f -> the loop was a poll that changed nothing, and the gate misreads PowerShell assignments -> worked around: polling stopped, the background run reported on its own, and the gate bug was logged as a follow-up.
