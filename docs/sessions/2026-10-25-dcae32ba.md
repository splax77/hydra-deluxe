## Roadblocks
- ALB-1 put the new album field in the middle of the library row struct -> some code fills that struct by position, so each value landed one field late, and the executor and reviewer were not allowed to run the CLI tests -> fixed: album moved to the end of the struct, a test was added against mid-struct inserts, and the fix got its own review.
- The session told the user that ImGui saves column settings by column ID number -> the claim came from a shallow reading of imgui_tables.cpp -> fixed: ALB-3 found ImGui keys saved settings by a hash of the header label; the plan and D263 were corrected, and the GUI test now loads an old five-column settings file.
- The first mock showed the second search line only on the selected row -> Hydra draws it on every row whenever a word search is on and Folder or Charter is hidden -> fixed: the design was corrected before the plan was written.
- The first real-app check script stopped before the rescan started, on a clashing argument name -> a bug in the session's own script -> fixed: the script was repaired and rerun on a fresh snapshot, so the one allowed rescan was not used up.
- Every chart showed "Stale" on the user's library copy -> cause not found -> worked around: reported in the Outcome; the rescan did not cause it, and the likely reason (results saved by the installed build) is unconfirmed.
- The popup sized its columns directly, around the one owner of column widths -> the shared table helper always draws a header row -> worked around: the reviewer routed the popup through the helper, and the user kept the header row.
- The search-tips text said "optimal path" for the filters, which read the best path -> the project uses "optimal path" for another concept -> fixed: the popup and the User Guide now say "best path".
