# Merge-on-main hook times out under load (2026-10-23)
session: f17c3dd2-a5f3-4afb-9814-865cddf9797f | project: hydra-test | commits: 060257b | D: none | tags: hooks, agents, review, tests | agents: 2

## Goal
The merge check on main, one of the hooks that guards merges, was denied when the machine was busy. Its fixed 8 s limit was too short, and a timeout left the first attempt running. The session gave the merge check its own longer budget, and made a hung check clean up after itself.

## Topics
merge-check hook timeout, hook server deadlines, pipe client deadline, process tree kill, load test, live exe swap

## Roadblocks
- A merge check on main timed out under load and was denied at 8 s -> the check is the slowest gate, about 1.7 s on a diverged branch, but it got the same fixed 8 s as every quick check -> fixed: the merge gate asks the server for 45 s on its own call, and the client moves its own deadline out, capped at 60 s.
- A timeout left the first attempt's judge process running, so a retry started a second copy -> the server stopped the check's process but not the judge process under it -> fixed: the merge gate now runs the check with a 40 s limit of its own and kills the whole process tree at that limit.
- A fresh pool might be slow on its first call, so a warm-up was considered -> the timings were 67 to 560 ms for a replacement pool and 390 to 753 ms for a fresh server, not reliably over the half-second line -> dead end: pool warm-up was left out.
- The live pipeclient.exe was in use, and Windows would not overwrite it during the fast-forward -> a running exe is locked -> worked around: the in-use exe was moved aside, then the free build was put in its place.

## Rulings
- "Yes, build the merge-check timeout plan as written." (01:16 UTC, approves the plan and the build)

## Outcome
The session ended with the fix live on the hooks main at 060257b, with the hook server restarted and running the new 45 s cap.
A related fallback fix from another session later landed on the same main. Its hash is not recorded here.
Tests: four test files that touch the changed hooks passed when run from the worktree (44, 53, 53 and 20 cases). A new load test showed the old code denied a slow check at 3.1 s, and the fix allows it.
