## Goal
The user wanted the chart scanning and analysis code audited for more speed, with web scouts searching for alternative algorithms and tools. Later he asked why dominance pruning was dismissed, and for the exact difference between the search rules in DragonDelgar's public Hydra 1.3.0 and 1.3.1.

chart folder scanning, MD5 song hashing, folder-listing APIs, database writer commits, graph building, memory allocators, path search algorithms, dominance pruning, SP-state grouping, the Informal Gluttony chart, the 1.3.0 versus 1.3.1 search code

## Roadblocks
- Web scout proposed dominance pruning (drop a path that another beats on score and SP bars) -> a fuller SP meter is not always better, because an activation spends the whole meter -> dead end: the whole-library test changed 58 of 18,811 stored results, and 3 lost their true best score (Informal Gluttony fell from 932,440 to 932,280).
- Upper-bound pruning (drop a path only when it provably cannot win) -> the bound is loose -> dead end: results stayed exact but the search shrank only 7-9%, as an August note had already found.
- Best path first, near-best list afterwards (lazy k-best) -> the search got about 5x faster in one test -> dead end: keeping stored results byte-identical would need a risky rewrite, so it was not built.
- CHOpt-style skip-ahead from one SP note to the next -> our graph already does most of this -> dead end: 2.5 million graph nodes against 45 million notes in the library.
- Reading the drive's file table directly, as Everything and WizTree do -> it needs admin rights or a background service -> dead end: ruled out.
- The 1.3.0 public version could miss the optimal path -> it compared paths with different SP amounts, and dropped a path once enough distinct scores beat it -> fixed: upstream in 1.3.1, which groups paths by exact SP state. Our engine already follows that rule.
- Four experiment agents (profile, scan, database writer, engine) stopped before writing final reports -> the previous session ended while they ran -> worked around: their last status lines and saved patches were kept, and the assistant offered to resume them.
