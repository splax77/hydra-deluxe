Hydra Deluxe 2.8.0 times Star Power and generated fills on Clone Hero's own measure grid, lets the path search use early fills that need up to 85 ms, and makes the path report cover every song in your library. Songs the analysis can't handle now say so, with a `Can't analyze` status and chip.

**Every saved result reads `Stale` after you update.** This release changes how charts are analyzed, so each result an earlier version saved reads `Stale` until that song is analyzed again. Click a song or run a batch to bring it up to date. Your old results are kept as `Stale` and replaced one song at a time as you analyze. The first start after updating converts `hydra.db` to a new layout once. If that takes a moment, a box says `Updating your library file for this version of Hydra` and `This happens once. Your charts and results are kept.`, with `Updating the results table...` over a bar that counts the results converted. You can close the window during the update, and the next start runs it again from the beginning. A library file from a version older than 2.2.0 is too old to convert: Hydra Deluxe renames it to `hydra.db.pre-2.2.0`, starts a fresh library and scans your song folders again, so your songs come back as `Not analyzed`. Because every result is `Stale`, the first time you open the path report it offers to analyze your whole library (see below).

**Star Power and fills follow Clone Hero's measure grid.** Star Power's length counts measures the way Clone Hero does. Where a time signature change cuts a measure short, that part measure counts as its share of a measure, so the SP end can move on charts with mid-measure meter changes. On a chart with no fills written in it, each fill Hydra Deluxe places now starts on the measure line, where Clone Hero 1.1's generator puts it. With `1.0 fills` on, fills are placed exactly as before. The measure lines and beat lines in the Preview follow the same grid, and it starts again at the first beat of each time signature change. A position such as `m27.2.450` counts the beats you see on the highway, so a beat is an eighth note in 6/8 or 7/8. Practice section names show as Clone Hero shows them, from the game's own list. The `fill_length_measures` key in `hydra_rules.ini` is retired; an old file that has it still loads.

**Early fills can need up to 85 ms.** When your Star Power comes ready after a fill's deadline, you can still summon the fill by hitting the activation early. The path search now keeps every activation that needs 85 ms or less, up from 60 ms. The `E` mark is unchanged: Star Power ready less than 60 ms before the deadline still shows `E`. Both numbers are fixed in Hydra Deluxe and don't follow the `hit_window_ms` setting. In a test run on a library of 18,858 charts with `1.0 fills` on, 25 best paths scored higher, by 80 to 10,040 points, and none scored lower. 48 more kept their score, but their path notation gained an `E` fill.

**The path report covers your whole library.** It lists your songs under your current Analysis settings: difficulty, Pro Drums, 2x Bass, Note Shuffle, SP cap, `1.0 fills`, score range and path limit. The `Mode` column is gone, and clicking a row no longer switches your settings. When you open the report and some songs have no current result, `Stale` ones included, Hydra Deluxe analyzes them first in an ordinary batch, with the strip, `Pause` and `Stop`. The window shows `Analyzing n of N charts` over a bar, and its `Cancel` stops the batch. When more than 500 songs need analyzing, the report window asks first, in the window itself: `Analyze N charts that have no result yet?`, with `Analyze` and `Cancel`. `Cancel` builds the report from the results already saved. The report then builds from the paths each analysis saved, without analyzing your songs again, and reads `Building the report from your library...` while it does. Lines above the table count the songs it can't show, like `59 charts have no Expert Pro Drums notes` or `N charts can't be analyzed`, with `Show list`, and `N charts have no result under these settings`. The `Charts shown` tile counts out of your whole library, like `19,453 of 19,512`. `Open path report` now shows whenever your library has songs and `hydra_rules.ini` has no error.

**Songs that can't be analyzed say so.** When something in a chart file itself stops the analysis, the `Best path` cell reads `Can't analyze`, dimmed, and hovering it gives the reason. Hydra Deluxe remembers four such causes: no notes for your difficulty and drum type, a timing line it refuses, a chart Clone Hero freezes on with Note Shuffle on, and a file it can't read or that is damaged. A fifth chip, `Can't analyze (N)`, filters these songs. A batch skips them as songs that already have a result, and the `Analyze library` window adds a dim line: `N of these can't be analyzed. Check the box to try them again.` Clicking such a song still analyzes it, and a changed file is tried again on its own.

**`Analyze library...` follows the chips.** While a search or a chip other than `All` narrows the table, the button reads `Analyze shown (N)...` and analyzes the N songs the table shows. It used to follow the search only, and read `Analyze search (N)...`.

**Clearer report labels.** In the path report, `Best path only` is now `Optimal paths only`, the `No squeezes` timing choice is `No timing needed`, the `Notes` column is `Note count` and `Avg multiplier` is `Average Multiplier`. The Stars tab's `Multiplier` column and the score breakdown's `Avg. Multiplier:` line read `Average Multiplier` too. When nothing is analyzed at all, the report and the batch strip say `Nothing is analyzed yet. Click a song or run a batch to analyze it.` Opening a song that saves a new result now marks an open report out of date: `Your library changed since this report was built.`

**Tables keep their shape.** Text columns in the Library and the report windows take fixed shares of the room, so their widths no longer follow their text. Columns of numbers are as wide as their widest entry, and their cells start at the left like the text. Clicking a row no longer scrolls the list. `Up`, `Down`, `<` and `>` move the list only as far as it takes to show the selected row. A selected row is a dark teal, so it stands out from the row stripes. Optimal rows in the path report no longer have a gold bar at their left edge. The score breakdown's numbers start in one column after the longest label.

**Smaller changes.** Each error's sentence shows once: a chart with no notes used to show its sentence twice in a batch's failure list, and a details line now appears under an error only when it adds something. A chart whose time signature makes a beat shorter than one tick is refused, with the sentence for an out-of-range time signature. A damaged .ogg or .flac audio file whose header claims an impossible size no longer runs Hydra Deluxe out of memory.

**Command-line tools.** `hydra_fillcompare` reads both fill rules from one database, because each result now carries its own rule. It reads `--db <path>`, or the app's own `hydra.db` when you leave that out. `--old` and `--new` are gone, and using either stops with a message saying so. Its page and summary line say `Only under 1.0`, `Only under 1.1` and `Under one rule only` where they said "only in 1.0" and "Only one side", and its notes column reads `Note count`. `hydra_batch --legacy-fills` no longer needs its own database, so a 1.0 run can go into the app's `hydra.db` beside the 1.1 results. Given a library file older than 2.2.0, both tools stop and say that opening it in Hydra sets it aside, and neither renames it.
