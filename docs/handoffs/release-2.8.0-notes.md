Hydra Deluxe 2.8.0 makes the path report cover every song in your library. It also follows Clone Hero's measure lines more closely and finds paths whose fill needs an earlier hit. Songs the analysis can't handle now say so, with a `Can't analyze` status and chip.

**Every saved result reads `Stale` after you update.** `Stale` means a result is out of date and needs analyzing again. This release changes how charts are analyzed, so each result an earlier version saved reads `Stale`. Click a song or run a batch (one background run over many songs) to bring it up to date. Your old results stay until you analyze each song again.

The first start after updating converts `hydra.db`, your library file, to a new layout. This happens once. If it takes a moment, a box says `Updating your library file for this version of Hydra` and `This happens once. Your charts and results are kept.`, with `Updating the results table...` over a bar that counts the results converted. You can close the window during the update. The next start runs it again from the beginning. A library file from before 2.2.0 is too old to convert, so Hydra Deluxe renames it to `hydra.db.pre-2.2.0`, scans your song folders again and shows your songs as `Not analyzed`. Because every result is `Stale`, the first time you open the path report it offers to analyze your whole library (see below).

**Star Power and fills follow Clone Hero's measure lines.** Hydra Deluxe now builds its measure lines and beat lines the way Clone Hero does, from the chart's time signatures. Star Power's length is counted in measures. Where a time signature change cuts a measure short, that short measure counts as its share of a full one. On a chart with a time signature change partway through a measure, the point where Star Power ends can therefore move.

Some charts have no fills written in them, and Hydra Deluxe places the fills itself. Each fill it places now starts on a measure line, where Clone Hero 1.1's fill generator puts it. With `1.0 fills` on, fills are placed exactly as before.

The measure lines and beat lines in the Preview follow the same lines. They start again at the first beat of each time signature change. A position such as `m27.2.450` means measure 27, beat 2, tick 450 within that beat. It counts the beats you see on the highway, so a beat is an eighth note in 6/8 or 7/8. Practice section names show as Clone Hero shows them, from the game's own list. The `fill_length_measures` key in `hydra_rules.ini` is retired. An old file that has it still loads.

**Early fills can need up to 85 ms.** A fill appears only if your Star Power is ready in time. When Star Power comes ready after a fill's deadline, you can still get the fill by hitting the activation early. The path search used to keep such an activation when Star Power came ready up to 60 ms after the deadline. It now keeps it up to 85 ms. The `E` mark is a separate check and is unchanged. It still shows when Star Power comes ready less than 60 ms before the deadline, so the fill only just appears. Both limits are fixed in Hydra Deluxe and don't follow the `hit_window_ms` setting.

The effect was measured in one test run on one library of 18,858 charts with `1.0 fills` on. In that run, 25 best paths scored higher, by 80 to 10,040 points, and none scored lower. 48 more kept their score, but their path text gained an `E` fill, for example `2 1 9 0` became `2 E2 9 0`.

**The path report covers your whole library.** It now lists every song in your library, under your current Analysis settings: difficulty, Pro Drums, 2x Bass, Note Shuffle, SP cap, `1.0 fills`, score range and path limit. The `Mode` column is gone, and clicking a row no longer switches your settings.

When some songs have no current result, `Stale` ones included, Hydra Deluxe analyzes them first in an ordinary batch, with its progress strip, `Pause` and `Stop`. The window shows `Analyzing n of N charts` over a bar, and its `Cancel` stops the batch. When more than 500 songs need analyzing, the report window asks first, in the window itself: `Analyze N charts that have no result yet?`, with `Analyze` and `Cancel`. `Cancel` builds the report from the results already saved. Once the songs have results, the report builds from the paths each analysis saved, without analyzing your songs again. It reads `Building the report from your library...` while it does.

Lines above the table count the songs it can't show: `59 charts have no Expert Pro Drums notes` or `N charts can't be analyzed`, with `Show list`, and `N charts have no result under these settings`. The `Charts shown` tile counts out of your whole library, like `19,453 of 19,512`. `Open path report` now shows whenever your library has songs and `hydra_rules.ini` has no error. Both report windows also have a `Close` button in the header, in every state, including while a report is building.

**Songs that can't be analyzed say so.** When something in the chart file itself stops the analysis, the `Best path` cell reads `Can't analyze`, dimmed. Hover it to see the reason. Hydra Deluxe remembers four such causes: no notes for your difficulty and drum type, a timing line it refuses, a chart Clone Hero freezes on with Note Shuffle on, and a file it can't read or that is damaged. A fifth chip, `Can't analyze (N)`, filters these songs. The chips are the filter buttons above the library table. A batch skips these songs, as it skips songs that already have a result, and the `Analyze library` window adds a dim line: `N of these can't be analyzed. Check the box to try them again.` Clicking such a song still analyzes it, and a changed file is tried again on its own.

**`Analyze library...` follows the chips.** While a search or a chip other than `All` narrows the table, the button reads `Analyze shown (N)...` and analyzes the N songs the table shows. It used to follow the search only, and read `Analyze search (N)...`.

**Clearer report labels.** In the path report, `Best path only` is now `Optimal paths only`, the `No squeezes` timing choice is `No timing needed`, the `Notes` column is `Note count` and `Avg multiplier` is `Average Multiplier`. The Stars tab's `Multiplier` column and the score breakdown's `Avg. Multiplier:` line read `Average Multiplier` too. When nothing is analyzed at all, the report and the batch strip say `Nothing is analyzed yet. Click a song or run a batch to analyze it.` Opening a song that saves a new result now marks an open report out of date: `Your library changed since this report was built.`

**Tables keep their shape.** Text columns in the Library and the report windows take fixed shares of the room, so their widths no longer follow their text. Columns of numbers are as wide as their widest entry, and their cells start at the left like the text. Clicking a row no longer scrolls the list. `Up`, `Down`, `<` and `>` move the list only as far as it takes to show the selected row. A selected row is a dark teal, so it stands out from the row stripes. Optimal rows in the path report no longer have a gold bar at their left edge. The score breakdown's numbers start in one column after the longest label.

**Smaller changes.** Each error's sentence shows once. A chart with no notes used to show its sentence twice in a batch's failure list, and a details line now appears under an error only when it adds something. A chart whose time signature makes a beat shorter than one tick is refused. Its message says the time signature has a bottom number that is out of range. A damaged .ogg or .flac audio file whose header claims an impossible size no longer runs Hydra Deluxe out of memory.

**Command-line tools.** `hydra_fillcompare` reads both fill rules from one database, because each result now carries its own rule. It reads `--db <path>`, or the app's own `hydra.db` when you leave that out. `--old` and `--new` are gone, and using either stops with a message saying so. Its page and summary line say `Only under 1.0`, `Only under 1.1` and `Under one rule only` where they said `Only in 1.0 db`, `Only in 1.1 db` and `Only one side`, and its notes column reads `Note count`. `hydra_batch --legacy-fills` no longer needs its own database, so a 1.0 run can go into the app's `hydra.db` beside the 1.1 results. Given a library file older than 2.2.0, both tools stop and say that opening it in Hydra sets it aside, and neither renames it.
